## 改动与范围

- 公共 RPC 的 `T5R1` 格式、8 KiB 上传/16 KiB 回复上限保持不变。照片、测速和 USB/BLE OTA 改为原始字节进出，省掉固件与 Windows 中间层的 Base64 编解码、字符串构造和 JSON 数据字段重建。旧桥接/固件仍在边界使用原 JSON 格式。照片最终存储入口仍执行既有图片解码、归属及完整性检查，因此不称为端到端零拷贝。
- Wi-Fi：在 IDF 5.4 公共 `esp_tls_plain_tcp_connect` 成功创建的 TCP socket 上设置 `TCP_NODELAY`。通过项目链接包装实现，不修改 SDK 文件、系统设置或 Wi-Fi 凭据。覆盖该 TCP transport 上的照片、语音、RPC 和 OTA；TLS 不改变。选项设置失败保留连接并记录无敏感信息的警告。动机是减少分开发送 HTTP 头/正文及小请求时的 Nagle 等待，效果以真机为准。
- BLE 语音：完成和断开直接唤醒本次请求的信号量，替代固定 10 ms 完成轮询。保持 12 秒截止时间；分配失败保留原有有界轮询；在锁内解除归属后才删除信号量。
- 不改变固定通道与自动选择规则，不自动跨通道重发，不减弱认证、防重放、序号/长度/哈希校验，不更换 USB 驱动或串口读取实现。
