# 软件固件更新入口本地交接（2026-11-17）

改动基于 `1e0b91b1f60f4aa10a1fae60096c628e81935802`，保留在当前工作区。本次为 Windows 与 macOS 本地验证，未发布。

| 用户操作 | 两端行为 |
| --- | --- |
| 查看更新 | 从「设备中心 → 桥接设置 → 软件固件」查看电脑软件、ESP8266、TAB5 和屏保图库的更新。屏保图库按一个项目计数。 |
| 选中「屏保图库」 | 有可升级的已安装图库时显示名画或书法的当前版本和目标版本。「管理图库…」打开已有的下载和导入工具。 |
| 打开设备卡片 | 「屏保图库」打开作品浏览，「连接设置」打开设备连接工具，保留 Wi-Fi、USB 配对、固件升级和传输测速。两处升级箭头已撤下。 |
| ESP8266 维护 | 从小屏设备页的「管理 → 手动刷机…」打开 USB 刷机工具。从「连接设置 → 重置网络…」打开原有确认流程。 |
| 点击系统通知 | Windows 按设备 ID 定位，多项通知选中其中首项。Mac 按组件定位，冷启动时在窗口准备好后打开。 |
| 下载后取消打开 Windows 安装器 | 显示「安装包已下载，尚未安装。」 |

Windows 已通过 Release 构建、`--status-once`、更新窗口、设备中心和图库浏览回归。更新窗口用模拟发布数据核对选中项、图库管理窗口及取消安装。连接设置专项离屏验证覆盖正常与最小窗口的多档缩放，确认 TAB5 新名称和小屏重置入口没有截断或重叠。Windows 本地预览位于 `artifacts/update-center-unified-20261117/update-ui/` 和 `artifacts/tab5-connection-settings-20261117/ui-final/`。

## Mac 对齐与验收

从 `codex/tab5-calendar-and-claude-idle-20261116` 拉取包含本文的提交。该提交不要求改动固件、版本号或用户配对数据。

1. 在 macOS 执行 `cd mac-app && swift test && swift build -c release`，然后用产物运行 `--self-test-parity` 与 `--self-test-tab5-ui <输出目录>`。界面自测新增屏保图库行及其管理动作，并核对设备卡片和小屏管理菜单。
2. 看设备中心和菜单栏快捷项里的 TAB5「连接设置」。打开后核对 Wi-Fi、USB 配对、固件升级和传输测速四页。ESP8266 的「管理」包含「手动刷机…」，「连接设置」保留「重置网络…」及取消保护。确认重置提示后使用取消验证导航。
3. 在「软件固件」检查四类更新。用测试发布记录核对「屏保图库」的状态、版本说明与管理动作，也核对应用已运行和冷启动时，点击系统通知是否选中对应组件。Mac 更新窗口当前没有 ESP8266 的运行版本，核对其显示「连接设备后查看」，不把未能比较的版本记为有更新。

Mac 原生构建、界面和系统通知验收待完成。Windows 的通知定位已通过离屏回归，系统实际送达和点击仍待实测。
