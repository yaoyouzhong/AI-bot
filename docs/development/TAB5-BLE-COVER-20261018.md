## 实现

- 普通用户桥接提供只读 `computer-control / lock-screen` 检查。必须当前会话仍锁定、前台 CoreWindow 属于 Windows SystemApps 中的正式 LockApp 路径且采样前后前台未变化，才返回明确封面证据。访问被拒绝或无法确认则保留未知；不访问受保护登录控件，不判断 PIN 内容或焦点。
- 仅打开原有蓝牙解锁面板时请求一次；结果绑定本次面板请求 ID。设备从请求派发起计算 1.5 秒有效期，包含通信往返时间；超时、旧桥接、不支持、未完成、未知等均不自动发空格，也不自动重试。
- 单次空格仍经过已认证/加密/绑定的 HID 连接、新鲜桥接身份、锁屏状态与连接代次门控。实际 key-down 前再次检查同一份未过期证据；仅发送 Space 按下及松开，不带 Enter、数字或其他按键。取消/超时/断连清理；释放按键尽力完成，发送异常不重放。
- 面板检查或发送期间暂时禁用 PIN 输入，结束后恢复原输入与确认流程；不增加按钮、不更改原有布局。提示只说“请求显示登录页”，不会声称已确认 PIN 框/凭据提供程序/焦点。普通权限无法确认 PIN 页时保留人工提示。
- 开发中的 Wi-Fi 路径保留原状，不使用本次自动空格；没有新增依赖、驱动、Windows 服务或 UIAccess 权限，不修改系统锁屏策略。

## 验证边界与后续真机验收

前一轮人工对照已观察到本机壁纸页的 LockApp 前台特征，而 PIN 页及刚锁屏过渡期可能都无权限读取。因此只使用正向封面证据，不能反推未知为 PIN 页。Windows 更新、不同登录状态或窗口实现变化可能使检测返回未知；应跳过自动空格。

采样、RPC 与 HID 投递是异步的，不能承诺与电脑上同时进行的手动界面切换原子同步。模拟验证通过也不能证明真实登录页已展开。待用户批准具体桥接/固件后按一项一次验收：

1. 停留锁屏壁纸页，从 TAB5 原解锁按钮打开面板，确认自动展开登录页且不输入 PIN 数字、不提交。
2. 电脑已经显示 PIN 页时重新打开面板，确认不再发送空格；由用户输入现有 PIN 完成真实解锁。
3. 检查取消、重复打开、断连/重连、超时后均不补发或重放；保留已通过的 PIN 清空与原桌面恢复条件。

新镜像与桥接只有上述主链路真机通过后才可记为自动准备功能验收通过。真实 PIN 不进入聊天、日志、证据或源码。
