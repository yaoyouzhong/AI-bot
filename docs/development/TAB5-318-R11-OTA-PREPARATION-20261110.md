用户确认安装后，正在结束的后台读取/草稿同步进入最多 12 秒的可见准备状态，按钮显示“取消准备”；期间停止新开非必要的后台读取，继续完成已有请求和草稿保存。准备完成后，仅对本次已确认的 offer/SHA 开始升级一次。取消、离开页面、固件改变或等待超时都不得启动写入。录音、发送、拍照、未确认送达和保存失败仍阻止升级，具体原因持续显示，直到下一次主动操作或更换固件。

电脑端继续使用现有升级状态和提示位置。被设备拒绝且尚未开始传输时显示“升级未开始”和该次拒绝原因，不以相同版本号覆盖结果。真正开始传输或重新选择固件后解除旧失败状态；精确镜像核验规则保持不变。

## 源码交接与限制

本目录同名 `.patch` 是 **R10 → R11** 的增量；先应用 R10 补丁，再应用 R11。R10 缓存优化未修改，源码摘要、补丁摘要与候选身份存于 `artifacts/t5-r11-ota-1110/candidate-evidence.json`。协议与公开版本未改变，Mac 无需增加新协议字段；Mac 原生界面若会用同版本心跳覆盖失败，需要在 Mac 上核对这一行为，Windows 测试不能替代。

R10 请求因 `device_busy` 在传输前被拒绝，那个具体忙碌标志尚未确定；不能因为显示欠载计数为零就断言肉眼不会闪。不得为安装绕过草稿或未确认消息保护。后续 R11 安装和现场观察见下方记录。

R10 聚合缓存修复回归中存在 R8 同样失败的 12 个缩放萌宠边缘像素差异，断言保留，没有记为通过。此项和屏闪实测仍需在发布前处理。安装后以精确 ELF 指纹和分区状态核验，再观察总览至少 5 分钟，必要时使用原包 R8 回退。

## 2026-11-10：升级被草稿同步阻断的现场定位

用户已授权 R11，固定交付目录已更新，但设备拒绝启动，传输为零。用户切换 Cloud → Codex 时一直显示“正在保存草稿，完成后切换”。桥接新增仅含 client 与状态码的诊断后，现场重复出现 Claude 草稿保存 404；实现检查确认 `ClaudeWorkspace.HandleAsync` 在执行草稿保存前要求会话存在于近期目录。实际原因是需保存草稿的会话已不在当前目录；旧固件在同步成功前既不切换也不开始 OTA。

Windows 桥接改为：已配对设备对合法会话 ID 的草稿保存及读取不依赖近期目录；消息发送、读取等会话操作仍需解析会话。会话不在目录且存在未确认送达时，空草稿保存返回冲突，不丢弃待核对记录。构建、合成真实加密存储和会话操作回归通过，覆盖不同设备隔离、缺失会话不可发送、未确认回执不被空保存丢弃。实际部署后，现场同类保存返回 200，用户确认 TAB5 自动切到 Codex；不记录用户文本或会话 ID。安装的桥接 DLL SHA-256 `af3e8b72d9ce568e96220c390c99c641f49644ea7f7c4238850d78e5162e262d`。此结果不证明 R11 已安装或总览屏闪已解决。

Mac 交接需检查 Claude 与 Codex 桥接处理设备草稿时是否依赖近期会话列表，并在 macOS 自行验证；这里尚未修改或验证 Mac。Codex 端是否存在相同场景也需单独验证，本次现场证据只涉及 Claude。
