# Mac 端开发指引（2026-11-03）

## 目标与入口

接收 Windows 及共用固件修复，完成 [Mac 对齐清单](MAC-ALIGNMENT-20261103.md) 中的实际差异，提供源码、测试和设备验收证据，为后续统一发布做准备。Windows 修复基线 `a9f56a1db126d73d8aa1ec4abef2663db39b565f`；本指引所在提交以 `git log` 和远端 `main` 实际结果为准。先阅读仓库 `AGENTS.md`、[统一开发发布流程](../DESKTOP-DEVELOPMENT-RELEASE.md)、[跨平台交接](WINDOWS-ESP8266-TAB5-HANDOFF-20261103.md)和对齐清单。

## Mac 上执行

1. 检查当前分支、`git status --short`、已有 worktree 和用户修改；保留这些数据。核对 `origin/main` 已含基线及本指引，再按仓库规则同步，不能覆盖本地工作。不要仅凭版本号认定二进制相同。
2. 逐项阅读实际调用方和设备协议对端，根据清单区分已具备、确需实现、需实测和平台不适用。优先解决 USB 重连资源去重与股票镜像；核实 Codex 监控能否从可靠的实际请求获得证据。没有可靠证据时维持未确认，不能把健康探测、登录或本地进程状态冒充模型成功。
3. 对 ESP8266 保持用户页面列表、顺序、间隔和协议 `version=1`，由固件负责变暗与恢复。先使用日志和离线测试定位，再进行有明确授权的设备操作；不得反复刷机猜测。资源缓存应在 ACK 成功后生效，变更内容、失败和新连接必须处理正确。
4. `cd mac-app && swift test && swift build -c release`；另跑对齐项的定向测试、设备链路及离屏预览。明确 Mac、Windows、固件各自的自动测试、安装和真实设备结果，不借用 Windows 测试当作 Mac 通过。
5. 真机验收包含小屏 USB 重插、切页、股票行情变化、镜像与设备一致、DeepSeek/GLM 同账户金额，以及 TAB5 当前适用的生日和告警场景。使用已有设备和账户；不记录凭据、Cookie、私人生日或金额。ESP8266 验收结束按项目规则恢复自动轮播并保留原顺序/间隔；TAB5 保留用户的展示设置。
6. 在交接记录中写源码提交、构建与设备证据、未验收项及各平台已发布版本。Mac 对齐完成后，按 [发布清单](../RELEASE-CHECKLIST.md)准备同一候选源码的双平台交付；发布前再取得相应授权，不自动推送、打标签、上传或公开发布。
