# Windows → Mac 对齐（2026-11-09）

## 范围、源码与交互设计

- Windows 来源：`origin/codex/windows-dynamic-microphone-20261105`，`6456c169c3f92222c1a233489da36af347b8ed28`。Mac 从原生 Claude 开发基线 `760a30b73621b4da33df8cccd2cbd0468f8a89ab` 继续。
- 对齐 Claude 原生 Terminal、Codex 桌面输入和语音。Mac VS Code、Windows 提权、COM、PickerHost 及第三方输入法不在范围内。沿用 TAB5 R4 的协议和交互；无需改动线协议、固件或发布版本。
- 现有横屏总览与回复页是这次的界面基线。列表同会话保持一个未读角标；接受下一条同会话输入时清旧角标，仅新的公开回复完成时再出现。精确轮次正文保持现有标题、字号、色彩、间距、翻页和返回区；已有读回执只在正文实际渲染后提交。重连只改变原发送按钮的灰色/可用状态，保留主次操作、按钮位置及触控面积。未确认输入目标时保持灰色。
- 权限沿用系统授权和现有语音状态；取消后保持原草稿，不触发提交。无新增弹窗文案、布局或动作。
- 开发与隔离测试已授权；真机测试留到次日。当前没有安装、刷机、推送或发布安排。

## 对齐清单

| Windows 行为 | Mac 实现 | 状态与证据 |
| --- | --- | --- |
| 同会话接受下一轮时清旧未读，完成后只提醒一次 | `MacClaudeNativeBackend` 从经会话身份核对的主支历史提取不透明轮次；`MacTab5Codex` 只在目录扫描处理完成。未连接或读历史不重置扫描记录。 | 已完成（离线）：两个会话，空白和侧支，先读后扫，暂时断联，重复扫描及跨会话隔离。 |
| 匹配最新有公开正文的结束轮次，读回执不制造未读 | `MacTab5Codex` 的 Claude `read` / `read-ack` 保持 device/task/turn、五分钟有效期和当前最新公开结束轮次核验。复用同绑定回执，满 80 条淘汰旧项；Codex 仍保留原桌面已读同步。 | 已完成（离线）：运行中后继、旧历史、跨设备和跨任务、超过容量的连续读取、过时回执。 |
| 所选原生 Terminal 会话优先重连 | `draft-load` 启动独立的所选会话探测，并每两秒复查仍选中的会话；批量扫描不持有 RPC 门锁。较旧的探测不能覆盖新状态；缩小 TAB5 帧时优先保留设备所选草稿会话。实际派发仍重新验证原会话和输入目标。 | 已完成（离线）：阻塞其他会话目录时可读、可载入选中草稿，选中控制先恢复，迟到断联结果不覆盖。真机耗时待测。 |
| 连接节点、提示和桌面输入兼容 | `MacClaudeHistory` 支持经身份核验的隐藏 `system/local_command` 连接节点；`MacClaudeTerminalRelay` 用淡色渲染和光标位置确认建议，普通同文草稿仍受保护。`MacTab5Desktop` 兼容两种 Composer 布局类名，仍检查附件、引用、目标与已有草稿。 | 已完成（离线）。已打开的 Apple Terminal 窗口只提供普通 AX 文本时无法确认淡色属性，歧义状态仍拒绝回填；待核对当前 Terminal 和 Codex 桌面实况。 |
| 首次语音授权继续原录音，取消不提交 | `MacTab5Voice` 等待 Mac 本地语音授权时保留该次录音及原绑定；授权前 TAB5 分片按序应答并丢弃，不保存、不送识别。只对仍有效的同一次录音启动原麦克风；TAB5 收音无需请求 Mac 麦克风权限。识别回到原有预览确认流程。 | 已完成（离线）：允许、拒绝、取消、重复回调、分片顺序、换设备请求及识别预览。首次系统弹窗与发送回执待真机。豆包继续走 Mac 既有独立实现。 |
| R4 共享回复界面 | 复用 Windows 交接的源增量和现有协议，不移植 Windows UI。 | 已完成（离屏）：原归档 1156 项摘要；R4 的 1006 个基线文件和 27 个改动文件通过 `--check`、`--apply`、`--verify`。真机待验证。 |
