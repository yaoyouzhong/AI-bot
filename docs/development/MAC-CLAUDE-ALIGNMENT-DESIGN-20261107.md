# Mac Claude 对齐：界面与状态设计

TAB5 用户在同一「对话」页选择项目和会话、查看回复、发送或返回。沿用已验收的
[来源标签](TAB5-SESSION-SOURCE-20261107.md)、[每会话控制](TAB5-SILENT-CONTROLS-20261107.md)
和 [回复状态](TAB5-REPLY-STATE-20261107.md)；Mac 只为既有 1280×720 横屏界面提供数据。
保留现有会话列表、标题及辅助来源标签的字级/颜色/省略规则，以及 72px 对话操作区、
间距和主次顺序。标签只作说明，未知与多端认领继续使用中性色。发送、追加和停止使用选中
会话的能力；未确认、等待、过期或撤权时对应操作禁用，草稿仍可读写。来源在断连时可以保留，
按钮权限不能保留。静默刷新失败保留已读到的正文及对应的完成状态；主动读取仍可报告真实失败。

macOS 设置沿用现有「TAB5 功能」窗口的 Claude 区块、系统字体、次要说明色、原布局和
开关操作区。Windows 交接已删除桥接代管审批入口，审批回到原客户端。Mac 不新增权限弹窗，
只在已具备权限、原会话在前台且输入可确认时接受原生写操作；只读观察不抢焦点。按既有最小
窗口及常用大小检查离屏布局；设备使用原设计的横屏预览和真机证据，不能以编译结果替代。

USB 验收预检发现，首次使用的 Mac 没有允许桥接读取 Terminal 选中标签的自动化权限。
在「Claude 会话」标题下增加一排系统样式次级按钮「授权 Terminal…」「授权 iTerm2…」，
沿用同页按钮尺寸、间距和左对齐，下面用次级系统文字反馈未打开、已授权或系统拒绝。
只在用户点指定按钮后对已运行的终端发起系统请求；处理中禁用该排按钮。不新增右键菜单项，
不把系统授权与原客户端的工具审批混用，后台观察仍不请求权限。最小窗口预览发现按钮
放在说明后会被滚动区域边缘裁切，因此将按钮放在说明前。按最小和常用窗口、浅深色检查。

Claude 列表与 Windows 一致，同名会话显示原名，不在标题前追加日期时间。列表仍按最近活动排序，
保留现有 80px 行高、标题和来源标签字号、颜色、间距、点击区和长标题省略。来源标签是独立信息，
同名会话仍按各自的会话标识选择；回复历史中的时间不变。

最后按用户要求撤回桥接发起的桌面授权入口：右键菜单移除 Codex 授权一行，标准菜单间距、
设备和退出顺序保留；左键与重新打开直接进入设备中心。取消自动弹出的应用引导和设置页新增的
Terminal 授权按钮。设置页保留原开关、系统字体、浅深色和次要状态，用短句说明系统不允许输入时
仍可查看；用户主动打开系统辅助功能设置是普通次要链接，不弹应用授权对话框。
普通功能继续默认开启，不改已保存的设置；操作受 macOS 实际权限和会话身份限制。
