# Mac 原生终端 Claude 会话

**产品验收未通过。** 用户要求 TAB5 无感接入 Terminal 或 iTerm2 中已经打开的普通 Claude Code 会话，完成读取、文字与图片发送、运行中追加和中断。交付条件包括保持原进程和原会话、沿用日常启动方式、无需逐个会话操作或额外系统授权。当前实现要求使用桥接启动命令，未达到此条件。下述通过项的范围限定为该启动入口的技术验证。

## 当前实验实现

用户在已有 Terminal 或 iTerm2 标签页运行桥接的 `--claude-terminal` 命令，直接使用原生 Claude Code 交互界面。需要接续历史时传入 `--resume <完整 UUID>`，在原会话退出后执行。桥接只向这个启动入口创建的本地 PTY 写入，标签页关闭即结束会话。普通入口打开的终端可查看历史。Mac「会话与权限…」的 Claude 会话区可以复制当前桥接的启动命令。此入口无需开启 macOS 自动化或辅助功能权限。

TAB5 沿用 1280×720 的「对话 → Claude」、会话来源「原生终端」、原会话标题、拍照和草稿列表。输入区、字号、颜色、间距与点击区保持一致。空闲时显示发送，运行中按当前轮次显示追加和停止。等待用户输入、有电脑草稿、目标失联或无法确定时暂停操作，原草稿和回复保留。Mac 功能页在 Claude 会话说明区添加启动提示及「复制终端启动命令」次要按钮，沿用次级标签样式、系统字号、标准按钮点击区和现有行距。协议使用现有会话能力字段。

启动器在当前标签页原样转发键盘输入和原生 CLI 画面，桥接通过同用户私有 Unix socket 联系它。派发须核对同一 UUID、进程和前台进程组、默认快捷键和空白输入区。图片沿用现有加密上传及本地引用回执。追加使用 Claude 的队列提交，停止只发送一次 Ctrl+C，并由原轮次的历史终态确认。

运行 `swift test --package-path mac-app` 后，在 macOS 上从仓库根目录运行 `python3 tools/probe_mac_claude_terminal.py`。回归在 Terminal 和 iTerm2 的环境标识下，用 Claude Code 2.1.318、测试 PTY 和本地模拟服务验证续接、保留电脑草稿、文字、三张图片、运行中追加和精确中断。没有前台窗口操作或实际模型调用。

## 已打开普通会话的接入调查

本机独立 PTY 试验中，外部进程向终端设备文件写入的字节只成为终端输出。跨会话 `TIOCSTI` 注入返回 `EACCES`。Windows 当前实现通过 `AttachConsole` 和 `WriteConsoleInputW` 操作现有控制台输入，Mac 当前实现尚无对应的接入链路。

Claude Code 2.1.318 的隔离普通交互会话能被 `claude agents --json` 识别，但该行没有可用于后台接入的 `id`。以 UUID 和名称分别执行 `claude attach` 均退出 1，原会话继续运行。模型请求只有本地模拟服务的一次测试历史准备。检查进程清理后没有遗留该试验的 Claude 进程。

安装版本公布的消息 socket 将入站内容标记为 peer 消息，并应用会话间消息接收策略。核对到的控制操作包括重命名、消息状态和空闲通知，缺少当前轮次的中断操作。此接口尚无满足完整验收条件的实现。

iTerm2 的 Coprocess 可以在目标标签页内手动启用，Claude Remote Control 可以在现有会话里启用并确认。这两条路径均包含额外操作。现阶段无感接入的产品验收继续保持未通过。[iTerm2 Coprocess 文档](https://iterm2.com/documentation-coprocesses.html) · [Claude Remote Control 文档](https://code.claude.com/docs/en/remote-control)

## 后续窗口接入方案的可行性

用户随后要求评估与 Codex 类似的终端窗口接入。此方案可操作已打开的普通 Claude 进程，已有会话和日常启动入口可作为目标。技术路径具备实现依据，状态为待实现及实机验收。

- 通过原生会话 UUID、进程代次、控制 TTY 和前台进程组核对目标，再匹配 Terminal 标签页或 iTerm2 分屏。每次输入前重新核对，目标变化或已有电脑草稿时保留设备草稿。
- 回复沿用现有原会话公开历史读取。发送和追加使用窗口输入，在原会话中核对新增用户轮次及送达回执。中断发送一次默认 Ctrl+C，并核对被指定轮次的停止状态。
- 图片可沿用已验证的本地图片引用输入路径，匹配原生记录中的图片回执。终端窗口中的照片输入、多图、追加及恢复剪贴板方案须分别验收后确定。
- 窗口输入使用辅助功能权限。通过 Apple Events 读取标签信息还需要对 Terminal 或 iTerm2 的自动化授权。macOS 按桥接签名身份和目标应用管理授权，普通会话可复用已授予的权限。权限是否已满足须在实际签名桥接中核对。
- 产品操作可定位或激活目标窗口后输入，前台切换行为须明确验收。自动化诊断遵循仓库后台要求，涉及实际窗口切换时由用户打开测试界面。

本机只读探针已获得 Terminal 窗口列表、标签 TTY 与文本区域结构，检查前后的前台应用一致。当前选中标签未匹配到已核实的前台 Claude 进程，未验证发送操作。本次诊断进程拥有的权限不能代替签名桥接的权限结论。iTerm2 当前未运行，本次只完成官方接口核对。
