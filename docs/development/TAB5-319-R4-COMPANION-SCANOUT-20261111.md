# TAB5 319-R4 Claude 等比缩小与扫描供数

以 [R3](TAB5-319-R3-COMPANION-DISPLAY-20261111.md) 为基线，应用[增量补丁](TAB5-319-R4-COMPANION-SCANOUT-20261111.patch)。应用和协议版本为 `0.2.319-ui`，内部修订为 `R4`。

用户选择保留当前 Codex 外形，只缩小 Claude。以原始比例按 `209/256` 缩放总览和屏保中的 Claude，相比先看的 `217/256` 预览再缩小约 3.7%。沿用 R3 的视觉中心、字体、颜色、卡片和触控区。六帧耳机素材、播放间隔和帧顺序保持一致。其他 Claude 状态沿用各自动作、相对比例和节奏。

R3 的稳定总览复现闪动时，LCD 欠载计数从 1 增至 2，后台缓存和 Flash 阶段空闲。欠载与视觉报告在相邻时间窗，支持继续定位 LCD 的数据供应，尚未定位每次争用的上游主设备。旧驱动以水平尺寸作为垂直欠载中断上限，可能漏报屏幕后段的欠载。R4 采用上游的全帧计数方式。 [Espressif DPI 驱动](https://raw.githubusercontent.com/espressif/esp-idf/master/components/esp_lcd/dsi/esp_lcd_panel_dpi.c)

针对固定 1024 个 64 位字的 FIFO，DMA 目的端单次补数从 256 字减至 128 字，启动补数的阈值从 768 字提高到 896 字。阈值与目的端突发大小之和仍为 1024 字。理论上多留 1,024 字节，在 80 MHz RGB565 有效扫描期间约等于 6.4 微秒的供数余量。保留既有像素时钟、面板时序、AXI 位宽、源端突发和亮度策略。用 `fifo,1,<阈值>,<突发>,<中断行上限>` 读回配置。能否抑制物理闪动需在同一台设备上验证。

构建只替换本次候选使用的 SDK 驱动副本，固定 SDK 和已构建的 R3 原包保留。诊断补丁在正常源码构建时由已有的脚本入口应用。

R4 镜像 7,052,768 字节，SHA-256 `56e4f8d0e0233f9a2805d7a3caa47ffba00243d083602fa79d04dc62dcf54b2c`，运行 ELF SHA-256 `99b390a574df08479be276551b89186495ac720ffa078d7715c237d3b6078e53`。固件、旋转、缓存与两套萌宠的真实 LVGL 回归通过。Codex 两处的工作画面与 R3 逐像素一致。用户随后要求 Claude 再缩小一档，本候选保留在历史目录，设备继续运行 R3。
