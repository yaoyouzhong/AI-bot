## 原因、设计与回归

- 原自动核对每次把按钮改成“查询中…”，随后改回“核对送达”，造成可重复的状态跳动。新逻辑在自动核对期间固定按钮文字和禁用态；三次自动核对耗尽或心跳不新鲜时恢复手动核对。底部继续显示送达核对状态，未确认内容和原请求编号保留，不重发。
- 渲染缓存允许切页动画期间暂用旧快照。复现测试证明：动画结束后如果缓存尚未重建，旧像素可以继续留在可见对话页；现立即对受影响区域安排正常重绘，不需要等待缓存重建。本问题与旧的实机“发送中”残留现象相符，但历史数据不足以证明它是当时唯一原因。
- 沿用原页面的文字、位置、尺寸、字体及颜色；自动核对按钮保持“核对送达”。横屏实际离屏渲染检查了核对中、确认后可输入以及真实固件 sidecar 更新说明的可读性、位置和留白。竖屏未做实际渲染验收。
- 本地 LVGL 回归：修复前按钮稳定性断言失败；旧快照释放后仍有 3335 个文字区域像素不一致。修复后 `TAB5_CLAUDE_APPEND_STABILITY_ONLY`、`TAB5_RECOVERY_ONLY`、`TAB5_CACHE_REFRESH_ONLY`、`TAB5_CLEAR_RENDER_ONLY` 通过，松手后差异为 0；覆盖未知回执、原编号查询、断线手动核对、确认后新输入、16 个清空重绘场景。相关日志保存在本地忽略目录。

## 真机验收

- `scripts/prepare_tab5_firmware.ps1` 正式校验并生成固定 `artifacts/firmware/tab5/latest/aibot_tab5.bin`，实际 sidecar 预览通过。USB 升级后验证精确 ELF、VALID 分区与三个实时界面样本，升级前后设备展示设置相同；正常桥接已恢复并重新持有 USB。
- 真实 TAB5 使用 USB、独立的模拟 Claude 会话和仅本机模型：先发送一条并保持运行，再追加一条。追加返回 504，自动查询两次仍为 504，随后同一回执返回 202；核对期间两次实际屏幕采样保持“正在核对送达记录…”和“核对送达”，原草稿保留。确认后未切页直接输入下一条并成功发送（202）；模型调用数与种子、首次发送、一次追加、后续一次发送一致，无重复追加。验证期间显示错误与欠载读数均为 0。
- 本次新固件的自动实机操作仅覆盖 USB，使用隔离模拟后台会话以遵守不得抢占电脑前台的规则；它不是 Terminal 原生窗口、Wi-Fi 或蓝牙上本次修复的实机证明。此前版本的 Terminal 和三种通道结果见基线记录，不能直接冒充本候选同条件复测。原始页面卡死的实际触发条件未能确定，持续观察；没有声称所有可能原因均已排除。
