# TAB5 长任务追加回执补测（2026-11-08）

## 范围与发现

- Mac／TAB5 联调，Windows 不变、协议未变。基线为 [追加状态与页面刷新候选](TAB5-CLAUDE-APPEND-STATE-20261108.md)中 BIN `88321ef2cb7c10ca3baf65826b493412db4427bc4066c3e33e40f3c0c2f11c6c`。
- 基线真机补测中，隔离任务持续超过前三次自动核对后，任务最终完成但设备不再自动查回执，草稿与输入维持锁定；手动选择“继续查询”得到 202。该行为可明确造成任务完成后仍需用户操作，不代表已证明旧截图的每个潜在原因。
- 本地增量 [补丁](TAB5-CLAUDE-LONG-APPEND-20261108.patch)在前两份 TAB5 候选补丁之后用 `patch -l -p1` 应用；已验证恢复出的基线可以 dry-run。用户要求修复并自行实机验收，未授权推送、标签或发布。

## 设计和回归

- 初次送达未知时先进行短间隔自动查询，之后每 30 秒查询一次**同一回执**，不重新发送原消息；无法启动查询时至少间隔 5 秒再试。未确认时保留文字、照片和请求编号；用户仍可手动查询，明确确认后才解锁输入。
- 使用原有布局、字号、颜色和操作区域。长时间未确认时固定显示“送达尚未确认，稍后自动核对”，按钮保持“核对送达”；查询中暂时禁用按钮，完成后恢复。横屏实际离屏画面和实际 sidecar 已检查文字、对齐与留白，竖屏未验收。
- 修复前针对第四次自动核对的回归失败；修复后 `TAB5_RECOVERY_ONLY`、`TAB5_CLAUDE_APPEND_STABILITY_ONLY`、`TAB5_CACHE_REFRESH_ONLY`、`TAB5_CLEAR_RENDER_ONLY` 均通过。覆盖长任务、原请求编号、30 秒间隔、断线退避、不重发、确认后输入以及缓存与清空回归。

## 固件与实机

- TAB5 独立工程构建成功，本地候选 `0.2.318-ui` BIN SHA-256 `4c4d3a015009c5cfdc136414f43e93cf2b83e8d0b6a59a50c6831b92c647a763`。经 `scripts/prepare_tab5_firmware.ps1` 校验、归档和预览后通过 USB 安装；精确 ELF、VALID 分区、三个实时界面样本和升级前后展示设置均核验通过。
- **真实 TAB5、USB：** 在隔离会话发起追加后等待，原回执多次返回 504，约 42 秒仍继续查询；模拟任务结束后自动查询得到 202，不切页输入并成功发送下一条。模型请求数对应首次发送、一次追加及后续一次发送，没有重复追加。
- **真实 TAB5、Wi-Fi：** 在 USB 上发起隔离追加后停止 USB 数据通道，保持蓝牙关闭。Wi-Fi 对同一回执多次返回 504，约 43 秒仍在查询；模拟任务结束后自动查询得到 202，实际画面恢复输入。随后恢复 USB，不切页输入并成功发送下一条；模型请求数量表明没有重复追加。
- **真实 TAB5、蓝牙：** 在 USB 上发起隔离追加后停止 USB 与 Wi-Fi 数据通道。蓝牙对原回执多次返回 504，约 48 秒仍在查询；模拟任务结束后自动查询得到 202，恢复 USB 后不切页输入并成功发送下一条；模型请求数量表明没有重复追加。设备设置前后相同，日常桥接已恢复 USB。
- 测试使用本机模拟模型和隔离后台 Claude 会话；Wi-Fi／蓝牙实际覆盖的是**回执查询、自动恢复与画面**，追加及后续发送操作通过 USB 发起，不将其描述为本候选的无线端到端发送验收。无线自动触控未绕过设备限制。
- 使用已安装桥接的只读检查确认：当前识别到 1 个可发送的 Terminal 原生 Claude 会话，Terminal 自动化与窗口输入权限就绪。追加只读实测在当前固件上分别用 Wi-Fi 和蓝牙从专用原生 Terminal 会话读取到 200，USB 上查看了上一轮实际公开回复；期间电脑前台保持 Codex，设置未变。当前固件仍未向真实 Terminal 窗口发送消息，也不以后台模拟会话替代原生窗口端到端验收；此前版本的 Terminal 三通道测试见 [Mac 验收记录](MAC-TERMINAL-ACCEPTANCE-20261108.md)。
