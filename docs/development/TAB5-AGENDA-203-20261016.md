# TAB5 203 存储与联网修复候选

2026-10-16。此前 202 的删除、屏保设置保存及 Wi-Fi 连接验收失败。经用户批准，配套桥接的 26 个文件已安装并逐一核验，正常桌面启动与资料保护检查通过；203 已通过 USB 刷入同一台 TAB5，精确 ELF、`ota_0 VALID`、持续心跳通过，Wi-Fi 自动连上。屏保设置与日程增删的实物操作验收及最终轮播收尾仍在进行，尚未公开发布。

## 用户最终保留规则

用户在本轮后续明确改为“最多 16 条、过期自动清理、不保留历史备份”，取代之前保留已结束记录的选择。203 两端自动清理已结束的单次事项，包括原来的过期记录；重复定义和无时间待办保留。设备未校时不清理，写入失败保留原记录、30 秒后重试。自动到期不增加删除队列，满额手动删除队列也不阻止到期清理；旧同步包不能恢复过期定义。界面去掉已结束筛选，新建过去的单次事项保留输入并提示调整时间。

下述“原三条记录无损／其他键保留”是迁移和 SDK 诊断断言，不代表部署后仍保留已过期记录。不新增日程历史或电脑文件备份；已有恢复文件不在本轮删除。
## 已确认的存储原因

- 24 KiB NVS 中还保留阅读位置、Codex 草稿、网络和显示设置。使用刷入 202 前的实际备份及固定 ESP-IDF NVS 实现重放，202 的 5,872 字节固定日程封套写入返回 `0x1105`。
- 原版 SDK 连续失败 100 次后，`saver_style` 一字节设置也返回 `0x1105`，复现用户“每日名画”下拉框保存失败。原日程与其余键仍在。
- 203 对 ID、时间及可变长度名称做无损编码，最多 3,574 字节；原有三条记录编码为 301 字节。启动读取旧格式后立即尝试原子整理，释放设置所需余量；失败继续显示完整旧记录并明确提示，不以空文档覆盖。不变更分区、事项字段、电脑 JSON、配对或用户屏保选择。
- 沿用 `agenda_v3` 键，读取 201 的 4,272 字节文档及 202 的 5,872 字节封套。201/202 无法读取新格式，降级须使用已有私有 NVS 备份或经过核验的同步副本。

## 写入中断保护

断电模拟在原 SDK 的第 117 个 Flash 操作位置重现日程键丢失。`scripts/apply-nvs-blob-safety.py` 修正固定 ESP-IDF 5.4.2 的最后一项重复检测：同键分块按 `chunkIndex` 区分；失败清理只处理此次版本，并在 GC 移页后重新定位。没有更换 SDK 版本或存储格式；保留上游 Apache-2.0 许可及来源记录。

`tests/nvs-replay` 编译实际 SDK 存储、页管理、CRC 和垃圾回收代码，使用仅在 RAM 中写入的 Flash 适配器。输入备份只读，不输出密码或原始数据。Windows CRT 测试失败改为 stderr 及失败退出码，避免调试弹窗。

修复后通过：100 次旧版失败后的重启迁移、三条原记录字段一致、最大 16 项加 16 条删除队列连续 100 次改写、29 个其他键保持不变、名画／书法设置写入及读回、132 个 Flash 操作位置的断电及重启。每次只能恢复完整旧文档或完整新文档，不能缺失或部分保存。这些不是实际硬件断电测试。

## Wi-Fi 故障与候选恢复

202 的设置／连接 API 均返回成功、SSID 读回匹配，早期没有联网完成事件，后续明确报 `NO_AP_FOUND` 且目标扫描为零。用户确认同名 2.4 GHz 已开启、其他设备可连接；电脑有线接口未连接。不能将电脑网卡地址选择当作热点扫描失败的原因，也尚未确认 Wi-Fi 与 NVS 同因。

203 增加由唯一 Wi-Fi worker 执行的站点停止／启动恢复：关联等待 30 秒、DHCP 等待 60 秒；长期无热点扫描也可触发恢复，自动重启冷却 120 秒。停止失败每 10 秒、启动失败每 2 秒重试；手动重新连接走同一站点重启路径。已联网时不自动重启，BLE 隔离作业先正常结束。不重启整个设备、不为普通 AP 故障给 C6 断电、不改密码。

USB 增加可选八字段 `wifiRecoveryDiag`，配套桥接只新增数值解析。原 `wifiDiag`、鉴权、USB/BLE 传输和 ESP8266 行为不变。实际 Wi-Fi 能否恢复仍待同一设备验收。
