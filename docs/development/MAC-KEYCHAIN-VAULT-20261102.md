# Mac 钥匙串单入口（实施前设计）

目标：减少桥接启动时逐项钥匙串提示。把桥接拥有的凭据保存在一个版本化钥匙串项目，应用进程成功读取一次后复用内存快照，拒绝结果也缓存，后台请求不反复提示。新安装由应用创建项目；已有旧资料先按允许名单完整迁移，成功后只使用新项目。不同 macOS 隐私权限仍由系统独立管理。

保持：配对令牌、TAB5 配对、私有加密密钥、供应商凭据字节不变；不输出凭据，不落明文文件，不因拒绝或损坏创建替代密钥。使用单用户跨进程锁序列化读取、迁移和修改，完整新项目保存成功才算迁移成功。结构／总大小有界；不支持的版本、无法读取任一旧项目或写入失败时停止，不建立不完整的新项目。

旧项目保留作为迁移前回退资料；新版本后续修改以新项目为准，不以旧项目回填缺失项。旧版本不能读取新项目的后续修改，降级前须核对配置兼容性，不能把旧记录当作最新备份。用户明确删除解锁密码时同时删除该旧项目，防止旧版重新使用已删除的密码。

系统若要求首次迁移分别授权旧项目，程序不能绕过其权限；本机已授权项目先以禁止交互方式迁移，不再自动弹出五次。旧项目尚未授权时，先显示原生“迁移旧版钥匙串资料”对话框：正文说明旧资料可能需要系统逐项批准、仅迁移成功后使用统一入口；默认“暂不迁移”，次操作“继续迁移”。取消或任何项目拒绝都保留旧资料，不写入不完整的新项目。系统原生字体及语义色，正文自然换行，沿用 NSAlert 标准间距和按钮区域，默认取消。此约束应在真实迁移验收中记录，不能保证任意旧包首次迁移都只需一次。

其余启动失败沿用现有提示，系统钥匙串提示由 macOS 绘制。测试覆盖新安装、完整迁移、拒绝、损坏、写入失败、进程内快照、并发修改、删除及旧数据不复活；随后构建、原生弹窗离屏检查和实机验收。

## 本地验证

- 最终 423 项 macOS XCTest、29,059 项隔离检查及任务追加回归通过；其中 11 项新测试覆盖资料迁移、错误／拒绝、快照复用、显式恢复、读取边界、旧协议及原值核对。
- 原生迁移弹窗已离屏渲染并查看明暗两种外观，文字与按钮可读，默认“暂不迁移”。首次预览使用调试程序的文件夹图标，改为系统锁图标后已查看签名包的实际明暗预览。
- 真实钥匙串迁移、读取次数及部署后定位仍待本机验收。`--prepare-keychain-vault` 在桥接实例锁保护下执行完整迁移并逐项核对原值，只输出结果／系统状态码，不输出资料。

首次本机核验在系统授权处等待超时，未确认迁移；系统元数据确认统一项目尚不存在，已恢复原桥接服务，候选未覆盖安装。为避免旧项目因辅助程序变化而再次询问，补充部署专用 `--prepare-keychain-vault-legacy-helper`：在同证书、合法父路径及旧协议校验后，通过原已授权辅助程序读取旧资料，再建立并核验统一项目。该迁移容器必须携带原辅助程序的精确字节；普通启动从不自动改用旧访问路径。旧协议标记阻止误把新辅助程序用于此模式造成递归锁等待。新候选使用 `LAContext.interactionNotAllowed` 控制非交互读取。

本轮安装前的应用以 ZIP 备份，避免把改名的 `.app` 留在“应用程序”目录并污染授权列表。本轮导出的 38 项固定设置及 29 份加密资料记录基线；原钥匙串值只在合法应用进程内比较，不导出为文件或日志。

## 最终安装验收通过

用户确认现在可连续核验后，将上述十分钟等待候选安装到 `/Applications/AIBotBridge.app`。截图确认系统询问的是统一项目“AI-bot Bridge 资料”，用户明确反馈此次只出现一次提示并完成“始终允许”；随后服务就绪、新进程收到 TAB5 USB 心跳。正常退出并重启同一包，用户确认没有再次出现钥匙串提示，直达定位成功；新进程后台记录定位 200。安装后二次核对：38 项固定设置、29 份原加密资料全部与基线相同，签名与主程序摘要匹配候选。现在运行的是统一入口候选，不是回退包。

已实测的是本机已有资料迁移、一次统一项目授权、同一包重启零次提示、USB 心跳及 Codex 定位；并未覆盖全新用户环境、不同 macOS 或不同正式签名跨版本升级，不保证系统权限永不再次询问。原钥匙串项目仍保留；后续修改以统一项目为准，降级前须核对兼容性。未推送、建标签、公开发布或刷设备。
