# Mac 录音麦克风选择优化（2026-11-01）

用户授权按评审建议优化。只修改 Mac 桥接，复用 Windows 自动优先 DJI、否则 TAB5 的用户语义；当前设备已在 Windows 更新最新 .302，不重新刷机。

## 实施前设计

- 场景：用户只需指定识别方式和下一段录音所用麦克风。将“收音设备／Mac 优先麦克风”合为一个“录音麦克风”列表，保留独立“识别方式”。
- 选项依次为“自动（优先 DJI，否则 TAB5）”、“TAB5 内置麦克风”、“Mac 系统默认麦克风”、实际物理输入设备名。不把内部音频转送设备列为普通麦克风。
- 现有640×600、最小600×500原生窗口，外边距24 pt、分节16 pt、字段8 pt，标题23 pt、正文13 pt、状态12 pt。沿用系统语义颜色、原生下拉框和按钮点击区；刷新在左，取消／保存在右，Escape／Return保持。两个字段后展示“下次预计使用”及“本次实际收音”状态。
- 自动只在开始新录音时解析，多个 DJI 不能随意选一个；指定设备断开必须明确报错，不切换其他麦克风。系统默认项直接使用当时的系统默认设备，不额外优先 DJI。实际启动使用本段冻结的设备，不通过改写用户偏好实现路由。
- 对照设备端既有调用，用户在TAB5显式选择内置收音（start.source=tab5或切换收音操作）可覆盖本段自动选择；返回的source仍只使用pc/tab5。旧配置的入口优先级保持历史行为，主动保存新策略后使用新规则。
- 只有显式保存才更新配置。取消、关闭、设备移除、检查失败和迟到回调不写入。保存前后台重新读取设备并复核；不因打开窗口请求权限、录音、切输入法或影响前台。
- 保留旧用户选择。旧 TAB5／指定设备可直接显示相应条目；旧“跟随入口”及“Mac 自动”不能无声改变含义，仅在这些旧配置下显示一个标明原行为的兼容项。新配置默认使用新的自动规则；用户主动选择新选项后才替换旧行为。
- 普通页不展示内部音频转送细节；资源缺失时给出必要的修复提示。未录音时使用“预计”，开始后才能报告实际设备，不能把枚举成功称作实际收音通过。

用户要求压缩备注／提示，并指出下拉框过宽。窗口改为560×480、最小520×420；两行表单采用90 pt标签、12 pt间距和340 pt下拉框，剩余空间留白，不再铺满整行。顶部只保留“保存后用于下一段录音。”。自动和系统默认的含义由选项名表达；仅指定设备及旧配置保留一条必要说明。状态区只显示预计设备、录音状态及需处理的异常，不重复展示“服务正常／设备检查通过／实际收音稍后确认”。保持原生字体、语义颜色及页脚操作区；长设备名在下拉框中截断并提供完整名称提示，状态可换行。实现后重新检查实际渲染。
