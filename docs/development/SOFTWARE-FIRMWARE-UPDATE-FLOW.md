# 软件固件更新界面设计与跨平台交接

## 界面设计

- 桥接设置卡片有可用更新时，标题右上显示深绿色圆底和白色向上箭头，副标题保留更新数量，沿用整张卡片的点击区域。沿用[已验收的圆形升级标识](../TAB5-ACCEPTANCE-164.md)，徽标由 26 点整体等比缩至 24 点或 DPI 对应尺寸，圆底为 `#21854A`。徽标中心距右边 29 点、距顶部 23 点，白箭头的轮廓中心比圆心略高约 0.5 点。无更新时恢复普通卡片。
- 软件固件窗口保持现有标题、版本表和浅色原生控件。选中软件或固件后，直接在表格下读取对应版本的分组说明。沿用 12–13 点正文和加重的小标题、项目符号、段落间距。说明区独立滚动，下载中心继续提供完整双语说明和附件。没有发布说明时显示明确的空状态。
- 底部提供一个组件主操作。软件和固件统一为「一键升级」，图库维持「管理图库…」。使用现有原生按钮尺寸和主色，下载中提供进度及取消。点击即授权所选版本升级。校验后桌面应用自动交接安装并重启，支持电脑端请求的 TAB5 会保存草稿并开始升级，已识别的 USB 小屏自动备份后再写入。系统授权、旧固件、USB 身份不明或手动安装场景显示对应下一步。失败或取消后仍在本页查看结果并可重试。
- 桌面双端设计。设备界面和协议沿用现有升级入口。

## 范围与交接

- Windows 和 macOS 使用同一按钮授权升级，分别调用原生安装链路。2026-11-19，用户确认 Mac 桥接和固件一键升级合入本地主干，固件模拟测试通过，真机刷写验收后补。Windows 代码保留在 `codex/software-firmware-update-flow`，待 Windows 原生验收后合入。正式发布仍待单独确认。
- TAB5 沿用已支持的电脑端升级请求、草稿保存与启动核验。ESP8266 沿用 USB 备份、写入和校验。Mac 读取已有 USB 回执和已认证 LAN 状态报告里的固件版本。无协议字段或固件版本改动。
- Windows 安装版在旧进程退出后运行安装器并重启桥接，便携版打开安装器。Mac 校验 App 标识、版本和签名，同卷替换并重启，受保护的位置提供已校验 App 的手动入口。
- Windows 验收分支为 `codex/windows-software-firmware-update-flow`，基于已包含 Mac 改动的 `main` 提交 `3a7f6e3`。Windows 源码与原开发分支一致。验收覆盖原生界面、安装包覆盖升级、便携版入口，以及 TAB5 和 ESP8266 的真机升级。

### Mac 完整桥接包升级复验

- 用 Mac arm64 本地完整签名包验证 `0.6.24 → 0.6.25`。源码为 `0f2d521b2b9e433eaeb8a4153bdc3d3b4497d9c3`，ZIP SHA-256 为 `b4bac86884d8b2a4e8dfe5eb08d6185cfcd4113981095783a3407181fbb9d189`。
- 在隔离 App 中点击原生「一键升级」按钮。先提供错误校验清单，确认失败后原 App 仍可重试。恢复正确清单后，ZIP 下载、签名核验、同路径替换、旧进程退出和新版自动重启均通过。新进程读取到 `0.6.25`，隔离设备配置前后哈希一致，安装后包内文件摘要通过。
- 升级起点为含新入口、重新签名为 `0.6.24` 的隔离副本。更新目录和响应在本机模拟，独立联网测试从已公开的 Mac `0.6.24` 下载 ZIP，通过 SHA-256 和 App 签名检查。隔离重启使用验收入口，未接入个人设备或测试日常账户的系统授权。
- 打包时执行 543 项 Swift 测试，跳过 4 项，0 失败。完整包严格签名检查、钥匙串 helper 身份和私有管道检查、离线刷机工具检查通过。日常运行的 Mac 桥接仍为 `0.6.23`。原 ZIP、启动回执和日志见本地 `artifacts/development/software-firmware-update/macos-bridge-install/`。

### 2026-11-19 日常 Mac 升级验收

- 使用上一节原 ZIP，将本机日常桥接从 `0.6.23` 覆盖到 `0.6.25`。最终从 `/Applications/AIBotBridge.app` 启动唯一进程，逐项核对运行 App 文件与原包清单一致。原开发候选恢复到备份前状态，两个 `0.6.23` App 与配置备份留在本机用户资料目录。
- 设备列表、日程、生日及常用任务文件的取样 SHA-256 与升级前一致。应用偏好仅变更权限巡检版本及刷新缓存，开机启动仍显示已启用。
- 两台实机接入后，新桥接已通过 TAB5 原配对，确认 USB、已认证 Wi-Fi 和蓝牙连接，成功只读获取实际显示设置。ESP8266 USB 握手和设备信息读回复核通过。LAN 服务已监听，钥匙串提供原状态令牌，未授权的状态请求仍被拒绝。
- 新版读到定位、麦克风、语音识别、通知、蓝牙、Terminal、音乐和系统事件自动化已授权。TAB5 的已认证 Wi-Fi 请求验证本地网络。Spotify 在升级前后均显示当前不可用。
- 升级前辅助功能已读作未生效。系统登记指向 `/Applications` 的临时签名旧副本，升级用本地证书签名包与该旧副本签名要求不同。macOS 27.3 的授权界面将按 App 控制和全系统保护覆盖分开，后者涉及更广的数据及输入访问。旧授权项已按确认移除，全面覆盖确认页已退出，授权范围待用户选择。公开 Mac 包升级权限兼容性需用实际公开旧包与拟发布原包另验。
- 用户最终确认全系统保护覆盖。系统设置确认授权对象为 `/Applications/AIBotBridge.app`，正常退出重启后系统授权页显示辅助功能已授权，只读检查显示 Terminal 自动化和窗口输入权限均就绪。
- 使用同一个 0.6.25 安装包和实际 TAB5，通过 USB 触控「Codex 直达」切到下一条会话并返回原会话。桥接记录定位 200 和目标会话标题匹配。测试只定位会话，诊断结束确认设备展示设置一致，日常桥接恢复并重新接管两台设备的 USB 连接。Terminal 本次复核升级后的授权状态，窗口操作沿用[既有实机验收](MAC-TERMINAL-LOCATE-RECOVERY-20261108.md)。

### 2026-11-19 Mac 固件一键升级模拟通过

- 从原生「一键升级」按钮启动。模拟发布目录和下载响应使用隔离测试数据，桥接实际执行下载、SHA-256 校验、解包和版本检查。发布版本等于设备上报版本时，两台设备的按钮均隐藏。

- ESP8266 模拟 `0.5.7 → 0.5.8`。校验通过后自动进入刷写流程。模拟刷写工具确认了完整备份及其 SHA-256、复核设备身份、写入、校验与新版本读回的顺序。
- 真机补验范围为 TAB5 的草稿保存、实际写入及启动核验，以及 ESP8266 的 USB 备份、实际刷写、重连和原展示设置恢复。
