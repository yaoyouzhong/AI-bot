# Mac 系统授权恢复

同路径测试中，macOS 对 0.6.28 临时签名记录了代码要求不匹配。0.6.26 的授权仍有效。另有一个独立的问题，天气定位一直等不到系统回调，使启动引导未走到系统事件和辅助功能。

保留原生授权窗口、列表和底部操作区。辅助功能行显示当前进程的状态，并引导用户在 Finder 核对当前 App。输入权限仍在辅助功能获准后单独判断。天气定位等待有上限，到期后其它步骤继续，定位可在同一页补办。默认 680 × 650 pt，最小 600 × 470 pt。沿用现有系统字体、间距、颜色和原生按钮，检查两种尺寸的授权状态与操作。

Windows 与固件没有对应改动。macOS 仍以自己的原生检查为权限依据。发布签名身份需单独处理：不同临时签名的代码哈希不可继承既有授权。要验证迁移，请用发布方稳定的签名身份构建新候选，并在实际安装路径确认首次授权以及后续同签名升级。切换签名身份的首个版本可能仍需重新确认。

用户报告在 macOS 完成几十秒的辅助功能授权后找不到原引导。重新打开应用或点击菜单栏图标时优先恢复还打开的引导，并在窗口重新获得焦点时刷新权限。已关掉的授权页可从菜单栏右键菜单或原生「窗口 → 系统授权」直接打开查看。

macOS 在临时目录运行 0.6.28、应用程序目录保留 0.6.26 时，将辅助功能授权写入了解析到的安装副本。授权引导现会检查两个同标识 App 的安装路径和签名摘要。未获得辅助功能授权的临时签名副本与安装副本冲突时，引导提示先安装，并保留安装后的自动核验机会。

已安装版本在升级后仍等待辅助功能时，页面先提示开启桥接。若开关已经开启仍未生效，页面解释如何仅移除辅助功能列表中的旧条目，再添加 Finder 定位的当前 App。系统权限由用户确认。

## 0.6.28 最终候选验收

Windows 无需对齐此修复。它没有 macOS 的应用签名和系统事件权限机制。本次改动未改变 Windows 授权流程或桥接协议。Windows 安装包已从公开 0.6.27 实测覆盖升级，自动退出、重启、设置和解锁记录保留通过。
