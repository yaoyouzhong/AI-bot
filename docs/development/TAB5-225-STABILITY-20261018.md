# TAB5 0.2.225-ui 解锁稳定性候选

范围：在已经通过 USB／蓝牙一键解锁实机验收的 0.2.224-ui 上，提高连接准备稳定性、保留失败原因、加快提交后的状态确认。包含前一轮尚未部署的 Windows 设置布局与 TAB5 音量间距调整。不安装 Wi-Fi 解锁组件。不自动部署或刷机。

候选源：`artifacts/development/unlock-stability-20261018/`。已部署 .224 与之前的布局候选保持不动。

## 失败分类与处理

| 情况 | 本轮处理 | 验证边界 |
| --- | --- | --- |
| 打开时连接／认证／订阅／桥接新鲜度／HID 暂未就绪 | 在同一连接、尚未发键或取用凭据的准备阶段，等待恢复；沿用 12 秒总预算，不延长 | USB/BLE 模拟七类初始缺口；实际首次失败原因尚未确认 |
| 准备期间普通电脑锁屏状态过期 | 尚未取用凭据时优先刷新只读状态，避免连续屏幕探测挤占普通状态更新；状态恢复后继续 | 已发键或已取用凭据时不这样重试 |
| 已确认的连接丢失／认证丢失／连接代次改变 | 停止，清空临时 PIN；不重新绑定当前面板，不改用另一通道 | 保留原有中途断连保护 |
| 黑屏／壁纸页／屏幕未知 | 保留已有 Shift、等待、新证据、最多两次 Shift、壁纸 Space 单次的限制 | 未增加未知状态发键或无条件唤醒 |
| PIN 未配置、配置不可读 | 区分固定错误码，提示在电脑端检查设置／重新保存 | 不读取聊天中的 PIN，不推断 Windows PIN 是否错误 |
| 凭据请求已消费、传输失败、加密信封无效、6 秒超时 | 记录不同错误，清空临时缓冲；不重新请求或重发 PIN | 测试取消后迟到回复、缓冲清零、禁止 Wi-Fi 凭据获取 |
| 发键中断、10 秒内未确认解锁 | 记录不同原因，停止重复提交；仍要求新的已解锁状态才成功 | 不把 HID 发送完成当作 Windows 已解锁 |
| 成功、取消、60 秒面板超时 | 保留成功提示约 500 ms 后关闭、取消清空；超时记录固定原因 | 正常成功清理不会冒充最近一次失败 |

## 等待时间

提交后前 10 秒，将普通状态确认周期从 2000 ms 调整为 500 ms，并绕过旧操作提示的显示等待；一次只允许一个电脑状态请求。面板关闭后恢复正常 2000 ms 周期。模拟核验 499 ms 不轮询、500 ms 轮询，不产生额外按键。

这只是减少成功检测的轮询等待，不是总解锁耗时保证。打开面板时针对黑屏电源通知延迟的 6000 ms 观察仍保留：现有 Windows 电源状态来自通知缓存，尚无可靠证据可将其全部取消。真实耗时改善待部署后验收。

## 可选诊断协议

Windows 与固件同时支持新增只读字段 `f`（8 位十六进制字符串），表示本次启动以来最近一次终止失败。关闭面板及后续成功不会清除；设备重启归零。不写 Flash，不记录 PIN、长度、键值、配对码或账户。

32 位布局：0..4 原因；5..13 缺失条件（连接、加密认证、键盘订阅、桥接新鲜度、HID 就绪、同连接代次、锁屏状态新鲜度、仍锁屏、键盘空闲）；14..16 准备阶段；17 USB；18 一键；19 已提交；20..31 操作序号模 4096。USB 另有 `unlockFailureUptimeMs`（设备运行毫秒，32 位回绕）。

原因：1 准备超时，2 唤醒中断，3 对端／锁屏状态变化，4 屏幕未确认，5 连接未就绪，6 凭据请求未启动，7 通用凭据错误，8 发键中断，9 未确认解锁，10 面板超时，12 PIN 未配置，13 PIN 存储不可读，14 屏幕未就绪，15 请求已消费，16 凭据传输失败，17 信封无效，18 凭据超时。序号不是总失败次数。

BLE 身份响应仍严格限制 512 字节；可选 `k` 当前状态与 `f` 历史错误轮换优先级，空间足够时同时返回，空间不足则省略可选字段。Windows 按设备缓存上次诊断样本，并标注 `hidSampleAgeMs`；这些字段从不参与认证或发键授权。USB 可选诊断装不下时保留原应答。macOS／旧桥接可以忽略可选字段；本候选 Windows 一键解锁行为不扩展到 macOS。
