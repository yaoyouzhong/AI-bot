# TAB5 320-R4：日历布局与总览欠载修订

## 范围与设计

在 320-R3 源码上应用同名增量补丁。协议版本保持 `0.2.320-ui`，内部标识为 `R4`。

1280×720 横屏总览右侧改为日历（436×328）与天气（436×160）两块，分别与左侧任务区和额度区对齐，间隔 24 像素。保留现有字体、卡片色和节假日颜色。时间居中，纵向坐标从 44 下移至 60；日期和星期同排，农历和节气同排。底部周历突出当天，普通「工作日／周末」说明不再重复显示，保留假期、调休、倒计时与生日。天气保留温度、湿度、天气图标以及「地区 · 天气」一行，两个区域各自打开对应详情。

离屏预览中的日期、天气与额度均是测试数据，不代表真实位置与账户。

## 屏闪证据与修订边界

320-R3 在总览发生用户报告的左侧闪动，设备的 LCD 欠载计数从 3 增至 4；亮度未变、显示错误为零。既有阶段码 32 只能说明最近一次 flush 回调已返回，不能断言后台 DMA 已完成。

读取固定 ESP-IDF 5.4.2 实现确认：`dma2d_connect` 每次把读、写通道重置为 128 字节突发，`esp_async_fbcpy` 没有覆盖该默认值；而项目的 PPA 填色早已限制为 32 字节。R4 在 framebuffer-copy 的两个通道连接完成后、开始 DMA 前，分别设为 32 字节，缩短与 LCD 扫描取像素争用内存的单次占用。保持面板时钟、扫描时序、FIFO 阈值、QoS、亮度及正常完成回调。

这是有源码依据的争用修订，不等于已经证明它是全部屏闪的唯一原因。上游也有减少 PPA 突发以缓解 DSI 欠载的记录，但该记录不能替代本设备的验证：[LVGL #9590](https://github.com/lvgl/lvgl/issues/9590)。

新增诊断后缀，不改变旧字段：

- `copy,1,32,<当前搬运中>,<搬运次数>`。
- 欠载时附加 `copyfault,1,<当时搬运中>,<距开始微秒>,<距完成微秒>,<上次搬运像素数>`；时间差使用 32 位无符号差值，应与有效位及次数结合使用。
- 在 DMA 开始前设置活动位，在完成回调释放图像所有权之前清除；中断只记录计数和时间，不打印、分配或等待。

SDK 补丁编译自本任务私有副本，没有修改共享 SDK。构建完成后原固件源码、构建目录与 SDK 已恢复并校验。正常源码构建仍使用 `scripts/apply-display-diagnostics.py` 应用同一补丁。

## Mac 对齐

这是共同固件变更，无需为新布局修改 Mac 桥接。Mac 可提供同一 R4 BIN 与匹配 sidecar；不得仅凭相同 `0.2.320-ui` 字样认定为同一镜像。新增诊断后缀可按可选字段保留显示，不要求改旧字段解析。

天气定位桥接修复属于另一项候选，见 `2026-11-12-weather-location-followup.md`；本次刷机未安装该 Windows 桥接，也不代表 Mac 已完成定位对齐。后续 R5 布局及整体交接见 [Mac 接续文档](MAC-TAB5-R5-WEATHER-HANDOFF-20261112.md)。本记录不是正式发布。
