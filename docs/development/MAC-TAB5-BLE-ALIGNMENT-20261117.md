# macOS 对齐 Windows 与 TAB5 交接（2026-11-17）

接收分支为 `codex/tab5-calendar-and-claude-idle-20261116`，审阅起点 `1e0b91b`。Windows 候选包、固件和既有实测见[原交接](MAC-TAB5-BLE-HANDOFF-20261117.md)。本轮只修改 Mac 桥接和验证记录，沿用当前设备固件和配对。

| 项目 | Mac 处理与验收边界 |
| --- | --- |
| BLE 状态帧 | 状态/资源逐片等 ATT 回执，只以认证的匹配序号推进完整状态的 delta 基线。局部超时或认证序号迟迟未匹配时，最多恢复两次；清掉基线，状态特征静默至少 5.1 秒，其间允许两个邮箱继续调度。超时写的回调迟到时，从该回调重新算静默。 |
| BLE 首次读 | 已认证连接上的邮箱首读 3 秒到期后释放当前调度，原邮箱等待迟到回调，其他特征仍可用；同邮箱最多允许两次连续恢复。CoreBluetooth 未提供逐次读取消或回调编号，因此在旧回调归来前不重发同特征读。原操作发出 12 秒还未收到回调时，等已开始的业务结束再重连。拿到请求头之后的通知窗口、认证失败与真实断线保持原失败路径。 |
| BLE RPC 重放 | 沿用 `rpcReplay` 能力协商与 `0x0e` 条件。只重放同一窗口的原有密文并逐片确认；在确认边界允许独立语音邮箱工作，返回时从原游标继续，不重复执行业务。暂停的 RPC 仍受原截止时间约束。 |
| 状态快照、图库 | Mac 已独立采集基础快照，Wi-Fi 另有后台成帧缓存；USB/BLE 仍在各自发送路径用快照组装含当下控制字段的帧。Windows 的完整后台成帧和 R3–R5 开发资料不在交接提交里，不能据此宣称等价。设备侧原链路重试由共用固件提供；慢采集、HTTP 响应头前重试和邮箱并行仍需设备证据。 |
| Claude 空闲 | `759a5f7` 已有 Mac 原生识别和日志兜底，无需重复移植。需验证真实终端空闲、工作、待输入、退出和多终端混合。 |
| 日历与总览 | 共用固件提供日历应用入口与 R6 萌宠单行。Mac 无需修改协议，真机需核对应用和总览两个入口、返回路径及数据。 |
| 解锁与 Codex 定位 | Windows WTS、登录助手和 Explorer 路径不适用；保持 Mac 原生授权和 `NSWorkspace`/辅助功能路径。实体按钮、目标会话和 Mac 系统解锁须单独验证。 |

CoreBluetooth 的[读值／通知回调](https://developer.apple.com/documentation/corebluetooth/cbperipheraldelegate/peripheral(_:didupdatevaluefor:error:)-1xyna)使用同一委托方法；[写回执](https://developer.apple.com/documentation/corebluetooth/cbperipheral/writevalue(_:for:type:))仅适用于有应答写。授权的通知窗口与首次读不重叠，超时后不复用对应特征，断开后等待系统断开回调再开始新一代认证。协议、认证、线速和传输优先顺序保持不变。

真机记录按实际桥接来源、可执行文件 SHA-256、固件 ELF 和实际通道登记。USB 管理口可以读取版本、启动槽及发起 RAM 测试；BLE 数据须由设备报告为 BLE。已有探针达到样本后会主动取消，取消后的未完成行不计作传输通过。
