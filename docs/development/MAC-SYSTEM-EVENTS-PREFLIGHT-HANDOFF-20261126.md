# Mac 0.6.34：系统事件预检与通知授权

本次为 Apple Silicon Mac 单端更新，以 `02a050c44af7e9368c72c819603563330aefac5e` 为基线。Windows 无功能改动、无需对齐或重新出包；工程仅同步共享桥接版本。设备协议、固件和签名身份不变。

## 场景及设计

打开桥接时，如果电脑控制已启用，后台核实一次 System Events。只读预检可以启动系统辅助进程，但不请求授权；同版本重启也会检查。授权页与启动共用该次后台检查，窗口刷新不反复启动辅助进程。实时确认已有权限显示「已授权」；辅助进程后来退出且刚才在本次运行中核实过，则显示「上次检查已授权」。若未得到确定结果，显示「尚未检查」和「检查状态…」，不计入待办、不自动要求授权。系统明确需要同意时，保留原来的授权入口。

沿用系统授权页 680 × 650 点窗口、600 × 470 点最小尺寸、112 点状态列、12 点行内间距、系统字体和原生按钮。用途说明旁仅补一句“尚未检查不代表未授权”，底栏不把未检查误报为缺权限；不增加对话框或改动其它行。上次测试的集中授权试验单独保留，不纳入本次定点补丁。通知、辅助功能、其它权限的检查和授权逻辑均不改。

## 系统通知独立授权（同一个本用户测试包）

先前隔离测试的系统日志显示：「系统通知」发出请求后，等到用户点击屏幕右上角的「允许」才返回，期间原集中流程无法继续。新设计保留原授权页的宽度、状态列、字体和按钮高度，只在通知这一行增加「允许通知…」和右上角位置提示；等待时在底栏提供「打开通知设置…」备用入口，不接管 macOS 弹窗。其它权限沿用原顺序，通知不进入集中请求队列，也不阻塞手动处理其它项目。只有通知待办时可以直接关闭。辅助功能不改。

Windows 不需对齐：UserNotifications 的系统弹窗位置、授权方式和回调均为 macOS 特有；不涉及协议或固件。与 System Events 分别断言，打入用户指定的同一个独立本机测试 App。

## 系统通知放在最后

在上述实测包之后，首装和升级引导补上最后一步：需要通知授权时，等其它自动请求及辅助功能的输入权限续步完成，再独立发起通知请求。引导不等屏幕右上角答复；用户关闭引导则不补弹，已授权或已拒绝也不自动重复请求。保留「允许通知…」和「打开通知设置…」作为稍后主动处理的入口。

原生界面沿用上节尺寸与布局。通知行文字同时适用于自动与手动触发，明确右上角系统提示的位置；引导副标题不再把辅助功能写成整个流程的最后一步。System Events 预检、辅助功能申请及其它请求顺序不改。Windows 无对应变更。

本机回归覆盖 System Events、辅助功能及其输入续步先请求，通知最后请求；通知答复仍悬而未决时，引导已结束。Mac 测试共 560 项、5 跳过、0 失败。Release 原生截图核对默认浅色和最小深色，右上角指引与独立设置入口保持可读。之前本用户组合包的真实授权结果仍有效，但该包不包含这次新增顺序，未替换日常安装或重新封包。
