# TAB5 回复打开、返回与 Windows 未读补验

用户在真机确认 VS Code 提交下一条后，TAB5 的旧未读消失；但第二轮完成后没有新提醒，普通“查看回复”仍显示第一轮。只读元数据确认 VS Code 第二轮于 17:27:30 完成，并有公开正文；没有输出或保存正文。用户同时报告新回复打开时会短暂显示上一条，返回后偶尔又进入回复页。

## 交互设计

Claude 和 Codex 共用回复页。维持 R3 横屏的标题、配色、字号、按钮位置和触控面积；“返回”一次回到原页面，下一次有意点按仍可立即在非重叠区域打开。等待读取未读轮次时，正文区域使用已有的“正在读取会话动态…”和“正在读取…”状态，不用旧正文填充，也不提前确认已读。已有的翻页及主动阅读位置继续保留。

## 原因和修复

- 两个按钮在不同层上，但触控区域重叠。用真实 LVGL 指针输入模拟间隔 60 ms 的第二次点击，R3 会从列表重新进入回复；这证明可能的触发路径，不能证明用户那次确实产生了两个点击。R4 仅在两个按钮之间拦截 250 ms 内落在上一按钮区域的第二次指针点击，程序导航不受此限制。
- 未读精确轮次未缓存时，读取代码保留上次的正文标签。R4 在打开时清除该标签中的旧正文，只接受匹配轮次的公开回复；错轮、读取超时及返回后的迟到结果不改变已读状态或重开页面。由未读入口临时固定的轮次不会被误存成主动选择的历史位置。
- Windows 的只读回复更新会覆盖用于判断“刚完成”的上一状态。测试先提交电脑端下一轮、再让读取先于后台完成扫描，旧版漏掉通知。候选把完成扫描的状态独立保存，读历史和短暂失去输入能力不能消耗完成通知；首次见到已有旧历史仍不触发新通知。
