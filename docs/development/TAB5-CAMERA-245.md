# TAB5 取景和拍摄控件方向 .245

## 已确认与待修复

`.244` 用户回复“三张增删和反复重开都正常”，三张附件删除补拍、每次删除后重开三次以及图库返回补拍这一轮内存回归通过。新问题是竖拿取景上下颠倒 180°，以及倒置横屏时“拍摄”文字未跟随。用户没有确认保存的 JPEG 是否同样倒置，没有读取用户照片。

旧代码在相机层可见或采集忙碌时禁止界面方向采样/应用；优化直出仅支持显示旋转 90°，倒置横屏 270° 回退到普通 LVGL 路径，原始相机图像又跟随界面多转了一次。新增真实 viewport 夹具在 `.244` 下确认倒置方向无法进入正确合成路径，保留 `baseline-244-direction-failure.log`。

## 修改

- 相机期间继续沿用既有横屏自动翻转/锁定策略采样。界面只提交方向请求，采集工作线程在帧边界、LVGL 互斥锁内先安全结束直出，再更新显示/触摸坐标、重建小控件快照并重新接管。CSI 不重启，三帧仍保留；按住手势时暂缓应用，显示交还失败时不修改坐标。
- 正反横屏均使用优化直出。传感器到物理屏幕的图像映射固定，按钮快照分别按对应方向合成，避免竖拿时受到上一次横屏方向的额外 180° 旋转影响。保留当前普通界面只支持两种横向的策略，不新增整套竖屏布局。
- 普通回退与拍后预览对相机图像取消界面的额外半转，校正整数像素中心偏移。LVGL 半转边界会丢一行一列，用独立边缘条补齐，只占 5,440 字节像素及少量对象/描述符；通过既有 LVGL 分配路径使用 PSRAM，不增加整帧申请。边缘缓存有明确父对象生命周期，删除时先销毁子图像再释放描述符。
- 保留原快门大触摸区、按钮位置、字体和颜色；文字与触摸坐标一起翻转，拍后照片像素及 JPEG 编码不变。本次没有修改 Windows/Mac 桥接、协议、附件格式、绑定、配对或显示偏好。
