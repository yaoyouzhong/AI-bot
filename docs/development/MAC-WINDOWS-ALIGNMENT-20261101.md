## 提交行为与状态设计（M01／M03，实施前）

场景为用户先在 TAB5 录音回填，再在同一电脑输入框校对，最后明确点击提交。原设备、会话、题卡和一次性票据仍是授权边界。最新非空文字在本次点击处理中冻结；原生动作前检查必须仍为原目标、同一编辑器和冻结文字。没有目标绑定的旧适配器保持原精确文字限制。动作后不再采纳新文字、切换接口或执行第二次提交。

不新增窗口或按钮，沿用现有菜单诊断、TAB5 提示与草稿位置。信息顺序是提交结果、具体原因、下一步；不显示内部标识或消息正文。明确未发送使用原错误区域，保留文字；已尝试且未确认显示“请检查电脑，不要重复发送”。普通会话和题卡分别使用现有协议的场景分类。状态变化的渲染检查须记录，不能把接口测试视为视觉验收。

| 状态 | 允许返回的事实 | 后续动作 |
| --- | --- | --- |
| 原目标上的电脑校对 | 冻结本次最新文字，保留原票据绑定 | 最终核对后单次原生提交 |
| 跨会话／切题／文字二次变化／附件／控件未就绪 | `submitted=false, attempted=false`，原场景的明确未发送原因 | 保留两端内容，不自动重试 |
| 已执行动作但送达未明 | `submitted=false, attempted=true`，未知回执 | 仅只读核对；票据不可重放 |
| 已可靠接受／保存排队 | 同目标的新消息或队列回执，沿用已有去重条件 | 成功；只清理匹配本次回填的本机镜像 |

## 设置界面设计约束（M09–M11，实施前）

沿用 AppKit 语义颜色和现有设置外壳：23 pt 标题、15 pt 分节、原生正文字号；外边距24 pt、分节间距16 pt、字段间距8 pt。Mac 使用左侧取消、右侧主保存，Return 对应保存、Escape 对应取消。关闭未保存内容时默认继续编辑，明确放弃才关闭；失败留在窗口内并保留输入。

语音设置在固定视口内展示识别方式、收音来源、麦克风和当前状态；音频列表后台加载，保存前以实时结果复核，加载中／不可用时有明确状态。常用任务沿现有600×470视口使用纵向列表，长标题换行、无横向滚动；计数包含列表外的原选择，取消不写配置。实施后检查实际离屏渲染和交互自动测试。
