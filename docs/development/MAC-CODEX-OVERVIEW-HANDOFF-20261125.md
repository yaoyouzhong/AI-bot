# Mac Codex 实时接口不可用时的 TAB5 总览

## 范围与设计

- Mac 发起；Windows 后续对齐总览的只读降级行为，不直接移植 Mac 实现。TAB5 协议 v1、显示布局及固件不变。
- 11 月 21 日 09:55（北京时间）新版 Codex 桌面进程启动；此前进程有 IPC 路由日志，此后没有。当前旧 IPC 拒绝连接；临时只读 App Server 仍能列出准确会话，但把该正在进行的轮次投影成没有结束时间的 `interrupted`。本机轮次索引则记录为 `inProgress`。
- 用户场景：总览应优先显示正在工作的会话，而不仅是最新的标题。保留原左侧项目／会话、右侧状态／萌宠，不修改尺寸、间距、字体、颜色、按钮、触控范围或状态文案。仍由已验证的桌面实时快照优先提供状态；只有旧端点不可用时，允许把同一会话的本机证据映射到现有「工作中」「空闲」；证据不足保留「状态未知」。备用信息只影响萌宠和总览选取，不影响回复、通知、等待细分或控制授权。

## Windows｜先验证，再对齐总览回退

- Windows 0.6.30 及当前主干已用 `CodexLifecycleTracker` 读取每个会话的本地生命周期，但 `Tab5LiveActivity.Uncertain()` 与 `Tab5CodexTasks.CaptureProjection()` 会把失败或过期的实时观测投影为 `unknown`，覆盖同一会话的本地萌宠状态。现有自测也明确要求已捕获的 owner 读取失败产生不确定状态。因此不能把已有的本地跟踪器算成已对齐的降级行为。
- **第一步：在 Windows 原生核实。** 记录实际运行的 Codex 客户端版本、桥接版本和 TAB5 固件／连接方式。用只读探针分别确认 `codex-ipc` 命名管道能否连接、能否取得同一会话的有效实时快照；在 TAB5 总览核对一条测试会话进行时及自然结束后的会话标题、状态与萌宠。分别记录「管道不可达」「管道可达但未取得有效快照」「实时状态正常」，不能用 Mac 复现结论代替 Windows 现场。
- **第二步：只改总览状态回退。** 已验证的实时快照优先。只有实时端点确实不可用、且有可靠的同会话生命周期证据时，才在总览投影「工作中／空闲」及对应萌宠。证据缺失、陈旧、矛盾或属于其他会话时保留「状态未知」；不能根据日志静默推断空闲。用 Windows 可验证的证据，不照搬 Mac 文件锁。不要修改发送、中断、控制授权、回复、通知、协议、界面布局或 TAB5 固件。
- **通过标准：** 离线回归分别覆盖实时快照优先、端点不可用且证据可靠、仅有不可信证据，以及控制不受降级影响。原生执行 `dotnet build windows-app\AIBotBridge\AIBotBridge.csproj -c Release` 和 `dotnet run --project windows-app\AIBotBridge\AIBotBridge.csproj -- --status-once`；用 TAB5 真机核对总览，保持原展示设置，在本节回填源码位置、版本、结果和未验项。如果现场端点仍正常，用隔离测试覆盖不可用分支，不把离线结果写成真机复现。
- Windows 回填：已对齐实现与原生专项测试，TAB5 实机待验证。Windows 端优先使用已确认的桌面实时快照；只有连接命名管道超时，且同一会话的根轮次属于当前桌面运行期、写入锁仍有效时，才为总览和萌宠回退到本机状态。控制、回复、通知和传输协议沿用原路径。
- Windows 现场只读核对：Codex 桌面包 `26.1120.6357.0` 由 `ChatGPT.exe` 承载，旧 `codex-ipc` 命名管道连接超时。修正后的生产读法用本机实际运行会话返回 `working`。Windows Release 构建、`--status-once` 和 `--self-test-codex-tasks` 通过。测试涵盖证据不足、过期、状态优先级和降级不授予控制。仍需在配对 TAB5 核对工作、自然结束及证据不足时的画面。
