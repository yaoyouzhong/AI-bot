# TAB5 322-R2 USB 解锁

在 [322-R1 源码](TAB5-322-R1-APPS-CALENDAR-20261116.md) 上应用 [R2 补丁](TAB5-322-R2-USB-UNLOCK-20261116.patch)。镜像中的公开版本字段为 `0.2.322-ui`，内部标记为 `R2`。

USB 本地解锁准备和单次凭据领取优先使用控制 RPC。安排送键后，复用认证的 `lock-screen` 请求，以 250 毫秒为最短间隔更新锁态。请求绑定的登录屏幕验证留给送键入口，Enter 仍要求最后一个凭据字符之后取得的新锁定状态。设备显示成功前需要同一连接上更新的已解锁状态，随后恢复完整控制状态刷新。

## 构建与安装

- ESP-IDF 完整构建、应用分区容量、画廊任务栈和绘制后端检查通过。离屏回归覆盖准备阶段优先级、单次 HID 提交、过期状态、完整状态恢复及三通道控制。实际 OTA 说明完成离屏渲染。
- BIN 为 7,070,768 字节，SHA-256 为 `714360453d6b61271926e900097673fed23eee475f541c451cb382e55d96d074`。首次 USB OTA 下载中断。Wi-Fi 恢复后重新升级，设备启动后从 USB 读回 ELF SHA-256 `724219f5f3478f5d2d237d50a518f7a86081fbe9abc1f6ae5ff6f2550d5308b3`、`ota_0 VALID` 及 `previousError=0`。

## USB 真机复测

通过 TAB5 原生触控诊断点击实际控制页。测试进程使用正式桥接的屏幕电源监听器、现有配对和已安装登录助手。每轮分别点击一次锁屏和解锁，通过 Windows WTS 以及设备的已认证 USB 回执交叉核对。每轮 Windows 锁定后约 2.10–2.44 秒发出解锁命令。

| 轮次 | 锁屏首试 | 解锁首试 | TAB5 面板打开到确认 | 自动命令发出到 Windows 解锁 |
| --- | --- | --- | ---: | ---: |
| 1 | 成功 | 成功 | 5.120 秒 | 6.915 秒 |
| 2 | 成功 | 成功 | 5.316 秒 | 6.869 秒 |
| 3 | 成功 | 成功 | 5.120 秒 | 6.820 秒 |
| 4 | 成功 | 成功 | 4.616 秒 | 6.326 秒 |
| 5 | 成功 | 成功 | 4.619 秒 | 6.280 秒 |

设备计时中位数从 R1 三轮的 7.569 秒降至 5.120 秒。R2 的送键前准备为 3.914–4.422 秒，安排送键至设备确认是 0.698–0.997 秒，仍高于 3–4 秒的目标。脚本计时包含指令送达 TAB5 和解锁面板打开前的等待。

首轮诊断配置遗漏屏幕电源监听器，导致两次送键前超时。另一次预定解锁前 Windows 已经解除锁定。表中只记录接入正式监听器后的五轮短间隔 USB 复测。结束后恢复了正常驻留桥接，核对展示设置、原桥接与登录助手摘要、USB 连接及 Windows 已解锁。原始日志和镜像保存在本机验收归档，R1 独立存放供回退。
