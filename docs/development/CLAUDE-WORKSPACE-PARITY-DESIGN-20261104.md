用户确认按 Codex 完整能力对齐，包括项目与历史会话、公开回复、草稿、发送/追加、语音、图片和中断。此前只读阅读页不代表完成本次范围。验收完成前不发布；普通功能默认可用，不增加功能授权勾选。工具操作仍沿用 Claude 自身的模型与审批策略，不自动批准。

## 使用场景与界面

TAB5 会话页复用现有 Codex 的 1280×720 横屏两栏布局。页面标题与底部入口统一为用户确认的“对话”，在左栏顶部提供 Codex / Claude 两个客户端分段按钮，各约 166×48px、间隔 10px；项目行下移 60px，历史会话列表保留 80px 点击行，左栏宽 390px，右栏宽 806px、栏间 24px。项目与会话 24px 字体、右侧沿用当前输入、阅读、草稿、图片与语音布局和既有浅蓝主操作色。0°/180° 横屏保持同一布局；不借此次改动扩展未支持的竖屏会话布局。

从总览进入 Codex 与 Claude 使用相同规则：常规入口统一为“查看对话”，有未读公开回复时为“查看回复”；两者都直接进入同一会话明细：常规入口打开当前轮次/最新公开回复，未读入口打开该会话对应的未读轮次。按钮沿用既有位置、尺寸、颜色与点击范围，客户端由卡片标题/桌宠和对话页选择器明确。已读只在对应公开内容实际渲染后确认，返回总览不清空草稿。手动切换客户端后恢复各自项目、会话、草稿和阅读位置；读取、发送、草稿同步、照片或语音忙时暂不切换，并显示已有风格的短提示。保存草稿后才完成切换，失败时保留原客户端与草稿。不得让 Claude 名称配 Codex 回复或附件。

用户进一步确认入口按实际可用目录显示：仅有 Claude 或 Codex 的对话目录时，只显示该客户端，单按钮宽 342px；两边都有对话时采用 166px 双按钮布局。最近成功目录在刷新失败时保留；尚无目录时显示“等待发现对话”。当前客户端消失时仅在保存完成且没有进行中操作后自动切到另一个；待保存草稿、未确认送达及其附件保留可访问入口，不能因目录暂不可用而隐藏。

总览入口必须按该卡片的客户端与不透明会话 ID 精确定位，不能沿用上次客户端或用“最近一条”代替。等待中的读取/草稿同步结束后继续这次明确导航；暂未同步到目录时等待该 ID，超时保留原页面并提示重试。另一个可用客户端仍可从工作区切换。桥接缩小状态目录时优先保留总览指向的 Claude 会话。

用户最终确认采用两字名称“对话”，与“总览、额度、应用”一致。左上角使用所有页面共用的 Noto Sans CJK 30px 标题，不增加英文前缀或单独的字体、字号、字重、位置覆盖；底部使用既有导航字体。

左栏先选择项目，再选择历史会话；无名称时使用“Claude Code”及活动时间，不以提示词或生成摘要代替标题。空项目、加载、离线或读取失败各有明确提示，失败保留最近成功目录与内容。右栏与 Codex 一样支持公开回复与轮次翻阅、草稿输入/恢复、语音转文字、图片预览/移除、发送、追加与中断。等待期间禁止重复提交，失败/未知送达保留草稿并提供精确请求核对，不通过自动重发猜测。

## 共同架构与协议

复用本项目现有会话界面、私密加密存储、草稿/送达记录、照片校验与语音处理。通过独立 Claude 后端适配器提供相同线程/轮次操作契约，不复制旧项目实现，不引入未知来源二进制。Codex 与 Claude 目录、草稿、附件、请求去重、缓存、语音目标和生命周期按客户端隔离。

TAB5 增加可选 `claudeTasks`，结构沿用 `codexTasks`；交互 RPC 带 `client=codex|claude`，缺省仍为 codex。Claude 原始 session ID、cwd 和日志路径仅留在电脑；设备使用独立不透明会话/项目别名。历史目录只同步项目名、既有会话名和固定状态元数据；正文按选中会话读取，排除用户提示、推理、工具输入输出。用户本次手工输入/选择的文字与图片按显式发送处理。

Claude 后端使用已安装官方 Claude CLI 的 stream-json 会话/控制协议，按精确 session resume，保持用户设置与审批方式，不用 continue 猜最近会话。发送前保存请求/草稿，结果绑定客户端、设备、会话、请求及轮次；重复请求复用送达记录。中断按控制回执及明确终态确认，不以单个 Stop 或静默推断完成。尚不能确认控制归属的外部执行会话保持受限状态，不能伪造可以中断或并发写入；能力差异必须在验收记录中说明。

先验两端后端与真实 CLI 的隔离模拟 API：项目/同名历史、无标题、损坏目录、失效会话、回复轮次、双客户端隔离、草稿及附件绑定、发送去重/未知回执、追加/中断、等待审批及失败；不得记录真实凭据或对话。随后执行原生构建与实际 LVGL 渲染，检查切换、长标题、列表与主次按钮，再用后台截图/点击/滑动工具进行真机操作。Windows 原生、真实语音识别准确性、物理触摸手感及尚无可靠来源的外部会话控制单独记录，不能由模拟或交叉编译替代。

总览状态与对话中的同一受控 Claude 会话使用最新的精确 CLI 结果；成功必须同时具备匹配消息 ID、completed、is_error=false 和正 num_turns。旧结果不能盖过同会话的新外部提示，另一会话的活跃或待确认状态继续按优先级选择。读取回复后清除完成提醒，不由日志静默推断成功。
