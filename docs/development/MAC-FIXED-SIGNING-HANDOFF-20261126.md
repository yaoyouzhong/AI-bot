# Mac 固定签名与内置更新交接

## 范围

- 发起端 macOS；Windows 和设备固件不需要对齐。证书校验和 macOS 隐私授权是平台专有行为，版本、下载目录及设备协议不变。
- `codex/mac-fixed-signing-updates` 从 `b00d8cf` 开发。当前仅构建隔离候选；不推送、不改变公开发行、不替换日常安装。构建用一次性测试证书不用于发布。

## 打包与发布身份

- `AIBOT_MAC_SIGN_MODE=fixed` 要求明确的证书指纹，App 与钥匙串辅助程序使用同一证书；可使用独立构建钥匙串。证书找不到、签名失败或指纹不符时停止，不产生临时签名替代品。ZIP 内 `MAC_SIGNING.json` 标明实际签名类型；它不是授权声明，也不代表 Apple 公证。
- 暂不改变 GitHub Actions 的默认签名。正式采用前需确定长期发布证书、私钥的存储及备份方式，并用确切的发布候选复核；不得把测试证书或私钥提交到仓库。

## 迁移、后续更新与设计

- **临时签名 → 固定签名：** 继续使用已验证的 GitHub 发布目录、SHA-256、应用标识和完整签名验证；临时签名本身没有可用于验证新发布者的旧证书。支持迁移提示的客户端在现有「安装新版 AI-bot？」附着式原生确认框中追加两句说明，告知重启后可能需要重新确认权限。更早的公开版没有这条提示：首次正式迁移要在该次更新说明中写清。只补办实际缺失的权限，不能静默授予或重置系统授权。
- **固定签名 → 同一固定签名：** 保留应用路径和标识。解包准备及替换前均核对同一证书、双向满足签名身份规则；包变更不因签名身份迁移提示用户。不同证书或临时签名均中止，不进入「手动替换」兜底。证书轮换不是常规内置升级，需要另行验证迁移。
- **界面：** 保持既有 800 × 640 更新窗口和自适应原生确认框；第一行显示版本变化，第二行显示重启行为，迁移说明单独分段、采用同一系统正文样式。主操作「安装并重启」，次操作「稍后」及 Escape 不变；普通同签名升级不多显示说明；签名不符复用现有更新状态区域。

## 验收

- 原生自动化覆盖临时签名过渡、同签名后继版、错证书与临时签名降级两种拒绝、替换前二次核对和原包保留。固定签名模式缺少证书指纹时快速失败。
- Apple Silicon / macOS 27.3 (26C5047e)：`swift test` 557 项，4 项跳过、0 失败；证书过渡和拒绝回归已实际执行。Release 构建、证书匹配、解压 SHA-256、许可证、包内刷机工具自检均通过；没有访问设备。发布工具两套回归通过。
- 使用隔离配置和内置更新入口，原生验证：本机临时签名 0.6.32 的原样副本 → 固定签名试验版、含迁移提示的临时签名试验版 → 固定签名、同签名下一版；均收到新进程、旧进程退出、版本及配置一致的回执。CLI 驱动与系统重新打开的进程归属不同，不能用这些回执做辅助功能继承结论。浅色和深色迁移确认、普通更新确认的实际 AppKit 图像已目视检查：无裁切，说明和按钮层级保持原样。
- 本地证据：`artifacts/mac-fixed-signing-20261126/`（包括原生回执和截图）。固定签名 ZIP 为 `AI-bot-bridge-v0.6.31-macos-arm64.zip`，19,948,421 字节，SHA-256 `984007a6a07a3d07698a62cc311fcbd9da29f0eee6d484841c0163212003bbae`。构建基线及未提交补丁单独留证；这是本机隔离候选，不是可直接公开晋级的包。试验版编号不是产品版本。
- 该机早先的独立标识真授权实测，已覆盖浏览器首装手动放行后，同证书内置升级保留辅助功能。本次使用另一个独立标识 `AIBotSigningMigration.app` 和当前内置更新逻辑，走完整授权路径：临时签名 1.1.0 获得辅助功能权限后，于 13:08:59 执行更新；固定签名 1.1.1 于 13:09:00 自动启动，未被系统阻止，但新进程读到未授权。系统列表不再显示旧测试条目，重新添加当前测试 App 即可，不需要先删除。重新授权后，1.1.1 于 13:12:53 更新；同证书 1.1.2 于 13:12:54 自动启动，第一次权限检查为已授权，无需再授予。两次均保持固定安装路径，旧、新进程分别确认。原始回执和汇总保存在本地 `artifacts/mac-fixed-signing-20261126/tcc/`。
- 测试结束后只重置测试标识的 Accessibility，通过新进程复验未授权；关闭测试 App 和回环更新服务，日常桥接未重启或替换。
