## 相机修改的关联

`.242` 将相机三帧在启动时预留，解决反复拍照时大块申请被碎片化的问题。相比 `.241` 相机关闭后多保留两帧，共 3,686,400 字节。旧图库仍从通用堆单独申请横、竖两幅 RGB565 帧，单幅 1,843,200 字节；两个子系统没有共用这些空闲的预留块。

本地对真实 `.250` 解码片段注入连续整帧申请失败：即使存在空闲预留帧，旧片段仍无法解码竖版；相同测试在修复后通过。该回归验证资源交接缺口，不能代替新固件真机验收；现场没有采到失败瞬间的最大连续块。

## 本地修复

修复保存在独立的 `artifacts/development/gallery-orientation-20261022/source/`，补丁为同目录上一级的 `GALLERY-ORIENTATION-FIX.patch`，共六个实现文件和五个测试文件。

- 相机空闲时借给图库最多两块预留帧，始终排除保留照片所在的帧。相机运行、JPEG 租约占用或停止失败隔离时，不再借出新帧。
- 图库解码、显示、备用帧与待收结果沿原所有权链移动。回收预留块只归还所有权，不调用 `free`；普通堆申请的块仍正常释放。
- 打开相机前先在界面线程脱离图片，再等待 worker 退出，释放待收结果和备用帧；所有借出的预留帧归还之后才允许 CSI 使用三帧。未归还仍保持原四秒等待、取消与报错路径。
- 保留普通堆分配回退和现有失败重试；实际输出申请失败时另外记录 `ESP_ERR_NO_MEM`，避免再次把阶段 6 / 错误 0 误读为成功。

保留分辨率、三帧相机、三张附件、照片内容、配对和设置；没有增加常驻整帧。另一聊天仍在处理 `.251`，本聊天没有覆盖其共享工作源码、固定 latest 入口或已授权的安装内容。隔离源码已从其冻结的 `.250` 基线恢复同时修改的文件，避免把正在编辑的 `.251` 测试片段混入本次验证。
