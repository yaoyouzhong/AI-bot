# Mac 一键解锁与豆包接入候选 · 2026-10-23

## 一键解锁调查与连接验证

用户要求普通权限桥接优先，并询问是否需要像 Windows 一样安装 VNC。此前对系统认证组件的提问只是路线讨论，不构成安装授权；本轮没有安装认证插件、修改认证数据库、开启服务或刷机。

实际只读检查发现：系统设置“通用 → 共享”中的屏幕共享已经开启，VNC 密码控制已经开启，访问范围为指定用户。`127.0.0.1:5900` 返回 `RFB 003.889`，协商 3.8 后提供认证类型 `30,33,36,2,35`。没有选择认证、读取密码、读取画面或发送按键。现有服务无需重装。

新增“电脑控制 → 一键解锁设置…”连接验证窗口，仅连接 IPv4 回环固定端口。用户在本机填写已有的 VNC 专用密码，按 RFC 6143 做一次标准 VNCAuth 认证及共享会话初始化；不使用无认证模式，不自动重试，不请求画面，不发送按键，不保存密码。密码与响应不进入日志、偏好、导出或网络 RPC。

这只是输入通道的第一步验证，不能证明锁屏解锁成功。后续仍须证明连接目标是当前本地会话、锁屏时可用、密码页准备可靠、错误／取消／断连不重输，以及真实解锁回执。Mac 登录密码尚未采集，`oneClickUnlock` 仍为 false，`lock-screen` 的授权字段仍未知，不把显示用通知改成输入授权。

用户已自行重设系统中的 VNC 专用密码，并在本机验证窗口执行认证，回报“VNC 认证与会话初始化通过（3456×2234）”。这确认实际 VNCAuth 与共享会话初始化已经通过；没有读取画面、发送按键或采集 Mac 登录密码。没有从系统或聊天读取、恢复或复用其 VNC 密码。锁屏连接与实际解锁仍未验收。旧调查中 `.234` 固件只支持数字的限制不能推断到新 Windows `credentialVersion=2`；已读新 Windows 字母／符号路径，但本机实际 TAB5 固件能力及 Mac 硬件键盘准备仍未验收。

后续本机候选增加“15 秒后验证锁屏连接”：用户重新输入 VNC 专用密码并点击后，手动按 Control-Command-Q 锁屏，约 25 秒后自行解锁查看结果。只做一次同样的认证及共享初始化，不请求画面、不发送按键。取消、关闭、睡眠或超过倒计时容限会丢弃待用凭据，不自动补做；在途连接检查取消状态，迟到结果不能覆盖新验证。结果中的锁屏通知只是显示参考，未被当作密码页、目标会话或实际解锁证明。即使延时连接成功，`oneClickUnlock` 仍为 false。此项需用户在本机输入密码并手动锁屏，尚未实测。

用户随后实际锁屏并回报“没有反应，没有解锁”。读取 r19 窗口结果确认：延时 VNC 认证与会话初始化通过（3456×2234），开始连接时曾收到锁屏通知。这是仅连接检查的预期行为，不是解锁后端失败；此前按钮及交接不能让用户误以为会执行解锁。锁屏通知仍不是输入授权。

后续候选新增独立的“15 秒后尝试解锁一次”，与“仅检查连接”明确区分。只在用户本机输入两个密码并点击后倒计时；不保存 Keychain、不从系统恢复密码、不增加 RPC 或 TAB5 能力。使用公共 AX 接口核对当前 UID 仍在本地控制台、焦点进程是 Apple 签名且位于固定系统路径的 `com.apple.loginwindow`、当前焦点是其安全密码框，且公开字符计数为零。认证完成后再次确认同一字段，发送一个临时标记并删除，以 AX 字符计数确认这个 RFB 连接实际到达相同的本地密码框；然后逐字符确认、仅追加一次 Return。只接受 1–128 字节可打印 ASCII，包括英文大小写、数字和符号，其他字符直接拒绝，不截断。没有读取安全字段的值、屏幕或剪贴板。

这是尚未实测的输入候选，不假定 macOS 一定开放登录窗口 AX 或字符计数。接口拒绝、焦点变化、字段非空、标记未回显／未删除、取消、断连或超时均停止；不使用显示通知兜底、不盲输、不自动重试。一个进程同时只允许一次解锁测试，部分输入或临时标记可能需要用户手动清空。公开接口观察和后续网络输入不是原子操作，仍有异步竞态；本候选不将输入发送成功称为解锁成功。完成后只显示“已提交一次登录输入，尚未确认解锁”，实际是否自动回到桌面需用户确认。尚未采集登录密码或执行真实输入，`oneClickUnlock` 仍为 false，Windows／固件／既有协议不变。

用户随后执行 r20 测试并反馈：未解锁，界面仍为“指纹或密码”，密码框没有出现，也没有输入光标。本轮未取到上次窗口的具体错误文本，不能据此断言是哪项 AX 调用失败。代码核对确认 r20 在创建 VNC 输入会话前便要求密码框已聚焦，没有密码页准备步骤，存在实际流程缺口。没有读取用户在测试中输入的两个密码，没有恢复或持久化它们，也没有将该次失败标为解锁成功。

r21 将顺序改为先认证 VNC，再确认当前控制台及 Apple 签名的登录窗口，不再要求起步时密码框已经有焦点。优先读取当前焦点或有界遍历当前登录窗口的安全字段（不读取文本、账户名称或 AXValue），仅在能确定唯一目标时设置公开 `AXFocused` 属性并重新确认实际焦点。若尚未出现安全字段，且仍能确认同一 Apple 登录窗口，最多发送一次非打印 Tab，再作有界只读等待；不发送 Space、Return 或密码作为准备。未知前台、多个候选、结构超界、取消、超时或不确定写入均停止。准备成功后仍必须通过原有的空白计数、RFB 标记／删除回显和逐字符检查。AX 接口是否对本机锁屏开放、Tab 是否能显示密码框、实际焦点与解锁仍需实机验证，不能由隔离测试代替。窗口增加阶段提示和仅内存中的最后结果，关闭再打开可查看，进程退出即丢弃；不增加凭据存储或设备能力。

用户再测 r21：密码框已出现但未解锁。本轮重新打开实际窗口取得保留结果：“密码框准备后未能确认空白字符计数（AX -25205），未发送登录密码。”Apple 文档将 -25205 定义为 `attributeUnsupported`；结合调用顺序可确定此次在密码框准备后的字符数读取处停止，尚未进入登录密码输入，不能说是密码错误。旧实现错误地把安全字段必须公开字符数作为通用前提。

r23 仅对明确的 `attributeUnsupported` 采用受保护字段模式，既不把未知字符数当作零，也不将其他 AX 错误当作兼容情形。可读计数字段沿用原有空白／标记回显检查；受保护字段改为同一登录窗口中的一次焦点往返：在原密码框按一次 Tab，确认焦点移到同一 Apple 登录进程内另一明确元素，再发送平衡的 Shift-Tab，并确认回到完全相同的安全字段。未知焦点不能当作已移出；取消、超时、焦点未变化／未返回、任何不确定写入均停止，不重试。之后每个密码字符输入前后仍检查当前控制台、签名登录窗口及原字段焦点，最多一次 Return。该模式不读取 AXValue、文本、密码长度、画面或剪贴板，也不声称能从接口证明空白或每个字符已落地；用户需保持新锁屏后的空白输入状态。实际解锁只待人工验收，`oneClickUnlock` 仍为 false。

本轮还试验了“当前 TCP 连接 PID 加 Apple 服务签名”校验。交互式系统工具可取得连接信息，但由本机编译应用启动的 `netstat` 返回空表；原因未确证，不能把它当作可用的普通权限依赖。r22 仅为本地诊断原型，未替换运行。该依赖及诊断命令已从 r23 源码移除，未借此修改权限、开启服务、使用管理员权限或请求额外授权。r23 使用上述不读取文本的输入路径证明，且仍保留全部焦点与会话门控。

参考：[Apple `AXError.attributeUnsupported`](https://developer.apple.com/documentation/applicationservices/axerror/attributeunsupported)。

参考：[Apple 屏幕共享](https://support.apple.com/en-gb/guide/mac-help/mh11848/mac)、[RFB RFC 6143](https://www.rfc-editor.org/rfc/rfc6143.html)。DES 仅为现有 VNCAuth 协议兼容，连接限制为本机回环；不作为新密码存储或网络加密方案。

### r25：先定位 VNC 键盘接收

用户返回且运行窗口保留结果确认 r24 的提示：“VNC 键盘输入未通过大小写／数字／符号校验，未发送登录密码；无需锁屏。”只能确认公开测试样本未匹配，不能区分无按键、延迟、大小写或其他映射错误。独立的隐藏 AppKit 夹具向自建安全编辑器插入公开样本，确认编辑器 `.string` 和控件 `.stringValue` 均匹配；此项不代表真实 VNC 输入已通过。

r25 在实际输入会话中补上标准像素格式、仅 Raw 编码及一次左上角 1×1 更新请求，收到单个符合范围的 Raw 矩形后丢弃四个像素字节，不渲染、返回、记录或持久化。只接受固定范围，拒绝整屏、额外矩形、未知编码和剪贴板消息，不解析剪贴板载荷；空更新／Bell 的数量也受限。连接检查入口仍只认证，不发更新或按键。RFC 本身不要求先更新才能输入，因此这是针对 Apple 服务的兼容诊断，尚未证实为本机故障根因。

增加“仅验证键盘（无需锁屏）”：只需 VNC 专用密码，不需要 Mac 登录密码、辅助功能授权或锁屏操作。认证与上述最小初始化后，仅在自有测试框验证公开样本，不进入解锁倒计时，也不提交登录。测试消息区分未收到字符、大小写不符、其他字符不符和失焦；本窗口的局部 AppKit 监视器只在测试框活动时计数按下／抬起，不读取字符或 keyCode，不观察凭据字段或其他应用。读取次数只显示在当次固定结果，不导出或持久化。每字符等待上限从 0.6 秒改为 1.25 秒，整体公开样本仍限 6 秒；不重发按键。取消、关闭、失焦、异常均清理测试框与局部监视器，登录密码仍无持久化，设备一键解锁仍关闭。

### r26：图像响应不再阻挡键盘检测

用户实测 r25 在“桌面初始化区域或编码不匹配”处停止，尚未发送公开测试按键或登录密码。该次实现只保留了固定错误，未取得具体矩形／编码值，不能推断某个 Apple 扩展或实际返回尺寸。r25 错误地把图像响应必须精确等于一个 Raw 像素作为键盘前提；RFB 输入与图像更新是独立消息，纯键盘桥接不需解码图像。

r26 保留认证、共享初始化、标准格式／Raw 编码声明及一次 1×1 更新请求，但准备函数只发送消息，不再读取或等待图像响应。公开测试字符在自有窗口的准确回显仍是进入解锁倒计时的必要条件，未降低固定回环地址、VNCAuth、当前控制台、签名登录窗口或原安全字段焦点要求。键盘检测失败时，在未取消／未过期且套接字仍有效的情况下，最多非阻塞窥看已到达的 FramebufferUpdate 首矩形头：先确认类型与非空计数，再取得固定 16 字节头，仅显示矩形数量、坐标、尺寸及有符号编码编号。缺失、不完整或其他消息直接略过，不等待、不消费流、不解码像素／剪贴板／名称载荷，结果只作诊断，绝不授权输入。没有图像头解析成功也不会产生新的前置失败。未启用设备解锁，未保存密码，真实 VNC 键盘与解锁仍须本机验收。

参考：[RFC 6143 输入协议](https://www.rfc-editor.org/rfc/rfc6143.html#section-4) 及客户端消息定义。后续诊断头只用于定位，不能把它当作桌面已验证或解锁已成功。

### r27：改用当前 Mac 账户认证

用户实测 r26：“未收到第 1 个测试字符”，自有测试框按下／抬起均为 0。只读系统日志进一步确认：此次 VNCAuth 连接进入 session 265 的独立虚拟登录会话（`onconsole 0`、`vfb 1`），物理桌面仍是 session 257（`onconsole 1`、`vfb 0`）。r25 也进入了独立虚拟会话。认证成功不代表连接到了本地当前桌面；此前图像精确匹配、焦点往返或按键时序均没有解决这一会话选择问题。日志在忽略目录 `artifacts/mac-vnc-input-system-r26.log`、`artifacts/mac-vnc-session-system-r26.log`，不包含密码或图像。

r27 独立实现 RFB security type 30 的 Mac 账户认证，使用当前 `NSUserName()` 和用户在本机窗口明确填写的 Mac 登录密码。新增“用 Mac 账户验证键盘（无需锁屏）”，不再要求该入口填写 VNC 专用密码。VNC 专用密码入口保留为仅连接检查，明确说明其本机实际会话边界。账户密码用于本机 Apple 屏幕共享认证这一用途在按钮旁说明；代理不代填或执行有凭据动作。当前账户是否实际进入物理桌面，仍以该窗口公开样本的逐字符回显验收，不能由握手或编译推断。

连接固定为 `127.0.0.1:5900`，仅接受 Apple 的 RFB 003.889 标识及 type 30，不降级为无认证或 VNCAuth。发送凭据前两次核验系统 launchd 的 `com.apple.screensharing` 任务路径、程序与同一 PID，并用公开 Security 接口核验 Apple 签名、daemon 标识和固定系统 bundle／可执行路径；这不是 TCP 对端 PID 的直接证明。客户端从不启动／配置服务或改变访问范围。公开握手确认本机使用 4096 位 DH；采用系统公开 Security CSP 的有限域 DH、协议规定的 MD5 派生及 AES-128-ECB 兼容包，未复制第三方实现或引入外部加密工具。弃用的 C 接口隔离在本项目 C target 中，不使用私有 API 或 Keychain 导出。账户名、密码各最多 63 个 UTF-8 字节，不截断；实际登录输入仍仅支持可打印 ASCII。

密码仅本次内存使用，不保存、导出、写日志、传入子进程或增加设备 RPC；取消、关闭、睡眠、到期及完成均清除待用数据。认证失败不重试，不发送测试按键；键盘样本失败不进入锁屏倒计时，也不向登录密码框输入。实际解锁继续保留控制台、Apple 登录窗口、原安全字段焦点和单次提交门控。由于账户密码已用于本机屏幕共享认证，结果措辞改为“未向登录密码框输入”，不再误称“未发送登录密码”。`oneClickUnlock` 仍为 false，普通权限路线尚未通过实际键盘／解锁验收。
