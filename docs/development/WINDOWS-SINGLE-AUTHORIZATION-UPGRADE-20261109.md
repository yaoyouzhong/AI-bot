# Windows 桥接单次授权升级

上一轮安装的 Python 弹窗是 UAC。临时 `SettingsProbe.exe` 和新路径的 `AIBotBridge.exe` 都首次监听网络，Windows 防火墙日志分别出现了对应入站规则。程序已经具备的管理员权限不会自动让新可执行路径继承防火墙许可。

## 设计和实现

- AI-bot 自己发起一次 UAC。在管理员进程中，正常退出旧常驻桥接、验证并安装新版到受保护的独立版本目录、更新固定的用户登录任务，然后通过该任务启动新版。旧目录与旧许可保留作回退，登录任务仍是同一用户、无额外参数。正常登录仍由既有任务启动，不运行安装入口。
- `BridgeFirewall` 只读取当前有效的受保护旧桥接路径上的入站 Allow。只继承旧规则已覆盖的 TCP 桥接端口和 UDP 发现端口、已有网络类型及更窄的地址/接口条件；原来对任意远端开放的收紧为 `LocalSubnet`，不启用边缘穿越。明确拒绝的路径、禁用规则、带无法重建的认证限制及不相关程序不产生许可。任务注册前读回新规则；失败时移除本次新增规则。不会修改网络类型、防火墙全局策略或外部规则。
- `--upgrade-admin-bridge` 可选带经过明确校验的 TAB5 镜像路径及 SHA。安装进程只通过已有同用户高权限 IPC 委托升级，常驻桥接处理设置读取、单次开始、传输和精确启动核验。不同配对设备/镜像拒绝；等待结果时不重复发起。真实更新前后设置必须一致，同镜像重装还核对不同的有效启动分区。常驻桥接的既有设备窗口也可独立操作固件，不需要启动设置探针。

## 验收计划

1. A/B 使用相同实现、不同内部构建标识，必须产生两个不同 DLL 摘要及两个受保护路径。分别由普通桌面启动，观察 AI-bot 的 UAC 和可能的额外弹窗。
2. 对每次安装核对实际登录任务、DLL 摘要、刚接续的规则、Windows 防火墙事件及 TAB5 的新鲜认证 Wi‑Fi 请求。USB 同时保留供电与恢复验证；Wi‑Fi 联网图标不能代替认证请求。
3. 第二次用正在运行的 B 桥接对已批准的 R4 原镜像做一次同镜像 OTA：记录一次开始、确切运行分区变化、设置保持和 Wi‑Fi 回连；检查没有启动 `SettingsProbe.exe`。此测试不向任何会话发送消息。

Windows Release A/B 与正常桌面只读启动通过，管理员基础、OTA/RPC、显示设置、启动核验及原生会话工作区回归通过。真机结果另记，不以这些测试代替实际安装。
