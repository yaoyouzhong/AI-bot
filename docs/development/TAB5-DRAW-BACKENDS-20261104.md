## 验证中发现的已有问题与最小修正

基线全量预览首先命中旧测试的“运行中”文案断言；当前已批准的萌宠状态用“工作中”，因此补充明确的新鲜 USB 心跳条件并检查现有状态，未删除断言。继续发现总览缓存会因重复设置同一文字对齐而失效。生产修正仅在对齐值改变时调用样式设置，保留位置与外观；原心跳缓存断言恢复通过。像素比较的参考与裁减构建都使用这个相同修正，故比较结论针对后端裁减本身。

本轮开始时，运行中 0.2.308 的图库最小栈余量从此前验收窗口的 1,836 字节进一步降到 **1 字节**，但未收到新崩溃。请求用户暂停 TF 同步，用户已确认切回设备缓存；后续游标停在名画 824/1765、书法 197/929，运行时间继续增长。此前短窗口的通过记录仍保留，不能据此声称持续负载稳定性已解决。

为降低已明确存在的栈压力，把图库 worker 的请求上下文、文件状态、临时路径/哈希等大块值移到每任务私有的 PSRAM 工作区（实际 1,728 字节），在成功、早退和清理路径释放。分配失败释放忙碌状态、回收输出缓冲并保留已完成缓存；不采用共享静态工作区。新增只读取通道模式的 `device_link_mode()`，在原互斥量下读取同一字段，取消检查不再复制整份配置。部分初始化/断点辅助函数保持独立栈帧，避免其临时值在 RPC/JSON 深层链路中始终占用主帧。

实际 GCC `-fstack-usage`：worker **2,448 → 1,184 字节**，取消检查 **192 → 16 字节**；构建预算收紧到 worker 1,280、取消检查 64 字节。8 KiB 任务栈、栈溢出检测、断言和 OTA 保护保持不变。静态帧下降不能替代 SDK/JSON 全链路真机最小余量，安装后仍须测量。
