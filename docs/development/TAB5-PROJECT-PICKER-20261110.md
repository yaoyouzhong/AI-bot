# TAB5 项目列表去重显示

在对话页从项目下拉框寻找某个项目的历史会话。主目录与经 Git 元数据确认属于同一仓库的 worktree 视作同一个项目，合并其会话列表；不同仓库或非 Git 目录继续独立，避免仅凭相同目录名混合。会话仍以原 ID 发送及读取，不修改源目录或电脑端会话。

沿用 262 × 48 px 项目选择器、24 px 字体、箭头与下拉触控；项目、列表行高和色彩不变。同一个项目只显示一次；会话在原列表内上下滚动，屏幕内约显示四条，内部复用 8 个行控件，以减少内存消耗。桥接传输仍有有界容量，不能承诺无限历史。设备验证现有分页的项目标识后合并为一项；未能验证的分页保留旧显示，确保不混合不同项目或改变会话 ID。其他真正不同路径恰好同名时用“父目录/项目名”区分，仍重名则增加短标识。选中、打开、关闭与切换草稿行为保持原样；不引入新协议字段。

Mac 以本地只读 Git 元数据识别主目录与 worktree，不调用 Git、不访问网络；无效、不可读或缺失信息降级为原路径，避免误合并。Claude 的项目归属不改。旧固件继续使用桥接现有分页；新固件识别同源分页，Windows 当前 Codex 桥接每项目只发 8 条，需在 Windows 端独立提高可传输的会话数并验证。协议不变。

## 跨平台交接与验证

- Windows 接收端：在 Windows 原生项目目录与 Git worktree 的元数据确认相同时归为一个项目；不同仓库或无效元数据保持独立。同名项目保留可见区分。当前 Windows `Tab5CodexCatalog.SelectRecent` 对每项目取前 8 条，需单独调整和原生测试，才能让新固件获得更多会话；仍应限制状态帧大小并保护每个项目和当前会话。不要以目录名相同为条件合并，也不要修改会话 ID、原目录、发送目标或草稿。
- 新固件对桥接现有分页的项目 ID 重新计算 SHA-256 后才合并，支持 Mac 前缀和 Windows Claude 后缀格式；未经验证的名字即使相同也不会合并。旧固件仍保留原分页展示，无需桥接协议变更。新增一个完全透明的列表高度占位对象和可见的滚动条，8 个行对象按视口重绑定；滚动不得改变当前选中会话。
- 实际 LVGL 离屏预览和触控模拟覆盖 64 条同项目会话、跨分页聚合、同名但不同 ID、顶部、中间、末尾、滚动与点击、未读计数和选中会话；Mac 自动回归覆盖同仓库主目录、worktree、不同同名目录、失效身份和分页。设备实测和 Windows 验证另行记录。
- 独立 TAB5 工程以 Windows .318 R4 为基线，使用 [LIST1 累计补丁](TAB5-PROJECT-SCROLL-LIST1-20261110.patch)，SHA-256 `096a8d73d16064b192216091283272cb83db13864cde539d9599d458f910d8d9`，该补丁包含 ICON2，不可重复叠加。已从原 R4 在独立目录重放并核对 13 个源文件。
