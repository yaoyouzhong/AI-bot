# Claude 公开回复阅读设计（2026-11-04）

用户补充要求一般功能默认开启、无需额外应用内授权。现有 Mac 首次启动默认值已覆盖音乐采集/控制、Codex 读取/手动操作、桌面直达和电脑控制；保持首次默认开启，将这些页面里的“允许/授权”文案改为普通“启用/停用”，总标题改为“功能设置”。保留用户后续主动停用的选择；本机按本次明确要求启用普通功能，不新增首次确认或引导页。真实 macOS 辅助功能、自动化和钥匙串权限仍遵循系统行为。窗口尺寸、间距、字体、操作顺序和系统授权按钮保持原样，使用实际原生离屏渲染核验文案不截断。

用户发现总览长按钮仍跳转 Claude 额度，明确要求像 Codex 一样查看 Claude 的公开回复，并授权将公开回复发送至已配对 TAB5。此授权不包括推理、工具输入输出、命令、用户提示词或发送/中断操作。

## 使用与布局

总览沿用原长按钮位置（卡片底部，约 706×62px）、字体、浅蓝主按钮和触控范围，文案改为“查看 Claude 会话”。无可确认会话时显示“Claude 会话待同步”并禁用，不跳往额度或 Codex。额度仍从额度卡进入。

点击后打开独立的 Claude 只读覆盖层：1280×720 横屏，沿用 Codex 阅读页的深色面板、24px 正文、30px 会话标题，左右 48px 留白；顶部显示返回按钮、Claude 会话名称和状态，正文滚动区宽 1160px、高约 440px。底部提供“上一页”“最新”“下一页”和页码，按钮至少 160×60px。没有文本输入、发送、语音、图片、授权或中断按钮。180° 横屏使用同一逻辑布局，检查长中文、英文、emoji、空回复及大段落。

点击固定到总览所示的同一会话。切换客户端、会话、断连或撤权时不把另一个会话的内容填入旧阅读页；显示明确状态并允许返回。加载中保留标题，正文显示“正在读取公开回复…”；无公开回复显示“此会话暂无公开回复”；既有数据源停止时显示“电脑已停止提供会话数据”；未知格式和读取失败不当作空回复覆盖已有内容，提供重试。页码/内容版本变化要重新确认分页，不拼接不同版本。

## 权限与边界

用户随后明确要求默认开通，不增加授权或设置。两端在现有设备 AI 状态数据源可用时默认提供 Claude 只读回复；不新增开关、弹窗或设置入口。点击总览长按钮即读取，未点击时不发送正文。现有设备停用、数据源关闭及配对边界仍生效，客户端不自动改写这些既有选择。

设备状态仅附加不透明读取绑定及能力提示。原始 session ID、prompt ID、路径和正文不进入周期状态帧。公开回复仅通过已配对、加密并带重放保护的 `kind=claude` / `op=read` RPC 按显式点击分页读取。仅允许桥接已选定的会话，不接受任意路径或原始会话 ID。所有发送、打断、草稿、照片操作均拒绝。

## 验证

先验证两端白名单解析和同一会话绑定，包括混合 thinking/tool_use/tool_result、用户和子代理记录、超长/未完成行、重复记录、损坏数据、权限关闭、旧绑定、旧分页和读取时切换。再运行真实 LVGL 阅读页面预览，检查所有状态、长文本、滚动、分页和 0°/180°。Windows 原生桥接与 TAB5 设备触控、USB/Wi-Fi/BLE 读取仍须分别记录，不将交叉编译或离屏预览当作真机通过。
