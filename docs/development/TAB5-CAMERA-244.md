# TAB5 相机重开内存检查 .244

## 现场与复现

`.243` 用户确认连接提示/电脑备注、Mac/Wi-Fi Codex 直达均正常；三张附件补拍回归报“相机内存不足，请稍后重试 (1/12)”。保持附件和设备运行、接回 Windows USB 后，相机诊断为 stage 1/error 12、实时内部空闲 48,383 字节、最大连续块 23,552 字节；上一张照片编码 stage 7/error 0、上传 HTTP 200。堆数字来自错误清理后的实时诊断，不是清理前分配快照。原始反馈与数值记录在 `artifacts/development/tab5-camera-reopen-244-20261022/FAILURE-243.json`。

这是进入驱动前的内存门槛，不是先前 stage 6 / ENOMEM 的整帧缓冲分配。相机驱动首次初始化后，会在本次启动期间保留传感器、视频设备及 ISP 管线对象；三帧数据也已在启动时预留。原来的每次打开入口仍要求内部空闲至少 49,152、最大块至少 16,384，重复计算了首次初始化的余量。

将现场 48,383/23,552 数值加入真实相机任务原生夹具，在不改 `.243` 实现时复现 stage 1/error 12，且重开整帧分配次数为 0；`baseline-243-failure.log` 保存这个预期失败。因此不能把本次错误归为新的整帧分配失败，也不能由此认定备注界面产生了泄漏。

## 修复与范围

- 将原内存门槛放入尚未初始化的分支。首次初始化仍保留原检查，避免在已知余量不足时进入无法完整撤销的设备注册。
- 已初始化相机的重开继续使用预留三帧，并由实际 `REQBUFS`、`STREAMON` 等结果判定是否成功。没有吞掉驱动分配错误，原错误提示、失败清理、停止失败隔离及 JPEG 不可变租约保持有效。
- 不改变分辨率、三帧预览、JPEG 质量、附件上限及草稿。新增常驻帧内存为 0；无 UI、桥接、协议或持久化布局变化。保留 `.243` 已通过实测的连接反馈/备注与 Mac/Wi-Fi 直达。
