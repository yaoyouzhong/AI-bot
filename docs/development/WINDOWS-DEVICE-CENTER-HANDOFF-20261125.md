# Windows 升级提示与 TAB5 会话目录

发起端为 Windows。两个场景均使用现有桥接接口，固件版本要求不变。Mac 已完成下述代码对齐；实体 TAB5 验收仍待完成。

| 场景 | Windows 预期 | Mac 对齐结果 |
| --- | --- | --- |
| 设备中心有可用更新 | 小箭头固定在软件固件卡片右上角。96 DPI 下直径 14 px，距上边和右边各 8 px。标题和更新数量左对齐，整张卡片可点击。更新数清零后移除提示。 | `MacBridgeActionCard` 将原 24 pt 图标缩为 14 pt，固定在右上角，上、右各留 8 pt。保留现有绿色底、白色箭头和原生卡片字体；标题和更新数量维持左对齐，无更新时移除图标，整卡仍为同一个操作入口。 |
| TAB5 同步 Codex 项目 | 只有 App Server 项目 ID 的会话还需能匹配已登记工作区或 Codex 工作树目录。桌面索引和旧项目分配可证明外部工作目录的真实归属。独立验证副本及其残留记录不进入项目列表。 | `MacCodexLocalMetadata` 对只有 App Server 项目 ID 的会话检验工作区归属；保留符合条件的项目会话、Codex 工作树和有明确分配的外部会话，不显示仅继承项目 ID 的验证副本；普通未分配会话保持原有分组。 |

Windows Release 构建、`--status-once`、`--self-test-device-center` 和 `--self-test-codex-tasks` 均通过。已检查两列、三列原生布局以及有无更新的状态。用真实本机目录只读验证，保留 AutoLoop 的侧栏维护和 AI-bot 的两条实际对齐开发，共排除五条隔离验证及重放会话。

## macOS 本机验证

- `swift test`、`swift build -c release` 通过。离屏 AppKit 渲染实看 560 与 920 pt 窗口的两列、三列布局；可用更新时角标不挤占标题，数量清零后提示消失；自动化验证三个状态下整卡均可点击。
- 用隔离的合成目录验证正常项目、Codex 工作树和明确分配的外部会话仍可列出；独立、嵌套和已删除的验证副本不显示。取消桌面分配后，即使 App Server 仍保有项目 ID，该验证会话也不再列出；恢复分配后重新列出。

## 待真机验收

- Windows 与 macOS 分别将对应桥接接入实体 TAB5，打开 Codex 项目列表：确认正常项目和明确分配的外部会话可见，只有继承项目 ID 的独立验证副本和残留记录不可见。未修改固件，不要求刷机。
