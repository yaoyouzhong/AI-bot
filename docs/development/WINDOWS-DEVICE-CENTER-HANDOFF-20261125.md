# Windows 升级提示与 TAB5 会话目录

发起端为 Windows，接收端为 macOS。两个场景使用现有桥接接口，固件版本要求不变。Mac 对齐已随 PR #51 合入主干。实体 TAB5 的两端验收待完成。

## 设备中心有可用更新

- 共同要求：小箭头固定在「软件固件」卡片右上角。有更新时显示，更新数清零后隐藏。标题和更新数量左对齐，整卡仍可点击。
- Windows 在 96 DPI 下使用 14 px 图标，上、右各留 8 px。Mac 的 `MacBridgeActionCard` 使用 14 pt 图标，上、右各留 8 pt，沿用原生字体及绿底白箭头。
- 验收：分别打开有更新和无更新的原生设备中心，在窄窗和宽窗检查角标、标题、数量及整卡点击。

对齐状态：已对齐。Windows 和 Mac 的原生布局及点击检查通过。

## TAB5 同步 Codex 项目

- 共同要求：只有 App Server 项目 ID 的会话还需能匹配已登记工作区或 Codex 工作树目录。桌面索引和旧项目分配可证明外部目录的真实归属。独立验证副本及其残留记录不进入项目列表。
- Mac 的 `MacCodexLocalMetadata` 应用同样的归属判断，普通未分配会话保留原有分组。
- 验收：两端分别用候选桥接连接实体 TAB5。打开 Codex 项目，确认真实项目会话、Codex 工作树会话和已明确分配的外部会话可见，仅继承项目 ID 的验证副本与残留记录不显示。

对齐状态：已对齐。Windows 只读目录验证及 Mac 隔离目录回归通过。

待验收：Windows｜用发布候选接入实体 TAB5 核对项目列表。

待验收：macOS｜用发布候选接入实体 TAB5 核对项目列表。

## 发起端验证

Windows Release 构建、`--status-once`、`--self-test-device-center` 和 `--self-test-codex-tasks` 均通过。已检查两列、三列原生布局以及有无更新的状态。用真实本机目录只读验证，保留 AutoLoop 的侧栏维护和 AI-bot 的两条实际对齐开发，共排除五条隔离验证及重放会话。

## macOS 本机验证

- `swift test`、`swift build -c release` 通过。离屏 AppKit 渲染实看 560 与 920 pt 窗口的两列、三列布局；可用更新时角标不挤占标题，数量清零后提示消失；自动化验证三个状态下整卡均可点击。
- 用隔离的合成目录验证正常项目、Codex 工作树和明确分配的外部会话仍可列出；独立、嵌套和已删除的验证副本不显示。取消桌面分配后，即使 App Server 仍保有项目 ID，该验证会话也不再列出；恢复分配后重新列出。
