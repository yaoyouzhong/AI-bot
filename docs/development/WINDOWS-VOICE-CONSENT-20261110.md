# Windows：麦克风允许后继续同一次语音

更新后的常驻桥接上，用户报告第一次启动时允许电脑权限后显示「电脑输入目标已变化」，第二次成功。现场日志：14:18:39 开始第一轮，物理麦克风初始化耗时 3.328 秒；停在取得麦克风后、恢复草稿焦点前，随后返回 error，未启动识别或发送。14:18:57 第二轮的麦克风初始化耗时 219 毫秒，随后进入录音、识别和回填，用户确认实际发送成功。旧日志没有记录权限窗口关闭时的前台归属，不能由此确定当次每一个焦点变化。

修复经确认属于本次的 PickerHost 授权框关闭时，Windows 短暂退回空白窗或无前台、鼠标允许键仍按住的路径。此时等待窗口过渡和点击释放，再恢复原有桥接草稿编辑器并开始同一次录音。未确认的弹窗不能授予恢复权限；切换其他应用、失去目标、取消和超时仍阻止启动。失败日志只保留阶段、是否识别权限窗和固定原因，不记录标题、键值或草稿内容。

Windows Release 构建、`--status-once`、语音核心、权限过渡和 Claude 原生工作区自动回归通过。对应候选已安装到日常桥接，用户在真实 TAB5 上确认：第一次弹出语音权限时点击「允许」，同一次录音直接继续，无需再次点语音。镜像身份、证据和 Mac 复测范围见[交接记录](MAC-HANDOFF-FROM-WINDOWS-20261110.md)。
