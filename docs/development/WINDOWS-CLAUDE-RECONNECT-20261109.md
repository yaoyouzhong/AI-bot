# Windows Claude 会话重新确认

范围：TAB5 的 Cloud 会话在 Windows 桥接重启、Claude 进程恢复或切回会话后，尽快重新取得该会话的输入能力。覆盖 Claude Code 原生终端和 VS Code Claude 扩展。沿用现有协议和界面，不改固件、Mac 或实际发送方式。

旧版把原生输入能力和历史检查串行放在同一个后台扫描里，整批结束后才发布，并与设备读取、草稿和发送共用同一个门锁。慢会话会挡住其他会话。已有历史的会话还会重复做空白面板发现；终端会把失败探测缓存 10 秒。此前实机记录的 117 秒托盘刷新停顿与约 120 秒的设备状态记录空档有重叠，但没有证据把这段停顿归因于其中一个代码点。

候选将会话目录刷新和原生能力探测与设备操作分开。设备加载所选草稿后，独立安排该会话的能力检查；后台最多并行两个探测，逐个发布，避免慢会话拖住另一个。所选会话优先保留在大小受限的设备状态帧中。已经有会话历史的条目跳过空白面板探测；原生终端存活清单改为一次扫描，失败探测缓存缩短为 750 ms（不是设备恢复耗时）。旧观测不能覆盖后发观测，实际发送仍重新校验会话、轮次和原输入目标；识别不获取焦点、不输入或重发。

Windows Release 构建零警告，正常桌面 `--status-once`、Claude 工作区/发送/回执、TAB5 RPC 和快捷控制台回归均通过。两条回归分别在其他两个会话的探测被挡住时，从设备工作区草稿加载到选中会话控制可发送，原生终端用时 47 ms、VS Code 用时 15 ms；两条均验证失联撤销和重新绑定。数据来自隔离故障注入，不能当成真实 TAB5 端到端耗时。
