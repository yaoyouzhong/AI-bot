## 追加回执

- Wi-Fi：USB 上发起隔离任务并保持运行，切为 Wi-Fi 单通道后手动追加短文本。设备显示“已追加”，回执 202，桥接处理 1763 ms；释放任务前后模型请求数从 38 增至 40，对应首次发送及一次追加。

## 照片

- 用户分别在同一测试会话拍摄相近画面。Wi-Fi 和 BLE 单通道发送均返回 202，隔离模型收到 JPEG。之后在隔离夹具内对照加密照片存储和原生 Terminal 会话记录，两张图片的字节数及 SHA-256 均一致；设备上传路径同时校验照片的传输摘要。模拟模型本次未预置实拍图片摘要，不能将模型侧逐字节一致单独记为通过。
- 设备照片上传诊断：Wi-Fi 144,192 字节、1086 ms（约 129.66 KiB/s）；BLE 152,252 字节、13821 ms（约 10.76 KiB/s）。这是每种通道各一次样本、两张不同 JPEG，约 12 倍的吞吐差异只说明本次观察，不证明长期速度或唯一瓶颈；计时是上传阶段，不包括拍照和模型处理。
- Wi-Fi 照片发送后，本机模拟服务因照片放行文件缺失返回 503 并触发隔离模型重试。补齐模拟服务的放行条件后该会话回到空闲，随后 BLE 照片发送完成。重试仅在本地模拟服务发生，不将这段测试夹具异常归因于产品，也不将 Wi-Fi 照片记为首次完整模型回复通过。

## USB 隔离后台停止补测

- 使用独立的旧式 `legacyFixture` 合成后台会话、本机受控模型与真实 TAB5；任务保持运行时，设备通过 USB 发出一次停止，回执 202，处理 89 ms。隔离会话记录出现用户中断标记，但设备之后显示“失败”而非“已中断”。
- 这个测试路径是只供测试的旧式夹具，生产桥接使用原生会话适配器，故不能推断生产 Terminal 中断存在同一问题。测试服务已结束，原设备设置核对未变并恢复日常桥接。
- **原生 Terminal 对照：** 在专用 Terminal、隔离模型和真实 TAB5 USB 链路上单独发起任务并保持运行，设备发出一次停止，桥接返回 202、处理 1502 ms；设备实际回复页显示“已中断”和“任务已停止，本轮尚无公开文字”。
- **Wi-Fi 原生 Terminal：** USB 发起隔离任务，停止 USB 和 BLE 后由用户在设备点停止。原生桥接日志确认已执行停止输入，设备页面显示“已中断”。交互诊断的短列表已被后续读取覆盖，没有保留下该次停止请求的 HTTP 状态，不能记为状态码 202。
- **BLE 原生 Terminal：** USB 发起隔离任务，停用 USB 和 Wi-Fi 后由用户点停止。BLE 返回 202、处理 1609 ms，恢复 USB 后在设备回复页确认“已中断”。各次使用本机隔离模型，设置保持不变，测试服务已停止，日常桥接和 USB 已恢复。
