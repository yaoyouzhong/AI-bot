# TAB5 321-R2 图库增量与左侧闪屏

## 图库同步

TAB5 在 TF 卡按目录版本保存逐件 SHA-256。Windows 桥接用设备摘要比对同一图片目录中的作品详情，按名画和书法分别生成 zlib 批量包。首次升级可以用 Windows 保留的旧全量包和 TF 卡上已完成的同版目录。原文分页随详情一起传输。设备校验压缩包和详情记录，写卡成功后提交新目录。保存失败时原图库仍可读取。

实测图库从 `2026.11.03.1` 更新至 `2026.11.12.1`。两版 4,036 张名画 JPEG 和 7,162 张书法 JPEG 的清单 SHA-256 全部一致。离线比对发现名画 539 件、书法 585 件详情变化，书法另有 31 个原文分页。实际 TAB5 收到了以下批量包。

| 图库 | 真机收到的压缩数据 | Wi-Fi 接收 | TF 阶段 | 单类批处理总耗时 | 最终保存 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 名画 | 218,744 字节 | 397 ms | 298 ms | 7,254 ms | 1,765/1,765 |
| 书法 | 413,373 字节 | 894 ms | 483 ms | 5,494 ms | 929/929 |
| 合计 | 632,117 字节 | 1,291 ms | 781 ms | 12,748 ms | 2,694/2,694 |

TF 阶段包含详情校验、持久化、旧图关联和目录提交。单类总耗时还包含准备、RPC 和解压。名画首次在开机时通过 USB 发起，未完成接收。设备约一分钟后通过 Wi-Fi 重试并完成，表中总耗时按成功批次计。真机 JPEG 接收计数从启动到两类完成都是 0 字节。

Windows 离线测试验证了所有变更详情和原文分页、再次上传相同摘要后零件变更。固件本地回归验证了卡写入中断、摘要重读和横竖版 JPEG 复用。Mac 可继续走已有逐件协议，本轮未实现 Mac 批量桥接。

## 左侧闪屏

320 运行期间用户重复报告左侧闪动。USB 诊断看到 LCD 欠载升到 14，刷新提交错误为 0。闪动在图库停止请求时仍发生，设备捕获了 40,352 像素的显示缓冲复制窗口和同一扫描帧内的欠载锁存。直接故障是 LCD 扫描 FIFO 欠载。DMA2D 复制与液晶扫描争用内存带宽是当前证据指向的触发条件。

R2 将这条复制路径的 DMA2D 突发从 32 字节降至 16 字节，沿用 ST7121 的现有像素时钟和行场时序，并保留欠载前的采样。此前 318-R7 的 ST7121 实验将像素时钟降到 60 MHz，真机出现持续强烈闪动并恢复原设置。

R2 在 13:49:19 首次回报新版本。13:54:17 样本新增一次 LCD 欠载，提交错误仍为 0。采样确认同一帧的欠载锁存从 0 变为 1，最近一次复制为 40,352 像素。13:55:40 样本确认累计两次欠载，第二次在 40,352 像素复制结束后 98 微秒由 DMA 扫描回调读出，复制起止仍在同一帧且锁存从 0 变为 1。R2 的 16 字节 DMA 调整未通过屏闪验收。两类图库此前已完成，最近一次图库 RPC 是 13:50:44。

## 候选与验证

固件版本 `0.2.321-ui`，内部版本 `321-R2`。镜像 7,069,472 字节，SHA-256 `a266ac379f72d578f58e9a9933ed6c7b1c86568322e92cd0f3616a59cbe6192d`。设备回报匹配的 ELF SHA-256 `3ed38b4163786b8236dc7b821b37607e021b4a8bbc818c41d757e388b84431be`，`ota_1` 分区状态为 `VALID`。初次升级程序先等待超时，后续独立启动核验已通过。

[固件补丁](TAB5-321-R2-GALLERY-SCANOUT-20261113.patch)基于已发布 320-R6 源码。Windows 真机测试桥接基于设备现场原有 0.6.19 源码 `d9150b180`，只加入图库协议所需改动。固件原生构建、分区和堆栈检查及 Windows Release 构建通过。实际 OTA 说明已离屏渲染。未公开发布。
