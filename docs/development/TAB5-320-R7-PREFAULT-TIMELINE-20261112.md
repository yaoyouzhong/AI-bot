# TAB5 总览欠载复查：上一笔搬运与渲染

11 月 12 日 17:56:13–18:00:23（北京时间），通过常驻 Mac 桥接被动读取运行 R6 的同一台 TAB5。195 份样本均为总览、无屏保、79% 亮度，同次启动且最长采样间隔 1.61 秒。LCD 欠载 **1→1**，绘制错误 **0→0**，显示刷新计数增加 3340，背光变化计数不变。按约定，这 250 秒没有新增屏闪；[R6 长测](TAB5-320-R6-SCANOUT-REARM-20261112.md)曾发生 **0→1**，整体仍未通过。随后设备自然进入屏保，该时段不计入总览结果。

上一次故障的 R6 记录为 `copyfault,1,1,1808,4500,18720;copywindow,1,1,125266,125265,1,0,2`。以扫描回调记下故障的时刻为 0：上一笔 DMA2D 搬运的完成回调在 −4500 μs；当前这笔 18720 像素搬运的启动钩子在 −1808 μs，启动前锁存位已置位，所属帧为 125265；下一帧的扫描回调读到并清除了锁存。两个搬运边界相隔 2692 μs。R6 没有留下上一笔结束时的锁存值：欠载可能更早发生（包括上一笔搬运期间），也可能发生在这段间隔的渲染、CPU 旋转、源缓冲缓存回写或 DMA 描述符准备阶段。完成钩子是软件回调，时间也不能当作最后一个总线字节的时间。故障快照里的 LVGL 阶段只是扫描回调读到的状态。

[R7 离线诊断补丁](TAB5-320-R7-PREFAULT-TIMELINE-20261112.patch)基于 R6：

- 分别记录 DMA2D 启动前／完成回调、LVGL 每个绘制块开始／绘制任务全部完成、CPU 旋转开始／结束、显示提交开始／返回。LVGL 完成点在等待上一笔搬运之前，提交范围包含源缓冲的缓存回写与 DMA 设置。比较时，提交开始到 DMA2D 启动之间的时间窗可用于排查前置操作。
- 欠载时沿用原计数和恢复逻辑，先重新使能扫描，再冻结最多 4 笔搬运边界和 8 笔界面边界；拒绝跨 50 ms、超出 8 帧以及未完整发布的样本。缓冲为定长内存，无正常路径日志或串口输出。面板时序、DMA 突发、FIFO 和界面保持原样。
- `displayDiag` 的可选后缀为 `;before,1,<欠载计数>,<tag,帧龄,微秒龄>...`。按微秒龄从大到小排时间线；`tag / 4` 向下取整得到阶段，1–8 依次对应搬运、绘制、旋转、提交四组的起止；`tag % 4` 的 0/1/2 分别为未锁存、已锁存、采样跨帧而不确定。只用同一欠载计数、同一扫描帧内明确的 0→1 边界缩小区间；并行区间重叠时仍需验证带宽竞争。后缀超过可用空间时省略，原回执与计数照常返回。

本地用 [回归脚本](../../scripts/test_tab5_scanout_history.py)执行了实际 C 代码：模拟四种触发时序、时间与帧号回绕、不完整样本和 USB 回执空间不足，并确认先恢复扫描才冻结记录。R5/R6 原回归、无线运行诊断和 USB 回执回归通过。源码补丁在独立 R6 前像通过 `git apply --check` 并应用，应用结果与候选逐字节一致。

私有工程的 ESP32-P4 原生构建及镜像校验通过：`0.2.320-ui` / R7，7,058,560 字节，OTA 分区余量 150,400 字节；BIN SHA-256 为 `2c03225cc67168fa1e07150203da81cda4d97d600f74b396456a39e0af714a84`，镜像嵌入的 ELF 指纹与本地 ELF 一致。反汇编确认欠载分支先使能扫描 DMA 再调用冻结逻辑；冻结和搬运边界代码位于 IRAM，诊断数据位于内部 DRAM，冻结函数没有外部调用。R7 只保存在私有构建目录，标准固件路径仍是 R6。
