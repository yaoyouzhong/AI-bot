# TAB5 321-R3 ST7121 显示缓冲复制

321-R2 的同屏测试再次出现 LCD 欠载。最清晰的事件在同一扫描帧内从 0 锁存为 1，40,352 像素的复制结束 98 微秒后被扫描中断采样。事发时两类图库已保存完成，JPEG 接收计数为 0。详见 [R2 现场记录](TAB5-321-R2-GALLERY-SCANOUT-20261113.md)。

321-R3 在 ST7121 上使用同步 CPU 复制，每次至多复制 4 行，再写回对应帧缓冲缓存。LVGL 仍在全部像素写完后收到一次完成信号。ST7121 使用原有像素时钟及行场时序，设备的另一个帧缓冲仍供相机使用。ST7123 与 ILI9881C 沿用各自现有 DMA 复制。

[补丁](TAB5-321-R3-ST7121-CPU-COPY-20261113.patch)基于 321-R2。实际 OTA 说明的离屏预览和生产构建通过，固件 7,069,728 字节，SHA-256 `628ae6c5009d881868d0f45caf6ecbd4fa563beb8605d81fd501c372f4f41117`。运行诊断、显示缓冲所有权、刷新控制、相机合成回归通过。另一个旧的 AXI 优先级测试期待拍照结束时恢复低优先级，与 320-R6 已采用的持续最高扫描优先级冲突。该测试和生产文件均与 R6 原包一致，保留原始失败记录。
