# TAB5 0.2.223-ui 本地集成候选

用户要求审计自动关闭面板的新增代码、保持改动简单，并将诊断随功能固件保留，避免另刷诊断固件。候选证据位于 `artifacts/development/ble-unlock-autoclose-diagnostics-20261018`。精确固件与桥接哈希以该目录最终 `candidate-review.json` 为准。未经对应部署确认不写入设备或替换运行桥接；Wi-Fi 组件不安装。

## 功能范围

复用原先显示“电脑已解锁”的两处条件调用现有关闭函数；提交后继续要求更新的解锁状态，同一安全连接与桥接认证。保留原来的连接就绪检查、PIN 输入提交、黑屏唤醒和取消清理，不增加打开计时。保留 .222 播报启停调整，音频体验仍待真机验收。

此前“电脑连接未就绪”的具体现场原因仍未确认，不把源码收敛、模型测试或构建通过称为已修好真实连接问题。

## 保留的只读诊断

诊断为本固件的常规能力，后续基于此版本的候选应保留。源码快照含 `ble_keyboard.h`、`ble_keyboard.inc`、`ble_link.c`、`ui_unlock.h` 的实现；编译源清单记录最终哈希，避免后续构建漏掉。

复用原 GATT Info 的可选数字字段 `k`，无需新增服务、特征或句柄，不改变协议版本。Windows 配套桥接把它放入现有蓝牙传输诊断的 `hidState`；旧 Windows 桥接忽略未知可选字段，身份认证和 ACK 语义不变。本轮无 macOS 变更或测试。此字段不参与 PIN 或按键授权。

| 位 | 含义 |
| --- | --- |
| 0–4 | 连接、缓存安全状态、当前协议订阅、桥接认证未过期、键盘就绪 |
| 5–9 | HID 暂停、Report 协议、Report 订阅、Boot 订阅、等待配对确认 |
| 11–14 | 锁定状态未过期、电脑锁定、面板连接代次匹配、解锁面板打开 |
| 15–19 | 已准备、准备中、待提交、已提交、准备失败 |
| 20–21 | HID 事务忙、上次事务失败或取消（不能单独解释为链路失败） |
| 23 | 当前连接曾收到桥接认证数据 |
| 24–27 | 协议栈实时加密、认证、已绑定、找到连接 |
| 28–30 | 准备阶段：0 无、1 读状态、2 等按键完成、3 等待稳定、4 等待重读 |

其余位保留。UI 原子写入标志，NimBLE 在现有 Info 回调读取；无新增定时任务或按键路径。诊断只读当前状态，复用现有传输更新，不持久化 PIN、输入长度、按键内容、账户或配对码。身份 JSON 在 ATT 512 字节上限内；未来最大宽度字段占满空间时省略诊断，优先保留原身份字段，缺失不视为全零或正常。

## 验证与待验收

直接源码审计和真实生产函数模型测试记录在 `ble-unlock-autoclose-audit-20261018/REVIEW.md`。集成候选需完成固件构建、诊断位与 JSON 边界测试、原 UI/唤醒/取消/提交回归、实际 sidecar 预览，以及配套桥接普通用户 status-once 和电脑控制/RPC 自检。

部署后集中核验当前未就绪状态的实际诊断、正常解锁后自动关闭、取消清空和正常音量播报。若仍失败，先读取缺失条件再改对应代码；不放宽安全门槛，不自动重配对，不自动重放 PIN。
