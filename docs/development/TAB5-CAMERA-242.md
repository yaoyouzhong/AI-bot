# TAB5 三张照片附件与相机帧预留 .242

## 目标与实测依据

支持三张照片上传，期间可以删除首张、中间或末尾照片，再补拍添加；保留其余照片和草稿文字。反复开关相机、全部删除后重开、从图库返回后拍照均属于验收范围。保持 1280×720 RGB565、三帧预览及 JPEG 质量 85。

`.241` 真机最初能添加三张，但删除一张后反复开关再次出现 `6/12`，删除全部照片后暂时恢复。用户正常退出 Windows 桥接，设备不重启，从 USB 读取到清理前的首个失败：

```text
camera_frames: frame=2/3 size=1843200 free=11640296 largest=1835008
```

总空闲足够，但最大连续块比一帧少 8192 字节。`.241` 将峰值从四帧降为三帧，仍会在附件与其他小块分配之间重新申请两帧，无法阻止后续碎片化。8192 字节差值不能证明某个指定线程栈就是唯一来源。

## 修改与影响

- 在启动的资源初始化阶段预留三块完整相机帧，早于图库、音频、USB 和界面资源；关闭相机只释放驱动元数据，不再把帧存储交回通用堆。重开不申请新的整帧。
- 沿用 `.241` 的 USERPTR、停止 DMA 后静帧交接、JPEG 不可变租约及界面线程隐藏旧画面。关闭失败时隔离三帧并禁止复用，保留首个驱动错误；启动部分分配失败则释放已取得的帧。
- 没有改写或删除已有照片、附件缩略图、草稿、电脑绑定、配对、Wi-Fi 或显示设置。没有修改 Windows 或 Mac 源码。
- 相比 `.241` 关闭相机后多常驻两帧，共 3,686,400 字节。图库与其他功能的真实内存余量需要单独真机验证，本地 LVGL 回归不能证明这部分硬件余量。

## 本地验证

实际相机工作线程的原生夹具模拟 `.241` 实测最大连续块 1,835,008 字节。保留旧实现时再次出现阶段 6 / ENOMEM 12；恢复新实现后，两种显示路径合计 128 次拍摄/重开通过，每次重开新增整帧分配为零。另覆盖启动三处部分分配失败与重试、不可变 JPEG 租约、启动/关闭故障和隔离行为。八项相机原生目标通过。

完整 LVGL 回归使用真实附件界面入口与上传确认处理，编码器和网络为模拟接口：三张上传后分别删除中间、末尾、首张并补拍，共六次上传、四次满三张状态、九次保留两张时重开；满三张拒绝第四张，全部删除后能重开，文字及无关附件保留，没有发送会话。这个夹具不代表真实 JPEG 编码、桥接上传或传感器验收。

固件构建及六文件补丁重放通过，`FIRMWARE-242.json` 记录精确源码与镜像哈希。增量补丁 [TAB5-CAMERA-242.patch](TAB5-CAMERA-242.patch) 基于 `.241`，包含四个实现文件和两个测试文件；补丁重放以 LF 规范化内容比对，原始源码字节哈希另外记录。

镜像 7,156,960 字节，SHA-256 `0d08b44a3d27f5725033ff1281beaf38c3c349231dad1256cca8777854487944`，ELF `4fb6dac151d5e29a288f8c0b1ae812ed560d8c6f95aca26c41f75daeb2834d3f`。正式桥接镜像校验器已校验版本、内容和 sidecar，标准入口及历史归档 `versions/0.2.242-ui/0d08b44a3d27-e620caa1` 已生成；构建、标准入口、归档三份镜像哈希一致。

最终完整 LVGL 回归通过，包括分别删除中间/末尾/首张后再添加；实际 sidecar 的顶部、滚动图片及三张附件页面已目视检查。`PREPARED-242.json` 保存准备阶段的证据哈希，不能作为已刷入或真机通过的证明。固定 Windows DLL 哈希未变。

用户已授权“刷入 .242 并验证，USB 已接好”。电脑操作曾由用户按 Esc 停止，尚未开始刷入；用户随后明确要求“继续”，原授权保留。
