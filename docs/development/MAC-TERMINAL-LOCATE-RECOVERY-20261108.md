## 前台与设备点按的区别

- 产品处理设备显式发送或停止时，会尝试定位并激活原 Terminal 标签；发送前读取输入区及注入按键要求目标窗口和标签在前台。用户不必一直手动维持前台；后台目标有时由桥接激活后可以发送。此次自动化验收遵守仓库的前台保护规则，不主动切换或置顶电脑窗口，所以由用户自行切到专用测试标签。
- 设备自动点按由现有固件的 USB 指令实现。日常 USB 测试可自动点停止；此前为证明请求经 Wi-Fi 或 BLE 单通道，停用了 USB 数据通道，因此该步骤由用户实际触控。

## 后台目标的定位恢复（后续修改）

- 用户明确允许设备发送、追加或停止时，桥接自动把需要操作的 Terminal 标签切到前台；不要求用户事先或一直保持该窗口在前台。普通历史读取仍不依赖窗口在前台。没有新增控件或提示；仅在设备显式操作需要窗口输入、且首次定位失败时，再次选择同一 TTY 目标。
- 上述旧版恢复要求 Terminal 已在前台，故故障注入时若首次定位尚未激活窗口，就会错误地拒绝。新版重试前重新核验授权、会话和操作状态，以唯一 TTY 定位并激活目标，仍最多重试两次，且只发生在输入事件发送之前。输入区、草稿和焦点仍须在实际输入前核实；输入后不重试提交。
- 上文的真机记录对应旧版；新版后台恢复的定向验收见下文。历史蓝牙 409 的原始系统错误码未记录，此修改不能证明已定位其根因。
