## 实现

- 复用应用控制页原锁屏按钮和原位置：未锁屏显示“锁屏”，已锁屏显示“解锁”；不新增解锁入口。复用遮罩、数字键盘与清空/退格/取消交互。
- 在当前 NimBLE/ESP-Hosted 主机内添加标准 HID over GATT 键盘服务及 Device Information，保留原私有 GATT、语音和数据服务，不启动第二套蓝牙栈；同一 Windows 主机共享既有单条 BLE 连接。
- 键盘服务要求链路加密、MITM 认证和持久绑定。首次配对显示数字比较码，由用户在 TAB5 明确确认；30 秒超时拒绝。蓝牙绑定密钥可以持久保存，Windows PIN 不保存。重复配对不会静默清除旧绑定，必须在 TAB5 单独确认后重新在 Windows 添加设备。
- 只有当前 BLE 连接收到既有配对协议验证通过的电脑数据（8 秒内）、HID 已订阅且电脑控制状态新鲜并确认锁屏，才允许发送。打开 PIN 面板后连接代次变化会清空并要求重新开始。
- PIN 只在自有可擦除 RAM 缓冲和短暂 HID 发送缓冲中处理；不放进 LVGL 文本对象、JSON、HTTP、RPC、文件、NVS、日志。提交后 UI 立即清零；发送队列逐个消费并清零，取消/断连/过期清零。每个数字有独立按下和松开报告。现有配置关闭 Flash/UART core dump。
- 不自动重试任何数字。发送失败终止事务及连接，避免不确定输入重放。用户取消只释放已按下的键，不继续输入。
- 数字发送后，等待比最后一位更新的电脑状态；仍锁屏才发送 Enter，避免 Windows Hello 自动提交后把 Enter 发到已解锁桌面。桥接状态确认解锁前只显示等待确认；按键入队成功不表示解锁成功。
- 用户需先在电脑显示现有 PIN 输入框；本实现不自动识别/操作登录界面焦点，不处理 BitLocker 开机前输入，也不承诺唤醒休眠电脑。

## 代码范围

源目录：`artifacts/release-068-20261016/tab5-saver-source/`。

- `firmware/main/ble_keyboard.h`、`ble_keyboard_flow.h`、`ble_keyboard.inc`：单次事务、标准 GATT、配对和发送。
- `ble_link.c`、`ble_advertising.inc`：注册服务、宣告键盘、复用当前连接的配对身份验证。
- `computer_remote.c/.h`：只读取锁屏状态的小型快照，避免蓝牙线程复制启动器图标。
- `ui_unlock.h`、`ui_computer.h`：复用按钮、掩码输入、配对和结果反馈。
- `tests/ui-preview/`：真实事务核心/后端的本地替身测试、广播回归和 LVGL 交互截图。

未修改 Windows 桥接的 PIN 处理或权限；现有已部署桥接继续提供经配对认证的状态及锁屏状态。

## 刷机后的验收顺序（尚未执行）

1. 在 Windows 与 TAB5 完成 BLE 键盘配对；核对比较码及系统 HID 识别，保留原桥接连接。
2. USB 拔出，确认 HID 订阅、配对身份及电脑状态新鲜。当前生产入口强制锁屏，普通文本框不能通过本入口发送；公开合成数字的按下/松开已在本地测试覆盖，不用错误数字试登录。
3. 锁屏并显示 PIN 输入框，用户在 TAB5 手工输入自己的现有 PIN，提交一次；核对原桌面恢复及 TAB5 的实际状态反馈。
4. 验证取消、连接中断、重连后旧内容不重放；断开 Wi-Fi 后验证纯蓝牙状态和解锁路径。不得用 Wi-Fi 在线的混合测试冒充纯蓝牙验收。
5. 恢复原日常连接及显示设置，并核对候选固件启动状态。

失败时保持失败现场和诊断，不自动重复真实 PIN，不切换到账户密码。
