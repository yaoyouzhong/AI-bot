# 0.2.58 相机启动内存候选

## 现场与判断

2026-09-30 固定蓝牙拍照附件验收时，0.2.57-ui 提示“相机内存不足，请稍后重试 (1/12)”，尚未生成照片。保留错误页、正常退出电脑桥接后，通过同一设备 COM9 的只读 `tab5_ping` 得到相机诊断：内部可用 14,439 字节、最大连续块 11,264 字节、拍摄帧数 0，运行时间 3,736,067 ms。均低于相机保护检查的 49,152/16,384 字节。这个错误码还覆盖任务创建和静态帧分配，不能仅凭错误码定位具体分配点。

用户随后重启设备立即尝试，先遇到“请等待当前操作完成后拍照”，再进入相机仍报同样内存错误；桥接确认运行时间约 91 秒。前者对应任务读取/同步/发送互斥，不是相机初始化错误。不把后者仅归因于长时间阅读，也尚未证明内存泄漏。

## 候选修复

当前 LVGL 配置为 CLIB 分配器，`lv_malloc_core/lv_realloc_core` 调用普通 `malloc/realloc`。本机 ESP-IDF 配置 `CONFIG_SPIRAM_MALLOC_ALWAYSINTERNAL=4096`，小对象优先占用内部 RAM。界面对象、文本等 CPU 数据没有必须占用内部 RAM 的要求。

在项目内增加三个 LVGL 核心分配函数的链接包装，显式使用 `MALLOC_CAP_SPIRAM | MALLOC_CAP_8BIT`，不修改全局 malloc、第三方托管源码、驱动 DMA 分配或 FreeRTOS 控制对象。保留 LVGL 公共零长度处理及 ESP-IDF realloc 失败保留原指针的语义，不回退抢占内部堆。保留相机启动保护阈值及现有显示/手势逻辑。

这是针对可确认内部堆占用来源的候选修复；释放多少内部 RAM、是否足以恢复相机，以及显示性能影响必须安装后实测。未将候选构建或桌面预览等同于相机硬件通过。

## 验证与部署边界

- 真实 LVGL 桌面预览通过，包含任务/草稿/附件及相机预览和拍后画面遮挡回归；桌面预览没有 ESP-IDF 堆，不能验证 PSRAM 分配或真机帧率。
- 固件构建通过。首次链接失败暴露主组件静态库未抽取仅被包装引用的新对象；显式保留三个包装入口后重新构建通过。`check-ui-memory.py` 检查最终 ELF 的四个 LVGL 公共分配调用及三个包装函数，确认最终调用路径和 1028（SPIRAM | 8BIT）能力参数；显示 ISR/辅助函数 IRAM 检查通过。镜像 `Chip ID: 18`、校验及 validation hash 有效。保留现有未使用函数及缺少 ROM 调试符号配置告警，不称为零告警。
- 固定候选 `.tools/camera-memory-058-20260930/aibot_tab5.bin`，6,620,944 字节，SHA-256 `e76fe0658da793e994f7d574d1098dd56af022ab90c2835d9962f63ea2e72956`，ELF 指纹 `31abe4bcacdb071f69f9f0b6dfeedefdea6167b3e9de2c44e04e92ddabf9c352`。同目录保留 BIN/ELF/MAP、配置、修改源码快照、验证日志及绑定版本/哈希的更新说明。
- 用户批准后已安装；2026-09-30 桥接现场确认运行 0.2.58-ui。用户再次开相机报“相机预览启动失败（7/19）”，因此相机仍未通过。尚未直接回读本次启动的 ELF 指纹及 OTA VALID 状态；版本号不替代这些检查。使用当前 OTA 分区流程，不能使用旧文档的 legacy `0x10000` 刷写命令。
- 真机顺序：启动健康及内部堆余量 → 相机预览 → 拍摄/重拍/关闭再打开 → 固定蓝牙添加照片及发送 → 翻轮后再次开相机；所有步骤分别记录。

## 已通过功能的回归

`.tools/camera-locality-20260926/verification.json` 保留了此前用户确认拍照正常且不闪的记录，以及连续预览约 10 fps、显示欠载和看门狗为零的现场数据。该记录的照片添加另有编码失败，不能混同为拍照预览未验收。历史通过保留，当前版本记为拍照回归失败。

与该冻结源码比较，0.2.58 的 `camera_preview.c` 采集逻辑没有变化；当前工作区对该文件的新改动仅为记录首条底层驱动错误。后续全局 DMA/显示中断安全配置、界面内存分配等存在差异，但尚无证据锁定哪个差异造成视频流启动失败。`7/19` 是 `VIDIOC_STREAMON` 返回 ENODEV，底层可能是 CSI、DMA、中断或 ISP 资源获取失败，不能直接判定摄像头硬件损坏。

0.2.59-ui 目前仅为未部署的诊断构建：普通后台读取占用时排队一次相机打开请求，保留发送/录音互斥；USB hello/ack 增加可选 `cameraLogHex` 字段，十六进制编码相机线程首条驱动错误，旧桥接忽略未知字段。记录长度有界，不记录照片、用户消息或凭据。队列交互、日志隔离及转发、相机缓冲所有权测试通过，固件构建、最终 ELF 分配路径与显示 ISR 检查通过；这些均不证明真机相机恢复。未执行安装，也未将当前视频流失败标为修复。
