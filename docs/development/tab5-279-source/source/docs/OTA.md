## 日常升级

电脑「TAB5 连接」选择「选择并提供升级固件」，提供本项目应用 `.bin`。桥接校验 ESP 头、项目名、大小、版本并计算 SHA-256，上限 7,208,960 字节。设备经状态通道收到信息后，在「设置 → 固件升级」点击「立即升级」才开始（优先可用 Wi-Fi，其次 USB；与日常连接模式独立，不在升级中途换通道）；仍先自动保存草稿，仅收到信息不会升级。

本地验收也可以先正常退出桥接，再以 `AIBotBridge.exe --tab5-offer-ota <应用文件绝对路径>` 启动。文件按同一规则校验，连接窗口显示所提供固件；仍须设备确认。已有桥接实例时明确失败，不会把另一进程未收到的参数误报为成功。

录音、拍照、发送/读取/同步期间禁止开始；未确认消息必须先查询送达结果，其他会话未同步草稿必须先同步。当前草稿必须成功保存。更新时遮盖操作区，显示进度并保持供电，成功后只重启 TAB5。

下载仅写备用槽。HMAC 绑定方法、路径、设备 ID、nonce；状态帧仍加密。下载中断、SHA 不符、镜像/项目/版本错误或写入失败时不切换启动槽。失败后在电脑重新提供固件以重试。撤回停止后续下载；已经开始的写入继续本次检查。

新 OTA 镜像需要 30 秒连续正常的 UI 心跳与无线驱动初始化才确认有效，不要求电脑或互联网在线。90 秒内不能达到条件则请求回滚。首次 USB 迁移没有上一版 OTA 槽，恢复依靠完整备份，不能声称首次迁移也能自动回滚。

## 新分区

| 分区 | 偏移 | 大小 |
|---|---:|---:|
| nvs | 0x9000 | 0x6000 |
| phy_init | 0xf000 | 0x1000 |
| otadata | 0x10000 | 0x2000 |

总范围不超过 16 MiB。旧 factory 应用在 0x10000；旧资源在 0xb00000，需要搬移。配对 NVS、PHY 原偏移保持不变。

## 一次性 USB 迁移

`scripts/migrate-ota.py` 仅支持已核对的 ESP32-P4 下载端口，全程 `no_reset`。通用构建脚本 `-Flash` 已禁用，避免默认刷写覆盖旧分区。

1. `backup --port <ROM端口> --output <私有备份.bin>`：读取完整 16 MiB，确认旧分区表，再与设备校验。拒绝覆盖既有备份。备份含配对/Wi-Fi 凭据，只存本地 `.tools`，不得发布。
2. `prepare --backup <备份> --build <冻结候选目录> --bundle <新目录>`：提取旧表、NVS/PHY 与资源，校验候选布局、应用身份/大小、bootloader 容量，冻结文件并生成 SHA manifest。
3. `install --port <ROM端口> --bundle <目录> --confirm-layout-migration`：校验冻结文件与备份；先验证现场旧表/NVS/资源仍匹配。先搬移并校验资源，再写入/校验新应用、清理备用槽，最后写入引导、分区表、空 otadata。再次验证 NVS/PHY 未变、新资源正确。任何失败立即停止，不自动刷回旧版。
4. 校验通过后短按复位，验证启动、配对、资源、三通道与日常功能。

首次迁移中断可能无法正常启动，可在 ROM 下载模式执行 `restore --port <ROM端口> --bundle <目录> --confirm-restore-backup`。恢复前复核完整备份 SHA，整片写回并校验；不进行整片擦除。端口和路径必须用本次核对值，不能盲抄示例。
