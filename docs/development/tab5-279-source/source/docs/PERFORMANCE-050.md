# 0.2.50 进一步优化及集中验收

0.2.50 累积包含 [0.2.49 的快照、内部绘制缓冲、并行 OTA 与 16 KiB USB](PERFORMANCE-049.md)。用户要求继续优化后集中验收，设备目前仍为 0.2.48；无需先安装 0.2.49。

## 新增改动

### 左右滑动

- 旋转增加按输出行顺序连续写入的实现，避免在外部 RAM 上散写小像素对。与原三种实现一并按实际条带形状、输入内存位置测时，仅当至少快 10% 时启用；旧路径保留。
- 无透明、遮罩、缩放的 RGB565 连续图块，在输入与输出行距都等于有效宽度时一次复制整个区域，避免每行重复调用。其他布局保持逐行处理。
- 增补内部 24 行缓冲下 1220 宽拖动损伤区的真实 LVGL 局部刷新检查，包含 INVALIDATE_AREA 对齐；结果与完整渲染逐像素相同。

### Wi-Fi 固件升级

- TCP 接收窗口从 5760 增至 23040 字节，即 4 倍窗口；接收邮箱从 6 增至 20。已在实际生成的 sdkconfig.h 核实，不只修改默认文件。
- 增量接收窗口约 17 KiB/活跃 TCP 接收连接，仍有界；保留 0.2.49 两块 64 KiB OTA 缓冲、TCP 回压、SDIO 包池修复，以及显示内部内存的剩余容量门槛。
- 此项是窗口和调度开销优化，不代表 Wi-Fi 实测速率提高 4 倍。TCP、SDIO 与 flash 写入仍需合并观测。

### USB 固件升级

- 固件接收响应从每 10 ms 轮询完成状态改为完成/断开事件唤醒；仍保留 75 秒截止及异常退出，不缩短等候时间掩盖错误。
- 每个请求使用自己的静态信号量存储，取消请求与新请求不能互相消耗唤醒；所有指针附加/分离都在 mailbox 锁内完成。没有新增每请求堆分配。
- 桥接完成一个真实分块后立即检查下一请求；重复读到已完成请求仍限速，避免忙轮询或重复执行。
- USB SetupAPI 设备枚举移到串口传输锁外的工作线程；枚举失败仍可恢复，不能误释放未持有的锁。身份确认和每帧确认校验保留。

## 验证

- ESP32-P4 完整重编译、镜像 Chip ID 18 / 0.2.50-ui / 校验有效。
- 真正 LVGL 原生预览通过，包括主页面缓存发布、按压/滑动、24/64 行刷新、网络图表、货币字形、相机遮挡及回复界面。
- 378 种旋转布局检查覆盖新旧算法、方向、奇偶边界、填充与保护区；23990 组绘制像素检查通过。
- 直接编译生产 RPC 生命周期代码，以 OS 线程执行 100 次完成竞态、100 次断开重连/新请求竞态、双通道隔离和截止退出；完成过程轮询 Sleep 次数为零。mailbox 仍验证分片顺序、重复、旧响应与精确重组。
- 52 组 USB/Wi-Fi OTA 成功和失败路径通过，含并行预读、第一/第二缓冲分配失败、接收任务失败、断流、写入、哈希、镜像身份和启动失败。
- 桥接 Release 零警告构建、RPC/基础自检及 status-once 通过；新增检查重复响应不计为新完成工作。
- 上述主机模拟和像素测试均不代替 P4 实机性能证明。SDK/BSP 原有警告仍在构建日志中，未通过关闭警告伪装无警告固件构建。

## 验收界限

候选已完成能从现有证据确定的进一步改动，不宣称达到硬件极限。仍需升级后核对版本、启动健康、帧耗时、是否启用内部缓冲、显示欠载/错误和看门狗计数，再由用户确认拖动体感。既有基线见 0.2.49 文档。

0.2.48 -> 0.2.50 的安装过程由旧版升级程序执行；0.2.50 的新接收窗口、事件唤醒及并行写入在安装之后才运行。因此这次安装时长不能算作新 OTA 的性能成绩。后续 USB、Wi-Fi 的真实升级均需记录完整耗时、SHA/身份校验、启动健康；不能只凭 TCP 已发送完或进度条成功宣称两通道验收通过。
