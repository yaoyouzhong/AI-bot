# 0.2.37-ui：滑动、升级、蓝牙语音、年度节假日

后续合并候选已更新为 [0.2.38](OFFLINE-CLOSEOUT-038.md)，补齐按心跳选择语音通道、后续年份节气和桥接升级窗口收尾。下文保留 0.2.37 构建时的实现与验证范围。

2026-09-28，本地实现与构建完成；未替换正在运行的桥接，未向设备提供/安装本候选。现场独立读回仍为 0.2.35-ui。用户不在设备旁，真实手势、纯 BLE 录音和新升级引擎耗时待验收。

## 滑动

包含 0.2.36 的重复快照不误失效缓存、松手不打断吸附动画两项修复。新增：手势/吸附期间合并整页数据刷新，松手后渲染最新快照；切页偏好在最后一次选择 750 ms 后且无触摸/滚动时保存。告警判断继续运行，未冻结任务停止/确认操作。

原生 LVGL 测试确认：松手位置保持 600，没有跳到 1220；动画期间不刷新整页、不写偏好，结束后写一次；既有绘制、缓存逐像素对比和十二页回归通过。未将模拟结果换算为真机 FPS；CPU 旋转/面板传输仍需真实帧采样。

## 升级

写入从 16 KiB 改为对齐 64 KiB，仍在备用分区顺序写入。IDF 5.4.2 `esp_ota_write` 的逐段擦除会将对齐范围交给 Flash 驱动，驱动满足块尺寸和对齐条件时使用块擦除，避免每个 64 KiB 都拆为 16 个扇区。末块按实际长度写入，仍检查 SHA256、镜像身份/版本、设置启动分区；失败不切换启动槽。不改 Flash 锁、中断或已修复的 SDIO 内存路径。

不同版本跳过当前运行镜像的全量重复哈希扫描。新增 RTC 保留的 `otaMs` / `previousOtaMs`（传输总时长、读取、写入），重启后可通过既有崩溃诊断读回。HTTP/Flash 故障注入 22 场景通过。

仍走 Wi-Fi HTTP；本次没有增加 USB/BLE OTA 引擎，也不能称已达到硬件极限。0.2.35 安装本包仍运行旧升级引擎，64 KiB 改善要在安装本包后的下一次升级测量。

## 蓝牙语音

新 GATT 特征 `7af50004-7f23-4a91-bc65-667a19320101`，与现有状态特征共用连接。电脑验证设备后启动独立、顺序执行的语音读取任务；每个 ATT 操作有界，状态发送仍保留窗口确认。旧固件没有此特征时继续原有状态业务。

TAB5 麦克风采样仍为 16 kHz；纯 BLE 使用 8 kHz 语音频宽的 IMA ADPCM 独立块，电脑还原为 16 kHz PCM 送入现有豆包通路。200 ms 原始 6400 字节变为 806 字节，再进行既有 JSON/Base64 和加密封装。这是语音听写带宽方案，不是蓝牙耳机音频协议；Wi-Fi 原有 PCM 路径不变。大疆优先、手动切到 TAB5、电脑音源恢复行为保留。

每次请求完整复用 HTTP 路径的 nonce、HMAC、AES-GCM、电脑会话/时间窗/重放校验；结果仍加密。请求/回复最多 12 KiB，按序重组，重复请求不重复调用。录音中不重复回传不断增长的识别正文，结束后完整回传草稿。缓冲最多 6 秒，断线/超时/拥塞停止收音并报错，不丢包后假称成功。

无 Wi-Fi且桥接支持新特征，或手动选 BLE 模式时使用 BLE；一次录音不在通道间自动重放。Wi-Fi关联存在但桥接不可达时，仍可能需选 BLE 模式，尚未实现跨传输会话续传。只实现语音通道，未因此新增 BLE Codex 历史/附件/发送 RPC。

验证：生产固件邮箱代码覆盖分片、越界、错序、断线及超时；电脑模拟 GATT 覆盖 MTU 23/247、加密、取消；通过实际 VoiceAsync 和语音状态机完成压缩音频→停止→返回草稿，拒绝篡改。C 编码/C#解码 16 kHz 算法交叉正弦向量 SNR 36.9 dB，不代表 8 kHz 蓝牙实测音质或识别率。豆包真机识别、蓝牙吞吐、长句/重连仍待设备验收。

## 后续年份节假日

桥接首次生成日历时后台检查上一年/当年/下一年，成功后每 24 小时检查，网络/数据异常 1 小时后再试。来源是 [holiday-cn](https://github.com/NateScarlet/holiday-cn) 维护的公开 JSON，引用国务院公告；不是官方 API。仅接受匹配年份、真实日期、无重复、七类假期齐全且带 `www.gov.cn` HTTPS 来源的数据；未发布空表不启用、不覆盖缓存。

验证后原子替换 `%LOCALAPPDATA%/AI-bot/calendar/YYYY.json`，离线和失败保留已确认数据；2026 有内置兜底。新年份公告对上一年 12 月的放假/补班调整会合并覆盖，不把跨年日期当作错误。新协议带三年安排并保留旧单年字段，不需要每年重刷固件。官方尚未发布的年份继续显示待更新。节气表仍为 2026–2028，本次未扩展天文节气数据源。

真实下载的 2026 数据校验通过；现场 2027 文件为 `papers:[], days:[]`，正确识别为未发布。测试覆盖跨年覆盖、重复/非法日期/假来源/错年/空表拒绝、异常更新保留已有缓存。数据源不可达期间不会失去已缓存年份，但不能提前获得尚未公开的新安排。
