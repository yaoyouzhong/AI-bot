# 拍照与 Codex 图片附件

## 使用方式

Codex 页选中会话后，点麦克风左侧的相机图标：预览 → 拍摄 → 添加照片。照片先暂存到配对电脑，在输入框下方显示缩略图；点缩略图看最近照片的预览，点旁边 × 移除。编辑文字后手动发送，图片与文字进入同一轮会话。允许只发照片。

相机快门固定在屏幕左侧中央，圆形快门和“拍摄”文字直接叠放在全屏画面上，不显示背后的半透明框；透明触摸区域仍为 188×304，避免右手靠近镜头遮挡；取消换边按钮。按下即进入“正在拍摄”，松手或重复按下不会重复拍摄。关闭放在右上角，避免盲按快门时误关页面。拍摄后快门隐藏，完整照片保持全屏供用户检查；左下“重拍”恢复取景，右下“添加照片”才进入附件处理。相机未收到画面时不能拍摄，连点快门不会直接确认照片或发送消息。取景和拍后检查不显示左上角引导文字；只在启动、拍摄中或出错时显示必要状态。

取景和拍后检查均为完整 1280×720，不缩小、不裁切。相机工作线程在 LVGL 锁外复制下一帧，双缓冲仅在锁内交换显示指针；移除原来每帧额外 50 ms 等待。拍摄后冻结当前显示缓冲，JPEG 编码也读取这一帧。两个全尺寸缓冲按需分配在 PSRAM 并复用，共约 3.52 MiB；不再分配额外原图和拍后缩略预览缓冲，不挤占驱动所需的内部 DMA 内存。

重拍重新启动取景并更新显示缓冲。相机按钮使用空过渡描述符，保持按压反馈立即响应（当前 LVGL 不接受 NULL 过渡属性）。

按用户要求暂时移除“存储卡”入口，仅保留拍照附件流程；底层 JPG/JPEG 目录读取实现保留，当前界面不可进入。每条消息最多 3 张，每张不超过 2 MiB，最大边长 4096、总像素不超过 4,194,304。TAB5 拍摄编码为 1280×720 JPEG，质量 85；添加附件不要求插卡，也不自动向存储卡写照片。

录音与照片处理互斥；读取存储卡、JPEG 编解码、上传分别在工作线程中执行。发送失败保留附件和文字，送达不确定时只能查询原请求，不能自动重发。最近草稿的附件 ID 随 NVS 检查点恢复；电脑端按会话加密保存草稿和原图。设备只保留最近三张照片的较大预览，重启后或预览释放后仍可发送已暂存附件，但不能在设备上再次放大旧照片。

## 手机照片入口（方案，尚未实现）

TAB5 为当前会话显示临时二维码，手机扫码打开局域网上的上传页，拍照或选择已有图片；上传后在 TAB5 草稿内显示缩略图，继续由用户确认发送。无需人在电脑旁，电脑与桥接仍需后台运行，手机需能通过局域网访问桥接；这不是互联网远程入口，也不是手机直接写入 TAB5 存储卡。

实现时须使用绑定设备、当前会话且短期有效的上传授权，不暴露永久配对凭据；关闭入口使授权失效。复用现有图片校验、附件上限和草稿机制，手机端不直接发消息给 Codex。现有加密图片 API 不能直接当作手机上传页面使用。

## 协议

- `POST /tab5/v1/codex/image`：沿用配对 HMAC 与 AES-256-GCM，独立最大密文 3 MiB。明文包含 `op=image-upload`、`session`、`taskId`、`requestId`（图片 UUID）、`issuedAt`、空 `message` 与 `image`（Base64）。只接受当前目录中存在的会话，校验图片格式和解码尺寸。
- 200 回执含 `imageId` 和内容 SHA-256；同 ID 同内容的重试可确认既有上传，同 ID 不同内容拒绝。重复 nonce 拒绝。上传仅暂存到桥接，不启动 Codex。
- 原 `send/steer/draft-save` 增加可选 `images` UUID 数组；`draftView.images` 返回已保存数组。原文字接口大小上限仍为 8192，状态帧上限仍为 32768。不能把原图放进三通道状态帧。
- 图片只能通过服务分配的暂存对象引用，设备不能指定电脑文件路径。图片绑定配对设备和会话。请求去重摘要包括附件 ID；确认发送才清空草稿。
- 桌面 IPC 的 `input` 同时携带 `text` 与 `localImage`。后者指向已经校验的实际图片文件，不能用正文中的文件路径代替。保留实际文件供 Codex 延迟读取和历史展示；暂存对象最多 512 份，满时明确失败，不自动删除历史附件。

## 左侧快门与取景性能修正（2026-09-26）

- 用户反馈：右侧快门会遮挡镜头，拍摄需点多次，晃动时取景明显卡顿。旧版诊断在 uptime 43,223→75,840 ms 内发布 7→144 帧，约 4.20 fps；这是应用取景帧数，不是 LCD 扫描刷新率。
- 现场代码确认：旧实现锁内复制整张图像并全屏重绘，每帧另等 50 ms；显示端保留 CPU 旋转，因为此前 PPA 阻塞造成显示任务停住。此版不恢复有问题的 PPA 路径，而是缩小持续重绘区域并缩短相机占锁时间。
- 左侧按下事件、LVGL 对象树命中检查（快门左右边缘与圆心）、松手移出目标、拍摄中重复按下、重拍更新预览和不自动发送已通过 Clang 原生检查。RGB565 取景缩放的边角与中心像素已核对。既有相机时钟、格式回读、低内存和重开检查通过。
- ESP-IDF legacy 构建通过，候选 `.tools/camera-left-20260926/aibot_tab5.bin`：6,435,616 字节，SHA-256 `EF239CA5D973A1A79A9025CDDEDB987851B5B59805F3082B3E7F01BB6C2142D9`。已通过 COM8 写入 `0x10000`，数据哈希校验通过；等待启动与性能验收。不能以模拟通过宣称真实快门响应和帧率已改善。
- Wi-Fi `DEV` 数字诊断在原 20 项后追加 4 项：图像准备耗时、等待 LVGL 锁耗时、持锁耗时、按下到拍摄结束耗时，单位 ms，上限 9999；不含图像、文本或凭据。桥接保持原可执行文件与接口。
