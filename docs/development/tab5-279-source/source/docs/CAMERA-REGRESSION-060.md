# 0.2.60 相机回归修复候选

## 实机根因

2026-09-30 同一 TAB5 `e8f60ae2ec56` 已运行 0.2.59-ui，用户首次打开相机报 `7/22`。正常退出桥接释放 COM9 后，仅发送只读 `tab5_ping`。首条驱动错误为：

`dw-gdma: dw_gdma_channel_register_event_callbacks(675): user context not in internal RAM`

`cameraDiag=7,22,196059,102400,0,7,19,0,0,0,0,0,0,0,0`。当前内部可用 196059、最大连续块 102400 字节，不是之前 0.2.57 的内部堆不足。照片处理未开始。证据保存在相邻 AI-bot 的 `artifacts/acceptance-20260930/camera-059-driver-error.json`。

后续显示安全改动启用了 `CONFIG_DW_GDMA_ISR_IRAM_SAFE`。固定 IDF 5.4.2 的 CSI 控制对象分配条件只看 `CONFIG_CAM_CTLR_MIPI_CSI_ISR_CACHE_SAFE`；此配置未启用，普通堆分配允许返回外部内存，违反共享 DMA 中断检查。CSI 对象实际为 148 字节。

另有确定的错误清理缺陷：CSI 控制器申领成功后，`csi_fsm` 直到后续全部初始化成功才设为 INIT；中途失败时清理函数看到零状态直接返回，未释放控制器，后续重试可变成 `7/19`。源码证明此路径，现场前次错误为 `7/19`，但不将所有 ENODEV 都归为此原因。

## 最小修复

- 构建脚本为固定 SDK 应用幂等补丁；相机自身缓存安全或共享 DMA ISR 安全启用时，控制对象必须使用 INTERNAL | 8BIT（2052），不含 DEFAULT。大图像缓冲分配不变。
- 控制器申领成功后立即设置可清理的 INIT 状态；队列未创建时不调用队列删除。保留运行态不可直接删除的检查。
- 保留 0.2.59 的单次相机打开排队和首条错误日志，不关闭显示 ISR 安全检查、不降低内存保护、不改配对或设置。

## 验证和边界

- 固件构建通过；最终 ELF `esp_cam_new_csi_ctlr` 在 `heap_caps_calloc(1,148,2052)` 中使用内部内存能力。
- 提取实际 SDK 清理函数的原生测试：五种部分初始化状态释放相应资源，空指针/运行态仍拒绝；启用断言执行。
- 相机缓冲所有权、首条驱动日志隔离及有界编码、完整 LVGL 预览通过。显示 ISR 与 LVGL PSRAM 分配 ELF 检查通过。镜像芯片 18、校验及 validation hash 有效。
- 构建通过不代表相机恢复。0.2.60 尚未安装，需同一设备安装后验收预览、拍摄/重拍、退出后再次打开，再继续蓝牙附件发送。保留历史拍照通过记录，当前回归在实测前不关闭。
- 读取现场后用户已正常重新启动桥接；自动展示开启，六页顺序及 15 秒间隔保持。当前只进行原应用分区 OTA，不执行全片刷写。
