## 使用方式

TAB5 的「Codex 任务」页先选择任务，然后点击「语音输入」。每次开始时重新选择音源：

1. Windows 中可打开的大疆输入设备优先，声音直接从大疆进入电脑桥接。
2. 大疆不存在或无法打开时，TAB5 开启自身麦克风，通过已配对的加密 Wi-Fi 链路上传声音。
3. 大疆采集中断或连续 2 秒没有音频数据回调，切到 TAB5。普通安静时段不视为断连；USB 接收器仍在线而发射器静音/超出覆盖时，无法仅靠 Windows 端点可靠判断，使用「改用 TAB5」。
4. 同一次说话中不自动切回大疆，下一次开始重新检测，避免反复切换截断内容。
5. 点击「结束说话」后，草稿回显到 TAB5。可修改并确认「发送给 Codex」。语音逻辑不调用任务发送接口。

原有草稿在语音期间保留为前缀，取消恢复原内容。单次录音最多 60 秒。离开任务页会取消；网络失联超过 4 秒，电脑端停止收音。最后的音频缓冲先排空，再结束豆包识别。音频不写入文件或日志。

2026-09-23 方案确认：继续使用电脑端豆包输入法处理两种音源，不接入小智云端或另装离线识别模型。为了在同一次识别中自动切换音源，当前开发版仍统一经 VB-CABLE 送入豆包；并未实现绕过虚拟声卡的豆包音频接口。

## 电脑端首次配置

入口：桥接托盘菜单 → TAB5 连接 → 语音设置。

- 需要另行安装官方 **VB-CABLE**，驱动没有随项目分发。本机已由用户授权安装且通过虚拟音频传输检查；用户要求暂不重启。
- 在豆包输入法中将麦克风设为 **CABLE Output (VB-Audio Virtual Cable)**；桥接仅向 **CABLE Input** 播放，声音不会输出到普通扬声器。
- 豆包的免按语音快捷键需与桥接一致，界面支持「左 Alt + 空格」「右 Alt + 空格」及「Ctrl + Alt + 空格」。本机豆包 0.9.0.0 设置界面显示为「左 Alt + 空格」，桥接新设置以此为默认；已有配置不被覆盖。
- 选择大疆设备，或使用 DJI / Wireless Mic Rx 名称自动识别。可手动指定实际端点，设备索引变化不会导致选中其他麦克风。
- 「重新检查音频通路」只枚举设备，不录音；同时检查 VB-CABLE 的播放端和录音端。大疆缺席时显示 TAB5 回退提示；之前手动选定的设备即使暂时断开也保留选择，保存时重新检查通路。
- 在专用草稿窗口选择豆包输入法，手动确认开始/结束识别及文字落入此框后，再勾选启用。
- 每次由 TAB5 开始时尝试激活此草稿窗口。Windows 拒绝激活、输入法不是豆包或焦点离开时，不向其他窗口注入快捷键；停止收音并提示在电脑处理。锁屏状态不支持。

豆包的文字提交时机和悬浮窗焦点行为仍需实测。当前没有官方 ASR API 集成；实现依赖用户配置的快捷键与本应用文本框。识别停止后等候 6 秒收集文字，超时无文字会明确提示，不宣称识别成功。返回最多 2000 UTF-8 字节，超长会提示前段显示，电脑草稿保留完整文字供整理；结束后 30 秒无设备请求会清空电脑草稿。

输入法判断采用 Windows TSF 活动配置查询。实际验证发现普通 `InputLanguage.LayoutName` 会把当前豆包显示为「中文(简体) - 美式键盘」，因此不能只按该名称判断。接口依据：[Microsoft GetActiveProfile](https://learn.microsoft.com/en-us/windows/win32/api/msctf/nf-msctf-itfinputprocessorprofilemgr-getactiveprofile)。

## 实现位置

- TAB5：`firmware/main/voice_remote.c`、`voice_remote.h`、`ui.c`。
- 公共 Windows 桥接：相邻 AI-bot 项目 `windows-app/AIBotBridge/Tab5Voice*.cs`；`Tab5Service.cs` 和 `LanStatusServer.cs` 接入已配对设备接口。
- WASAPI 音频库：NAudio.Wasapi / NAudio.Core 2.2.1，MIT；不自研或捆绑虚拟驱动。
- TAB5 使用仓库内官方 BSP 的 ES7210 录音接口，16 kHz / 16 bit / 4 路 TDM 中选取 MIC-L，上传为单声道 PCM，每包至多 200 ms。音频采集与网络发送分任务，有界队列积压时明确失败，不无限录音。

### 2026-09-24 自动快捷键过滤定位
