# 蓝牙升级中断与更新说明排版

> 历史阶段记录。当前实现、验收状态和升级通道边界以 [0.2.52 收尾清单](CLOSEOUT-052.md) 为准；下文的“待实现/待部署”仅描述当时状态。

## 现场证据

2026-09-29，设备 0.2.39 固定蓝牙模式升级 0.2.40 失败。桥接记录已提供 16384 / 6594960 字节，这只证明两个分块请求到达桥接，不证明这些数据均被设备接收。旧进度只在 64 KiB 缓冲写入后刷新，因此首块未满时可一直显示零。蓝牙存在多次重连；旧诊断会被后来的成功帧覆盖，尚不能断言本次中断的唯一根因。

## 配套桥接改动

- 同一 GATT 会话内，状态帧与完整 RPC/语音交换排队执行。等待排队不消耗请求本身的传输超时，避免并发 ATT 操作争用状态帧、邮箱和响应的超时预算。
- 保留最近一次蓝牙中断的时间、请求阶段、响应字节偏移；后续成功帧不会清除它。不记录请求正文、鉴权材料或会话内容。
- 电脑固件页更新说明增加标题、浅色底、项目符号、悬挂缩进和条目间距；内容超过高度上限时滚动，按窗口宽度换行。

## 固件 0.2.41

在 0.2.40 的改动基础上，每次收到下载数据即更新接收 KB 数和百分比，不再等待第一个 64 KiB 写入块。100% 仍只在校验镜像及设置启动分区成功后显示。原 0.2.40 候选保留，未覆盖。

用户随后明确不接受几十分钟的蓝牙固件升级，并取消长时间蓝牙复测。因此 0.2.41 升级只选择有有效心跳的 Wi-Fi 或 USB，优先 Wi-Fi，不修改日常连接模式；按钮显示实际升级通道，仅蓝牙可用时提示连接快速通道。桥接拒绝蓝牙 OTA 请求，但保留蓝牙会话和附件 RPC。0.2.39 / 0.2.40 用户需要先将连接方式固定为 Wi-Fi，避免原自动模式优先使用 USB。

## 验证与边界

- Windows Release 构建、status-once、BLE 状态帧、BLE voice、通用 RPC 模拟验证通过。新增排队互斥、排队取消、失败释放测试。
- WinForms 固件页正常及最小窗口布局检查与截图通过。
- 最终 ESP-IDF 构建、原生 LVGL 回归、44 项 USB/Wi-Fi OTA 场景及纯蓝牙拒绝通过。独立链路测试覆盖 Wi-Fi 优先、USB 回退、拒绝旧心跳/未来时钟、纯蓝牙不可升级、日常模式不变。首次写入前已出现下载反馈。
- 桥接已备份后正常退出、更新并重启；保留配对及自动轮播页面、顺序、间隔，并重新提供用户此前选择的 0.2.40。
- 固定蓝牙完整升级、实际吞吐率与失败恢复仍待真机复测。模拟通过和桥接已提供字节数均不等于升级成功。

串行化桥接上线后，15:45:02 仍记录一次状态帧在 27084 / 27737 字节处等待分片确认超时，随后恢复；这不是 OTA 请求失败。不能宣称蓝牙所有断线已修复。用户已改为自动连接并自行开始 0.2.40 升级，期间暂停桥接部署，观察完整升级结果。

该次 USB 升级最终停在桥接已提供 3809280 / 6594960 字节，用户确认设备报升级失败，仍运行 0.2.39。旧桥接没有记录 USB RPC 失败环节，无法据此确诊唯一根因；新桥接补充最近中断阶段诊断。此问题未标记修复。此前 docs/OTA.md 记录过 Wi-Fi 发送 6568640 字节耗时 65875 ms 的完整成功验收，本轮改用 Wi-Fi 进行升级。
