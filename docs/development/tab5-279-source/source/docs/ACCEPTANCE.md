# TAB5 本机验收

> 历史阶段记录。当前实现、验收状态和升级通道边界以 [0.2.52 收尾清单](CLOSEOUT-052.md) 为准；下文的“待实现/待部署”仅描述当时状态。

日期：2026-09-23。未完成项目不能视为已支持。

## 已验证

- Windows TAB5 接入候选构建：0 警告、0 错误。
- `--self-test-tab5`：DPAPI 配对存储、AES-GCM 加解密、篡改/错误 challenge 拒绝、真实 loopback HTTP 认证与加密响应、无认证拒绝、旧 `/status` 兼容、null 额度保留。
- C# 输出与 Python cryptography 的 AES-GCM 交叉解密通过。
- 固件实际 `link_state.c` 经 MSVC `/W4 /WX` 编译执行：优先级、手动模式、重复序号不延长心跳、8 秒超时、桥接重启会话切换通过。
- 新 Windows 程序 `--status-once` 成功输出协议版本 1，并包含天气、额度对象。此检查不代表设备已收到数据。
- esptool 在 COM8 识别 ESP32-P4 revision v1.3，MAC 尾号 e2ec56。
- 原设备完整 16 MB 闪存已备份在 `.local/backups/`，仅本地保存，不进入发布材料。
- 原 NVS/PHY 起始位置与新工程一致；未读取或回显 Wi-Fi 密码。
- 固件完整构建通过，更新中文字库后约 2.35 MB；已烧录并通过设备照片确认启动。
- USB 实测需要 DTR=true / RTS=false；USB 配对、状态确认及连续心跳已通过。
- 用户在桌面窗口输入 Wi-Fi 后，设备确认联网并持续收到经过认证/解密的状态；用户通过触摸选择“仅 Wi-Fi”，照片及反馈确认顶部 Wi-Fi、时钟走动、真实电脑数据。
- Noto Sans CJK 24 px 字库替换原 16 px 有限字库，用户照片确认页面汉字正常。
- 原 ESP8266 `/diagnostics/device` 确认 `usb_active=true`、`bridge_online=true` 且状态计数继续更新；轮播页面、顺序及 15 秒间隔与部署前一致。
- 独立 Bleak 客户端已发现 TAB5、连接成功并读取匹配设备 ID 的 GATT Info。此项不能代替桥接 BLE 数据确认。
- Windows 桥接改用完整 GATT 服务发现后，已通过配对身份验证、加密分片传输和匹配序号的设备确认；设备 USB 诊断同时记录 BLE 新状态到达。
- 用户确认“仅蓝牙”顶部 BLE、数据/时钟更新正常，改回自动后恢复 USB。
- 用户确认自动模式下拔除 USB，约 10 秒后切换 Wi-Fi 并继续更新；重新插入后恢复 USB。
- 两台设备已同时在线：原小屏 USB 状态计数更新，TAB5 的 USB/Wi-Fi/BLE 三条心跳同时刷新。
- 固件正文汉字已逐字与生成字库对照，没有缺字；原始照片发现的系统状态卡片裁切已修复。
