# 三通道公共传输优化：0.2.61 候选与实测入口

## 目标和当前证据

用户要求覆盖图片、OTA、语音等较大传输，不限于图片；只有自动模式可择优，指定模式必须固定。目标是实测有效吞吐、延迟与稳定性的最优组合，不能把硬件标称速率或模拟结果当成达到上限。

0.2.60 的 73903 字节照片已由用户确认添加成功。相邻 AI-bot `artifacts/acceptance-20260930/photo-060-upload-success.txt` 确认 BLE、200、73903/73903；旧版没有完整起始时间，不能编造总耗时。此前一段 6144 字节照片 RPC 的接收耗时约 14 秒，13.5 KB 后台状态曾在约 10 秒时中断；窗口和总时限调整后上传完成，但用户反馈总耗时很长。

## 当前已实现的候选改动

- 通道：自动模式照片使用 Wi-Fi 整包 HTTP > USB RPC > BLE RPC；必须同一认证会话且近期有有效数据。固定模式严格生效，包括原来会跨通道的 OTA/语音。
- BLE 公共层：RPC 和语音的游标 ACK 支持无 ATT 响应写，下一次读取严格验证 ID/偏移；响应仍确认写，旧固件保留原方式。请求 MTU 517，使 488 字节邮箱有机会用一次 ATT 读取返回，而非较小 MTU 下的多次 read-blob；实际协商由主机决定，尚未实测。
- USB/BLE 图片：原始片段 6144 → 8192，保持 RPC 12 KiB 总长。旧桥接明确拒绝时回退，小包/旧桥接兼容；不自动重发不确定结果。
- 可观测性：设备端记录实际通道、原始大小、端到端毫秒、结果；UI 显示通道/进度或总大小及完成耗时。桥接为公共 USB/BLE RPC、BLE 语音记录请求/处理/响应耗时和字节数。
- 保留：Wi-Fi 语音已使用单连接复用；OTA 的 TCP 背压、两个 64 KiB 缓冲区、读写重叠、映像校验、回滚确认均保留。

## 本地验证与部署边界

固件、真实 LVGL 预览、图片生产分片函数（8 KiB/旧桥接回退/错误偏移/不确定失败不重试）、固定模式路由、实际 RPC 断连并发、语音控制、相机所有权/错误清理和 OTA 52 项故障路径检查通过；Windows Release、RPC 图片字节一致/幂等、语音加密分片与 MTU 23/247/517 测试、status-once 通过。8 KiB 测试最初暴露测试端默认 JSON HTML 转义扩大 base64 的差异，改为与固件 cJSON 相同的编码方式后通过，没有放宽生产协议上限。

候选并不等于达到三通道硬件上限；需批准安装本次新固件和对应桥接，然后逐项测量。历史拍照/照片添加通过保留；完整图片消息送达、语音与各通道性能仍是独立待验收项。
