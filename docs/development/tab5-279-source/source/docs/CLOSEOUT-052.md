## USB 收尾实现

1. 请求选路、OTA USB 可用性和 RPC 提交都检查控制器真实 ready 状态。拔线后不再等八秒心跳过期才绕开 USB。
2. CDC 任务监测 ready→不可用转换，在任务上下文内失效 USB 心跳、重置邮箱并唤醒等候请求。TinyUSB 回调不获取应用锁。USB 写出遇断线尽快结束，不继续等待整个写出超时。
3. 清理本地半包及断线期间输入，避免 JSON 帧跨断线拼接；保留 session/sequence 防重放记录。重插或普通 mailbox 轮询不能独自恢复可用状态，需要新的有效状态帧。
4. 为提交绑定 mailbox generation，拒绝断线之前已准备、重连后才提交的旧请求；旧分片不能进入新请求的响应。
5. 日常自动模式保持 USB > Wi-Fi > BLE；固定 USB 不自动改成别的模式。读取失败由原有只读刷新流程按新状态再次选路；发送、追加和附件不跨通道自动重放，结果不确定仍保留草稿并提示核对。OTA 中途断 USB 则失败保留旧槽，不跨通道续传。

OTA 选路与日常模式独立：在开始时从有有效心跳的 Wi-Fi、USB 中优先选择 Wi-Fi，开始后固定通道；BLE OTA 已因速度决策停用，要求改用 USB/Wi-Fi。此前个别性能文档“固定通道选择不变”容易造成误解，以上述代码行为为准。

## 请求信号的内存安全收尾

部分 Codex 请求任务运行在 PSRAM 栈上。完成信号改用 ESP-IDF FreeRTOS 动态分配器，保证控制对象位于内部 RAM；仍由每个请求独立持有，锁内解绑后释放，不共用重连唤醒信号。内部内存分配失败时保留原有有界等待回退，回复与取消均有模拟验证，正常路径不轮询。SDK 依据为 `components/freertos/heap_idf.c` 对 FreeRTOS 控制对象缓存关闭期间可访问性的约束。

0.2.51 候选与证据保留不覆盖；最终验收候选为 0.2.52。

## 本地检查与真机边界

- 生产 `rpc_link.c` 与 CDC watcher 被原生测试直接编译：物理 USB 不可用时的选路、等候中断、重连前后 generation、同会话序号防重放、旧响应拒绝、固定 USB 和无线回退均通过；另覆盖 100 次完成竞态、100 次重连/新请求竞态、双通道隔离及截止退出；补测信号分配失败时的正确回复、取消和释放。
- 实际 `link_state.c` 验证失效后立即回退、重放不续期、同会话新帧恢复，以及既有日常/OTA优先级。
- 实际 LVGL 全量预览与 OTA 52 组成功/失败路径回归；固件构建和镜像身份/校验记录放入候选包 checks。
- 没有用模拟线程时长冒充 USB 实际拔线延迟，没有把候选提供当作设备已安装。

## 明天集中验收

先由用户在设备确认安装最新候选，核对版本与健康启动，再依次检查：

1. 四个主页面左右拖动、松手吸附；电脑状态曲线与金额符号简短回归。
2. 自动模式读取历史时拔 USB：旧请求退出，Wi-Fi/BLE 可继续读取；重插后接收新数据恢复 USB。固定 USB 拔线保持离线，不自行改模式。发送中断不自动重复发送。
3. 纯蓝牙首次读、连续上一轮跨批次、往返缓存；附件及一次实际发送回执。
4. 完成提醒正确轮次与未读清除、纯蓝牙语音，可在前三项通过后验收。

新 OTA 引擎必须在本候选安装之后的下一次升级才运行；从旧 0.2.48 安装本候选的时长不是新引擎成绩。USB/Wi-Fi 完整升级性能需分别记录真实时长、完整校验与健康重启。既有通过项不要求全部重复。
