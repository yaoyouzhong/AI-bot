# 0.2.46 本地候选：历史补取、网络曲线与滑动诊断

> 历史阶段记录。当前实现、验收状态和升级通道边界以 [0.2.52 收尾清单](CLOSEOUT-052.md) 为准；下文的“待实现/待部署”仅描述当时状态。

## 行为

- 保留 0.2.45 的多轮批量传输和 32 页缓存。用户向更早的历史翻页后，剩余旧轮次缓存不超过两轮时，从缓存最旧处后台补取一批。补取仅由导航触发，静默成功或失败，不无限遍历历史；同一任务、桥接会话和边界 30 秒内不重复补取。
- 后台响应只更新缓存。缓存导航保持可用；用户在补取期间请求的目标若已包含在返回批次中，直接显示，不重复请求。任务、导航版本、桥接会话变化不能让旧响应覆盖当前页。发送仍遵循现有单任务调度，进行中的传输不强行中断。
- 参考相邻 AI-bot `firmware/src/main.cpp::drawSystem` 的 250 ms 数据点、224 点窗口、队列播放、下载区域底色和峰值 1/7 余量。TAB5 使用三点 1:2:1 加权平滑，避免交替零值采样形成锯齿；原始速率与顶部数字不被平滑修改。断档保留空点，重复序列不入队，重连清除旧会话数据。队列落后超过 16 点时每次推进三点，恢复后推进一点。
- 旋转增加直接 32×64 分块路径，与原 64×16 路径及内部 RAM 中转路径在启动首个完整绘制条带上比较。候选必须至少快 10% 才启用。奇数尺寸只逐像素处理边缘，内部仍使用对齐的 2×2 转置；例如 81920 像素缓冲容纳的 1220×67 条带，原来整条回退，现在仅一行边缘回退。不对齐缓冲和相机路径保持原处理，未重启 PPA 阻塞旋转。

## 真机证据：已安装的 0.2.45

2026-09-29 用户连续左右滑动，USB 采集显示缓存命中增长，但 629520 像素整帧绘制仍约 67.5–73.7 ms，连续帧间隔约 72.6–113.9 ms。旋转约 25.6–29.0 ms，包含旋转的刷新约 31.1–34.7 ms。四页缓存没有解决全部卡顿，不能称流畅验收通过。

读取启动诊断确认 0.2.45 位于有效 ota_0 分区，ELF SHA-256 与冻结候选一致；运行 1115679 ms，UI 心跳年龄 42 ms，显示欠载和刷新错误为零。桥接正常退出释放串口，读取后正常重启，自动模式、循环页面、顺序和间隔已复核。

上一次 6601712 字节 Wi-Fi OTA：设备记录总耗时 70550 ms，读取 38159 ms，写入 32139 ms。桥接 TCP 发送计时约 69484 ms。上述是 OTA 应用过程，包含设备背压，不能当作 Wi-Fi 物理吞吐上限。

## 传输优化空间

当前 Wi-Fi OTA 的 tcp-v2 使用 16 KiB 连续写入，不包含旧 tcp-v1 每 2 KiB 等待 64 ms 的节流；设备 64 KiB 顺序读满后写闪存。可进一步研究有界双缓冲，接收与擦写重叠，但必须验证 SDIO 内存、看门狗和断电恢复，不能据此承诺接近链路上限。

USB OTA 仍使用每次至多 8192 字节的 RPC 数据、JSON/Base64 封装及 2048 字节分片逐次确认。批量确认、减少封装和连续传输有优化空间；本轮没有修改 USB 协议或宣称实测提速。日常数据通道仍 USB > Wi-Fi > BLE，OTA 自动选择仍优先 Wi-Fi，再 USB；蓝牙 OTA 继续拒绝长时间传输。

## 本地验证与待验收

UI 原生预览覆盖缓存回退、补取失败、导航竞态、边界去重、队列采样与断档、分条刷新曲线连续性和百分比圆环居中。曲线绘制坐标独立缩放，验证 1 GB/s 样本不会溢出 LVGL 的 32 位像素乘法。旋转对照实际 LVGL 通过 342 种像素布局，包括新增的 1220×67 奇数条带；RGB565 绘制、链路、RPC 邮箱和 OTA 失败保护用例通过。ESP32-P4 构建及镜像身份校验另存候选 checks。
