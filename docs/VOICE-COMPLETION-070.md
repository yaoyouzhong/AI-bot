## 问题与改动

- 空白录音原先与有声音但未返回文字的情况共用 8 秒等待及麦克风错误提示。现在按整次音频活动决定：确认静音且停止已确认时，在送完音频尾段后保留 1.2 秒最终文字保护期，然后返回“未检测到语音，已结束”。有声音、已出现文字修订、数据不足或无效数据均保留正常等待；晚到非空文字优先进入审阅，仍不自动发送。
- 音量表仅代表最新块，不能用结束时的零音量判断整次录音。新增全程活动锁存，包含 UI 计时器之间的短声音和末尾数据；源切换不清除已记录的活动。仅 TAB5 收音的初始一秒对高纯度 880 Hz 提示音单独判断，其他频率及明显混合声音保留等待。该判断是保守的音频分类，不是普适语音识别；环境噪声、强回声或无法确认的声音可能仍走原等待。
- 现场豆包已更新至 0.9.1.22，不在旧 native 控制的指纹允许列表。未放宽校验、未猜测新控制命令，保留已有 USB 键盘兼容触发。此路径原先遗漏临时麦克风确认，现在也使用已有音源租约：录音前确认 CABLE Output，结束后恢复之前的选择；用户中途手动改选优先。只读现场查询确认配置里保存的旧麦克风不在线，旧文字成功不足以验证具体收音源。
- HID 诊断区分门锁繁忙、身份确认、触发确认和执行异常；不盲目重发切换快捷键。USB 首次两次失败根因尚未确认，后续多次成功不改写为已定位修复。
- 诊断仅包含状态、音源类型、活动判断、触发类型及最终等待时长，不记录 PCM、识别文字或凭据。
