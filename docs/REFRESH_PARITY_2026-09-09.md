# 刷新节奏与双额度窗口修复

对照源：只读旧固件 loop、drawResetCreditBadge、drawCodexSprite；旧 Windows UsageFetcher、StockMonitor、NowPlayingMonitor、NetSpeedMonitor、WeatherMonitor、MirrorForm。

## 已核对的周期

| 项目 | 旧版基准 | 新版处理 |
|---|---|---|
| 额度取数（含重置次数） | 120 秒 | 原本一致，保持 |
| 股票取数 / 翻页 | 5 秒 / 5 秒 | 保持；翻页从进入页面计时 |
| 音乐取数 | 2 秒 | 保持；封面/标题不随进度重复清屏 |
| 系统采样 | 250 毫秒 | 原本一致，保持 |
| 天气提供商取数 | 15 分钟 | 已迁入旧服务，保持 |
| 天气时钟 / 动画 | 1 秒 / 350 毫秒 | 时钟保持，动画由 250 改回 350 毫秒 |
| 原 Codex 机器人 | 每帧 120 毫秒 | 保持本机导入的六帧延迟 |
| 重置次数徽标 | 数量/到期记录变化才画；精灵避开徽标 | 去掉每轮循环擦写，宠物扫描行避开徽标矩形 |

天气、股票、双额度、国产额度使用可见内容键，阻止无关状态心跳触发完整清屏；切页、资源代次和在线状态变化仍重新绘制。系统采样周期未改，尚不能据此声称系统图表绘制方式与旧版逐帧相同。供应商真实余额变化、提醒边框与实体视觉仍需现场验收。

## 左键双额度窗口

已复现：240px 离屏画布继承桌面 DPI，Consolas 点数字体放大，百分比底部裁切、CODEX 与重置次数重叠。旧版原始离屏 oracle 也有相同缺陷，先前零像素差异不能证明布局有效。

改为按 96 DPI 将点数换算成固定像素字号，再由窗口做一次缩放；文本不自动换行。新增 96/120/144/168/192 DPI 像素一致检查，参考图 `artifacts/dual-dpi-verified.png` 已人工查看，无上述遮挡。旧版双额度比较改用明确的 96 DPI 逻辑画布，不将高 DPI 裁切当作通过标准。

刷新固件 520880 bytes 已刷入 COM7，Hash verified。Windows Release 0 警告/0 错误；镜像、双额度布局及 DPI 测试通过。最终实体效果待用户确认；不代表 Wi-Fi 回退、macOS 或全部功能验收通过。未恢复旧版、未推送发布。

部署后生产资源测试 exit 0，全部九项资源 ACK；新版进程 PID 64264 已启动，8765 状态接口返回天气、6 条股票、Codex 及系统数据。归一化旧版 oracle 的四种双额度会员布局均为 0 像素差异；广泛场景对比中 weather-long 出现 83 像素差异，尚未定位，不记作全部场景通过。
