# AI-bot 本地工作区保留与清理

发布与验收需要具体证据。日常工作区保留现用资源、进行中的交付原包，以及能回查关键结论的材料。发布到 GitHub 的历史附件、标签和下载地址按发布规则继续保留。

| 内容 | 保留规则 | 何时清理 |
| --- | --- | --- |
| 源码、测试和手工改动 | 可提交的内容留在 Git。未合并的改动先提交、合入或按 worktree 规则存档。 | 确认 Git 中的提交可找到后，清理重复源码 ZIP 和整份 checkout 快照。包含未归档改动的快照继续保留。 |
| 冻结候选与实际部署原包 | 每个待验收或待发布的组件及平台保留一份原包，附源码 SHA、文件 SHA-256、候选 ID 和验收状态。交接与重试均使用同一原包。 | 正式附件的下载入口、文件大小和 SHA-256 已核对，且交付闭环完成后，清理本地同字节副本。已被明确替代的候选，在所需证据已留存且无待复测或回退用途时清理。 |
| 当前固件和回退包 | 保留 TAB5、ESP8266 的现用 `latest` 及相关说明、清单和校验，保留 TAB5 当前清单指向的归档。需要离线回退、继续验收或交接原包时，单独注明保留原因、责任人和下次复核点。 | 历史本地固件镜像、旧首刷和升级包默认随阶段收尾清理。旧版本的摘要、说明和必要验收记录可独立保留。例外到期后复核用途，计划删除前核对 `latest` 与被引用的归档。 |
| 验收证据与恢复档案 | 每个实际交付的组件和平台留一份简洁验收记录，包含必要的设备与环境信息、验证结果、限制和关键证据。历史恢复档案只留仍需回查、在 Git 或可用原包中找不到的内容，并保留恢复索引。 | 确认有稳定替代记录后，清理完整测试环境快照、旧截图和重复日志。精简恢复档案前，检查引用并验证保留的文件可以恢复，不能只保留失效索引。 |
| 画廊和宣传资料 | 书法和绘画各留一份经校验的完整包。保留当前使用、可复现的宣传工程及其原始授权材料。 | 包核验和导入验收结束后，清理上传分卷、重复 ZIP、解包副本、临时转码和重复导出。 |
| 构建缓存和临时资料 | 活跃工作可保留可重建的 `bin`、`obj`、CMake、PlatformIO、测试 profile 缓存和诊断输出。使用 `artifacts/<任务>/` 隔离本次资料，避免跨任务混放或把整个 `artifacts` 复制到另一份快照。 | 任务结束或候选更换后，提取必要证据，清理旧临时文件、重复安装包和可再生缓存。按现有规则清理任务 worktree、分支及专用 Cargo target。 |

## 任务收尾

1. 核对 Git、工作树和候选状态。把资料里仅有的一份补丁、验收结论或回退包先放到可验证的保留位置。保留索引需指向仍存在的文件。日志和测试数据先去掉凭据、个人资料及其他敏感内容。
2. 为已完成任务列出待清理目录或文件、预估体积和保留依据。已获得该范围授权时执行，随后检查目标实际消失、现用入口及留存证据仍可读取。清理前排除链接、联接目录和工作区外的目标。
3. 有待验收、唯一改动或明确回退依赖时，记录路径、原因、责任人和下次复核点，比如真机验收完成、发布闭环或下一版本接手。任务结束记录清理前后的项目文件大小和实际可用空间变化，两者分别统计。

## 空间预算

- 以 **30 GB** 作为无大规模构建时的项目占用目标。测量整个 checkout，包括 Git 与 `artifacts`，跳过链接指向的外部内容；共享、硬链或压缩会让文件字节总量与磁盘实占不同。
- 项目超过 **40 GB** 时，在当前任务收尾检查最大的目录和保留理由。先处理重复包、已完成的安装测试副本和可重建产物。活跃多平台构建、图库制包或待验收原包可以暂时超出，写明原因和复核点。空间阈值只触发盘点，删除仍按已有授权。
- 以 2026-11-18 盘点为初始基线：完整书法和绘画包合计约 16.81 GB，`artifacts` 外的源码、资源和 Git 约 3.37 GB，两份较大的历史恢复归档约 3.08 GB。预算是本项目的管理起点，主要资源增长后可以重算。

发布按 [发布收尾清单](RELEASE-CHECKLIST.md) 完成，候选的原包与证据绑定继续遵循 [发布自动化](RELEASE-AUTOMATION.md)。
