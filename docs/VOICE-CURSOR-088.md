# TAB5 语音按光标插入（0.2.88-ui）

## 问题与修改

用户要求语音内容接在 TAB5 输入框当前光标处。087 的 `codex_voice_tick` 将原草稿和识别文字直接首尾拼接，因此总是落到末尾。

088 在麦克风启动成功后、隐藏键盘前，保存已提交拼音的草稿、LVGL 字符光标及其 UTF-8 字节偏移。每次完整识别结果组成“原前文 + 本轮识别全文 + 原后文”，重复轮询和识别改词不会重复累加。录音中的 TAB5 误触/失焦/切页不修改这个锚点；返回文字后光标停在新增文字之后。取消恢复原文字和原光标；空结果保留草稿；总长超过 2000 UTF-8 字节时沿用提示及电脑草稿整理路径，不截断原文。不自动发送。

源码在相邻 `m5stack TAB5/firmware/main/ui.c`，版本在 `firmware/CMakeLists.txt`，原生 LVGL 集成测试在 `tests/ui-preview/preview.c`。桥接返回的是本轮完整识别文本；不修改 Windows 桥接、语音协议或电脑焦点策略。V6 的断线前语音未回收问题仍保留，未由本修正解决。

## 真机步骤（升级并启动核验后执行）

验收进度：088-V1 中间插入、088-V2 不移动光标连续录音、088-V3 TAB5 误触/切页期间保持录音和插入点、088-V4 取消恢复草稿/光标并立即重新录音、088-V5 开头/末尾插入均由用户明确确认通过。本轮五项真机验收完成；电脑端失焦容错不在本次范围，语音断线结果回收另有未关闭问题，不扩大本结论。现场自动轮播保持 auto/true、原六页顺序与 15 秒间隔。

1. 输入“今天去公园”，将光标放在“去”和“公”之间，点击麦克风，说“附近的”，停止。预期“今天去附近的公园”（以实际识别字词/标点为准），原前后文不丢，未自动发送。
2. 保持文字返回后的光标，再录一段，确认从上次插入结束处继续；再分别试开头、末尾。
3. 将光标放在草稿中间，开始录音，误触空白或切页再返回，停止后仍在开始录音时的位置插入。
4. 中间光标开始一轮并取消，确认原草稿/光标恢复，键盘继续输入位置正确。全程不发送；三通道的共用 UI 逻辑已测试，但实际设备行为仍以逐项反馈为准。
