# 桥接设备中心改造方案

状态：2026-09-28，A–D 开发及 E 阶段电脑侧测试已完成；尚未部署。按用户安排，真机验收留到次日。验证范围、运行方式与回退步骤见 [验收记录](DEVICE-CENTER-VALIDATION.zh.md)。

## 1. 目标与首版边界

保留一套 AI-bot Windows 桥接。用户添加自己拥有的设备后，只显示对应设备支持的功能；公共账号和数据源设置保留一份。设备暂时离线不会导致功能入口消失。

首版支持现有规模：一台 ESP8266 和一台 TAB5，可以单独使用或同时使用。数据结构使用设备列表，便于以后扩展；当前连接服务和凭据仍有单设备约束，首版不宣称支持多台同型号。发现第二台同型号时明确提示当前限制，不覆盖已绑定设备。

不在本轮扩展 macOS、手机桥接、TAB5 实时电脑镜像或新硬件型号。只为现有能力整理入口和运行边界；不因为在电脑界面新增一个按钮就宣称设备具备远程设置能力。

## 2. 当前需要解决的真实关联

| 当前实现 | 影响 | 改造方向 |
|---|---|---|
| `TrayMenu` 无条件创建 TAB5、旧小屏和生日入口 | 未拥有该设备也看到入口 | 按已添加设备及功能描述生成菜单 |
| 托盘左键固定打开 `MirrorForm` | TAB5 用户看到原小屏镜像 | 左键打开设备中心，镜像归属 ESP8266 |
| `TrayApplicationContext` 固定创建串口、TAB5 及语音服务 | 没有设备也启动对应工作循环 | 由已启用设备创建和销毁服务 |
| 显示模式、轮播、屏保动作使用一组旧 `BridgeSettings` | 通用名称掩盖了 ESP8266 操作归属 | 旧设置保留归属 ESP8266，动作必须带目标设备 |
| `MigratedDomesticBridge.Tab5Paired` 结合原小屏所选页面决定采集 | TAB5 需求与 ESP8266 页面选择耦合 | 每台设备声明数据需求，再去重合并 |
| `BridgeRuntime` 默认启动天气、股票、额度、音乐等采集 | 隐藏菜单不等于停止不需要的后台任务 | 区分公共采集需求与设备专属工作循环 |
| `Tab5PairingStore.Current`、旧串口发布器均为单实例 | 无法直接支持任意多设备 | 首版保留数量限制，避免假多设备 |

## 3. 用户入口和界面

托盘顶层固定为“我的设备”“账号与数据源”“桥接设置”“关于”“退出”。硬件操作不再散落在全局菜单中。

- 新用户无设备：打开简洁欢迎页，主按钮“添加设备”；允许访问公共设置，不显示任一型号的设备功能。
- 只有一个设备：设备中心直接显示该设备详情；托盘可列出其常用操作，但始终带设备名称。
- 两种设备都有：左侧设备列表，右侧当前设备详情；切换设备只切换管理对象，不改变设备当前显示内容。
- 设备卡片：用户名称、型号、在线状态、可用通道、正在使用的通道、运行固件版本。通道关联与桥接心跳分开判断。
- 所有设备子窗口标题固定“设备名称 · 型号 · 功能”；打开后绑定设备 ID，不能因主窗口切换设备而改变操作目标。
- 长说明折叠或滚动；按钮保持紧凑、主操作就近；最小窗口、125%/150%/200% DPI 都需可操作。

首版默认名称为“ESP8266 小屏”“TAB5 平板”，用户可改名为“办公室小屏”等。界面不要求用户理解芯片、COM 口、GATT、配置文件路径；连接故障诊断中再显示技术信息。

## 4. 功能归属与显示规则

| 功能 | 公共入口 | ESP8266 设备页 | TAB5 设备页 |
|---|---|---|---|
| 模型账号、授权、额度历史 | 保留一份 | 选择本设备需要的数据 | 选择本设备需要的数据 |
| 天气位置、自选股、音乐数据 | 保留一份，标明共享范围 | 选择是否使用 | 选择是否使用 |
| 连接与设备诊断 | 无通用硬件控制 | USB / Wi-Fi | USB / Wi-Fi / BLE |
| 亮度、页面、轮播、屏保 | 从全局移出 | 现有小屏操作 | 已支持的电脑控制才显示，其余在设备端设置 |
| 设备镜像 | 从全局移出 | 现有镜像 | 首版不显示未实现的镜像 |
| 豆包语音与麦克风配置 | 无独立全局硬件入口 | 不显示 | 显示，保持文本审阅后手动发送 |
| 日历与生日管理 | 数据保留为独立资料 | 不显示专用入口 | 显示生日管理入口 |
| 桌宠素材 | 可共用素材库 | 显示支持的应用操作 | 仅显示已支持的资源操作，不绑定原小屏显示模式 |
| 天气右下角动画等旧显示选项 | 从公共天气数据源页移出 | 显示 | 不显示不适用选项 |
| 固件更新、首次安装、备份恢复 | 无含糊“刷机”入口 | 仅匹配 ESP8266 流程 | 仅匹配 TAB5 OTA/首次安装流程 |
| 桥接更新、开机启动、日志 | 公共 | 无重复设置 | 无重复设置 |

规则优先级：已登记设备 → 本地已实现的型号能力 → 设备协议/固件兼容情况 → 当前连接是否能执行该操作。不是按在线状态决定功能是否存在，也不信任设备随意上报一个能力名就开放操作。

未添加：相关专属功能和后台服务均不存在。已添加但离线：保留入口；本地配置可编辑，即时设备操作置灰并说明原因。需要固件支持但版本不兼容：解释所需升级，不假装操作成功。不支持的功能直接不显示。

## 5. 添加、重连、停用与移除

### 添加

1. 点击“添加设备”，打开有界时长的发现流程；不在后台长期弹出发现提示。
2. 尽量通过现有协议握手识别型号；USB 标识、端口号和名称只作为发现线索。无法自动识别时允许选择型号并查看连接说明，不把手动选择当作硬件已验证。
3. TAB5：复用 USB 初次配对与 Wi-Fi 配置；已经持有有效配对时验证设备身份后重连。出厂设备走专用首次安装流程，失败不会登记为就绪。
4. ESP8266：复用已有 USB 握手、设备信息及 LAN 配置流程；旧协议缺少稳定设备标识时明确使用“兼容设备绑定”，不声称有强身份识别。
5. 收到正确协议和有效数据回执后，允许命名并完成登记；只关联 Wi-Fi、只出现蓝牙设备或打开串口都不算完成。
6. 取消或失败：不留下半完成的启用记录。已完成配对但登记尚未完成的恢复资料保留，下次可继续，不自动清除密钥。

状态至少区分：待配置、离线、连接中、在线、连接异常、已停用；升级时另有受控的忙碌状态。设备身份、登记状态和瞬时连接状态分别存放。

### 重连

已有设备自动恢复；COM 口或 IP 变化不新建重复记录。TAB5 以配对设备 ID 为准。ESP8266 首版遵守单设备限制，无法确认同一硬件时提示重新选择，不凭相同 COM 号自动迁移绑定。

### 停用与移除

- 停用：保留设备卡片、设置和资料，停止该设备连接/扫描/告警，便于以后恢复。
- 移除：在产品内明确确认目标及影响后从设备列表移除，停止相关服务；默认保留本地配置、配对恢复资料和生日等数据，也不清空硬件。
- “清除配对资料”“删除备份”“恢复出厂”是独立操作，不能隐藏在普通移除中。
- 正在录音/升级/安装的设备不能被直接移除或停用。正常结束/取消当前流程后再处理，避免留下麦克风音源或刷写状态。
- 最后一台设备移除后回到欢迎页；显式启用的电脑额度历史采集仍可继续，不能因无设备清空或停止用户既有独立需求。

## 6. 配置与服务结构

以下职责已经接入 Windows 桥接；动作路由由 `TrayApplicationContext.HandleDeviceAction` 统一执行，不另建重复转发层。

- `DeviceRegistryStore`：在用户应用数据目录新增版本化设备清单。记录随机内部 ID、型号、名称、启用状态、绑定引用、创建时间、迁移状态；不存明文密钥或 Wi-Fi 密码。
- `DeviceCapabilities`：集中描述每种设备支持的功能和最小兼容条件，菜单、窗口、命令处理共用，避免三处判断不一致。
- `DeviceServiceManager`：管理每台启用设备的连接任务、取消、资源释放和重连退避。未添加 TAB5 不创建 TAB5 语音端点/蓝牙循环；未添加 ESP8266 不启动小屏串口扫描和发布。
- `HandleDeviceAction`：操作显式带设备 ID；执行时再次校验型号、启用状态、能力与当前会话。旧窗口、快捷入口和命令行不能绕过设备选择。
- `DeviceDataDemand`：公共采集按所有启用设备及显式电脑功能的需求取并集，账号只采集一次。离线设备保留其配置与缓存，采用退避；不因短暂离线重启全部采集。
- `DeviceCenterForm` / `AddDeviceForm`：设备中心与添加引导；现有设置窗逐步复用，避免重写全部界面。

`BridgeSettings` 先保留公共字段和旧 ESP8266 字段，不一次性重写所有存储。TAB5 配对密钥继续使用原 DPAPI 保护；生日、额度历史和固件备份不并入设备清单。TAB5 设备端 NVS 继续是本机亮度/音量/屏保等设置的来源，未实现同步前不在电脑复制一套会互相覆盖的值。

LAN 监听的公共生命周期与型号路由分开：同一服务器可保留，但只开放已启用设备的相应路由。USB 发现统一协调扫描和端口占用，避免两个循环同时探测同一串口。旧 ESP8266 协议保持兼容，TAB5 协议保持独立。

## 7. 旧用户迁移

必须在正式部署前用隔离目录的旧配置样本验证，迁移时原子写入新清单，并保留原始配置和可恢复备份。

1. 有可解密、格式有效的 TAB5 配对记录：自动导入已登记 TAB5，沿用配对引用；离线也显示为已添加，不要求重新配对。
2. 有明确 ESP8266 配置但没有稳定身份依据：提供一次“发现原小屏配置，是否继续使用”的迁移选择，保留原设置供确认；不能仅因为默认配置文件存在就认定用户拥有 ESP8266。
3. 原小屏的轮播页面、顺序、间隔、屏保和连接配置原样保留。TAB5 的数据需求不得继续通过修改这些小屏字段实现。
4. 两类配置都有：分别导入，不复制为同一设备；菜单重新组织，但公共账号、授权、额度历史等保持原样。
5. 空配置：新用户欢迎页，不自动添加任何设备。
6. 配置损坏/新格式来自更高版本：保留文件，明确报告并提供恢复路径，不能覆盖为空清单或默认创建两台设备。
7. 重复启动迁移幂等；迁移过程中断不产生重复设备。设备移除后记录已迁移状态，不能在下次启动再次从旧配对自动“复活”。

旧版本回退与新清单的关系需写清：旧版不读取设备清单，无法遵守新增停用状态。因此首版不承诺无条件双向同步；原配置可恢复、旧版回退须按文档执行，不能继续运行两个桥接实例。

## 8. 实施顺序与交付物

| 阶段 | 主要工作 | 完成证据 |
|---|---|---|
| A：登记与迁移 | 设备模型、版本化清单、能力表、旧配置导入 | 零设备/单设备/双设备、坏配置、中断和重复迁移测试 |
| B：用户入口 | 设备中心、添加引导、托盘菜单、全部旧入口归属 | 四种设备组合的菜单矩阵、子窗口目标固定、DPI/滚动截图 |
| C：运行隔离 | 按设备启动服务，动作路由，串口占用协调，数据需求合并 | 未添加设备不启动对应循环；失联/重连/停用/移除模拟；双设备设置不串写 |
| D：更新与异常 | 型号匹配、版本显示、安装/OTA/恢复入口，旧快捷方式兼容 | 错型号固件拒绝、未验证身份不可执行、旧固件降级展示、忙碌时不移除 |
| E：集成验收 | 合并构建、配置备份、在原设备配置上升级桥接 | ESP8266 单机、TAB5 单机、两者同时连接的真实操作和长时间恢复测试 |

每阶段保留可审查的本地提交和验证记录；后一个阶段依赖前一个阶段接口稳定。先完成电脑和模拟检查，部署与真机验收另行执行。功能分组改造原则上可先复用当前固件；只有发现缺少必要身份/能力信息且旧协议不能兼容解决时，才单独列出固件改动，不把所有设备强制升级作为添加前提。

## 9. 验收清单

- 全新用户：没有 TAB5/ESP8266 专属菜单、没有硬件扫描告警；添加引导可见。
- 只有 TAB5：没有原小屏镜像、原小屏页面切换、ESP8266 刷机；语音/生日/OTA 正常可达。
- 只有 ESP8266：没有 TAB5、豆包设备语音、生日管理和蓝牙专属入口；原小屏控制/镜像/轮播保留。
- 两者都有：窗口始终显示目标设备，切换/设置/升级不会串到另一台；公共数据只采集一次。
- 离线/未供电：设备卡片不消失，不重复弹出添加；重连到原记录；无身份确认不显示在线。
- 停用/移除/重新添加：服务正确关闭和释放，资料按说明保留，删除记录不会在下次启动被旧迁移自动恢复。
- 添加取消、电脑休眠恢复、COM/IP 变化、配对失效：状态明确，无重复实例、端口争用或无期限等待。
- 旧用户：数据源授权、历史数据、轮播、屏保和 TAB5 设备端设置保持；无明显启动变慢或后台请求增多。
- 安装/OTA：型号和固件匹配、当前运行版本显示正确，错误包被拒绝；真实完成仍核对镜像及启动健康。
- 界面：最小窗口及 125%/150%/200% DPI 可用，离线状态可读，空态短句，主操作无需长距离滚动。

关键通过标准：没有添加的硬件不显示其专属功能、也不启动其专属服务；已添加设备离线仍可辨认和管理；任一设备操作不影响另一台的设置或连接。构建与模拟通过不能代替最后三种硬件组合的实际验收。
