# 0.2.70 统一传输优化与验收

用户于 2026-09-30 要求继续优化，完成后统一刷固件并做一轮前后对比。.069 提示修复候选未单独安装，已并入本轮。当前现场为 .070：原目录桥接已替换、设备升级及启动核验通过，18 轮对照测速完成；三通道照片添加与提示重叠修复已获用户确认。语音最终均有文字，但 USB 初次两次触发失败、随后多次未复现；音源核对及空白录音退出另行修复，不能将其记为全部稳定通过。

## 本轮范围

- 由加密状态协商批量 RPC 能力，保留旧 T5R1 边界和旧端回退；T5R2 使用有界较大数据块，减少照片、OTA、内存测速的重复请求开销。固定模式不跨通道，不自动重发不确定业务操作。
- 蓝牙共用链路按有限传输窗口调度，避免整条大 RPC 阻塞语音和状态；写入顺序、最终确认、队列上限与取消所有权必须通过故障测试。
- USB 改善文本确认读取与状态传输，补全身份、状态、资源、指标阶段的原始故障记录。现有短暂超时原因未确认，不凭提速宣称已修复。
- 保留 .069 编辑区提示互斥和照片反馈保持。照片清晰度、认证和防重放、草稿审阅及手动发送保持。

## 完成证据

先完成两端实现及协议/内存/取消故障回归，冻结配套固件与桥接并备份原程序。随后正常桌面启动，统一安装一次；核验实际版本、镜像、合法分区及健康状态。对照 .068 同数据量每方向三轮，并记录块大小变化、错误数、各阶段耗时和内存；再做真实照片、语音和提示回归，恢复用户原自动轮播配置。

当前参考 .068 的 256 KiB 中位数（上传/下载，KiB/s）：USB 247.6/169.4，Wi-Fi 74.2/129.6，BLE 20.0/24.0。真实照片分别为 USB 133804 字节/683 ms、Wi-Fi 136393 字节/867 ms、BLE 142116 字节/9435 ms，照片不同不作严格跨通道基准。旧数据保留，不挑选较慢基线，也不承诺达到硬件标称极限。

## 已实现与本地验证

- 新端协商 `rpcBinary=1` 和 `rpcBulk=1` 后，照片及测速的单次有效载荷由 8 KiB 增至 48 KiB，USB/BLE OTA 范围读也支持 48 KiB。256 KiB 基准每轮从 32 个 RPC 降为 6 个；总字节量、模式绑定、逐块 SHA 与偏移检查保持。Wi-Fi 照片仍用既有整张二进制 HTTP，不将此项计作 Wi-Fi 照片改动。
- 蓝牙共享锁从整条 RPC 缩小至一次读取、窗口授权或至多 8 片的响应窗口。窗口内逐片等待写入，最后一片带确认；等通知、解密与业务处理时释放锁。没有并发提交未知顺序的 WinRT 写入。
- USB 文本确认改为有界阻塞读取（最多 50 ms 检查一次取消，整体仍为 4 秒），调用者持锁至读取真正退出；完整行后解码 UTF-8。新设备显式 `usbPacked=1` 才发送压缩完整状态；小指标帧与旧端格式保持。设备分发树先释放再处理状态，减少双份 JSON 内存；拒收立即回报，日志记录失败阶段。
- 修复仅 USB 语音在界面的旧限制；用户实际得到识别文字，初次两次触发失败的根因未确认，后续多次未复现。另发现新版豆包兼容路径缺少临时音源确认，需要补验真实收音来源。
- 合入 .069 相机准备/照片添加/语音反馈共用区域互斥及后台刷新保持；本地 LVGL 真实分支预览及用户真机确认均通过。
- Windows 候选 Release 构建零警告/错误。真实生产 RPC 模拟覆盖 48 KiB 数据、MTU 23/247/517、旧端边界、照片归属/字节、OTA 范围、坏 HMAC、防重放、重复执行与取消。C# 生成 1/8192/16384/16385/49152 字节数据交给固件 C 解码通过。
- 固件构建、邮箱 65535 字节边界、100 次完成/重连竞争、蓝牙窗口丢失/乱序/取消、OTA 故障矩阵、语音路由/ADPCM、压缩状态接收、LVGL 预览通过。ELF 的 PSRAM 分配、BLE 回调栈、Flash 期间显示 ISR 检查通过。固件保留既有未使用 `weather_icon_create` 编译警告。
- `dotnet run ... --status-once` 在当前工具宿主仍报无效控制台句柄；直接候选 DLL `--status-once` 成功，分别记录。首次本地测试命令的镜像长度未按 16 字节对齐、原生测试缺少数据参数，修正测试调用/夹具后通过，未跳过断言。

新增包在本轮优化与刷机授权范围内。冻结包中的未部署状态是打包时记录，后续以以下验收为准。

## 真实业务回归与接续项

用户确认三通道照片均添加成功、文字重叠已经消失。15 分钟只读记录含 BLE 136198 字节/5144 ms、USB 142597 字节/533 ms、Wi-Fi 135696 字节/967 ms；另一次 USB 为 135745 字节/347 ms。均为设备端上传成功诊断。照片不同，不能作为同文件对照；Wi-Fi 本次照片比上一张 .068 的 867 ms 略慢，不宣称所有真实业务均加快。882 个采样中显示错误/欠载均为零，证据 `performance-070-usage-summary.json`。

USB 初次语音两次失败，第三次成功；用户记得其中一次提到 USB 键盘未触发，随后多次测试未再出现。22:46:08、22:46:52 出现 RPC disconnected，后一次附近状态持续显示已连接；缺少原始触发失败信息，不能认定物理线缆或吞吐优化是根因。当前加载的豆包为 0.9.1.22，严格版本核验不接受它调用旧 native 控制，因而使用 USB HID 兼容路径。只读查询还确认所保存的旧麦克风不在线，而兼容路径遗漏了原有临时 CABLE 音源确认。因此之前文字返回不单独证明 TAB5 收音，更不证明拔掉 USB 后的纯无线触发。

用户新报空白录音仍等待后提示麦克风错误。桥接候选补齐音源确认与恢复，记录整次录音活动、保留尾段播放和晚到文字；确认静音后使用 1.2 秒最终文字保护期。仅初始一秒识别高纯度 880 Hz 就绪提示音，不修改实际传送的音频。声音/噪声或证据不足时仍保留原 8 秒等待。首版修补已替换且正常启动，但真机复测仍出现焦点失败、空白等待 8031 ms 及错误被后到音频覆盖。第二版候选新增经核验的 0.9.1.22 明确控制及完成反馈，电脑真实合成音频检查通过，23:48 已备份替换原目录，正常启动已核实，用户确认仅 USB 空白录音及时返回、有声短句快速准确，本轮验收通过，详见 [语音收尾补丁](VOICE-COMPLETION-070.md)。本轮 .070 固件保持，无需重刷。
