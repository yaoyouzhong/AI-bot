# 模型余额刷新与诊断

## DeepSeek 官方接口

已配置项目专用 API Key 时，桥接调用官方 `GET https://api.deepseek.com/user/balance`，不依赖网页登录，定时刷新间隔为两分钟。

超时、DNS/连接失败、响应中断或 HTTP 408/500/502/503/504 会在一秒后重试一次。401、403、429 不立即重试；429 保留五分钟退避。连接池空闲期为 30 秒，使两分钟定时查询重新建立连接，减少复用已失效连接的风险。

失败保留最近成功余额并标记过期。通知等待至少三分钟，并覆盖一轮网页刷新所需时间；期间恢复则取消待发送通知。已发送的 Windows 通知不代表当前仍失败，应核对 `/status` 的更新时间与 `stale`。

## 安全诊断

- `%LOCALAPPDATA%\AI-bot\deepseek-requests.jsonl`：最多保留 200 条，只记录时间、错误类别、HTTP 状态及耗时。
- `--diagnose-deepseek`：使用已保存凭据进行最多三轮查询，每轮临时失败最多重试一次；输出成功与否、错误类别及 HTTP 状态，不修改余额缓存。遇到认证失败、拒绝访问或限流即停止。
- `GET /diagnostics/web-quota`：仅本机访问，返回最近 80 条网页采集阶段记录，包括登录页跳转、超时、智谱余额响应和保存结果。重启清空，不记录 URL、页面文本或凭据。
- `%LOCALAPPDATA%\AI-bot\local-server-error.json`：最近一次监听失败的时间与 SocketError 类别。文件表示历史错误，恢复情况以实际状态接口为准。

所有上述记录都不保存密钥、请求头、响应正文或异常原文。真实运行记录和账户余额不得提交进仓库。

## 登录与后台采集

已登录页面不代表已经捕获余额。智谱需要进入财务总览，并收到可识别的余额响应；成功后更新缓存并解除过期状态。若后台阶段为 `login-page`，说明本次导航进入了登录页；应在内置网页确认登录，再观察 `balance-response` 和 `balance-saved`。

一次重新登录后后台刷新成功，不等于已经验证再次退出进程后的登录保留。

## 端口冲突

本机及局域网监听遇到 AccessDenied / AddressAlreadyInUse 时每两秒重试，退出时取消。重试不会抢占其他监听者。

排查时使用 `netstat -anoq -p tcp`，同时检查 LISTENING、BOUND 和 TIME_WAIT；普通监听列表可能漏掉已绑定但未监听的进程。不要仅凭进程名结束系统宿主。

现有 `AIBOT_HTTP_PORT` 同时调整本机和局域网端口，设备通过 USB 配对接收端口。持续冲突时可选择已验证空闲的端口；持久修改用户环境变量须取得授权。修改后为本次启动传入新值，并验证本机状态、局域网监听及 USB 设备状态。

## 验证范围

回归测试覆盖临时服务端失败恢复、认证/限流不立即重试、通知等待与恢复取消，以及端口占用释放后的监听恢复和取消。模拟测试不能替代真实供应商查询与设备验收。
