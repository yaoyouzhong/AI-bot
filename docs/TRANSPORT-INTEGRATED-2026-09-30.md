## 统一传输结构

业务层保留图片、语音、OTA 各自的完整性和生命周期；公共大数据层统一承担能力协商、有界缓冲、流控、取消、耗时统计和通道约束。已有短消息和旧设备协议继续兼容，ESP8266 不套用 TAB5 新协议。

| 层次 | 必须解决的问题 | 完成证据 |
| --- | --- | --- |
| 路由 | 固定模式只用指定通道；自动模式按已认证且可用的高吞吐通道选择；一次操作中途锁定通道 | 三路同时在线的固定模式负例；断线后不偷偷换路、不重复执行 |
| 业务排队 | 控制和取消有界响应；语音有实时预算；图片/OTA 使用连续传输窗口；后台同步不能无界抢占 | 队列、有效传输、处理、确认分别计时，后台负载下验证 |
| 状态同步 | 协商支持后只传变化部分或已验证基线引用，避免反复发整份目录；重连先全量，基线不一致恢复全量 | 断线、会话更换、漏帧、乱序均不能拿旧状态续新鲜度；不改变授权时限 |
| 可靠性 | 明确流 ID、偏移、长度、完整性；已确认偏移决定续传；不确定的发送操作不自动重放 | 丢包、重复、乱序、超时、取消、断线和重连故障注入 |
| 内存 | 缓冲按上限分配和复用；用户照片/草稿与可重建绘图缓存分开；记录峰值及最大连续块 | 相机连续开关/重拍/附件保留，传输中取消及结束后回收 |

## 通道实现要求

### 蓝牙

1. 记录实际连接间隔、PHY、数据长度、MTU、通知窗口和更新结果，再按设备/Windows 支持能力请求高吞吐参数。拒绝或不支持时保留正常连接，不能把“发出请求”当作协商成功。
2. 公共 RPC/语音使用有界通知窗口和接收方授予的额度；授权后的通知本身验证 ID/偏移，支持时省掉重复的 ATT 授权响应。窗口由能力和接收内存协商，不能只把四包改成一个很大的常量。
3. 长内容减少逐段请求往返，持续流控并保留明确完成确认。接收队列满时背压；缺片不能被最终确认掩盖。
4. 和状态同步共同安排时隙。压缩只是辅助，不能把改变压缩级别作为排队问题的完整修复。
5. BLE OTA 需要完整下载、认证校验、失败恢复和启动核验链路；完成前明确标为未支持，固定 BLE 不跨路升级。

### USB

1. 保留现有 `@AIBOT` 小消息；新增大数据能力时由双方协商，使用长度明确的二进制流，避免大数据再包一层 base64/JSON 和逐片串口命令往返。
2. 明确收发缓冲、分段长度、超时、帧边界恢复和断线处理；控制/诊断不能被无限长流阻塞。依据实际 USB 端点与 CDC 驱动测量，禁止套用 UART 理论速率。
3. 图片、OTA 与 USB 语音复用大数据层；语音仍生成可审阅草稿，不能自动发送。

### Wi-Fi

1. 大内容直接用带认证的 HTTP/TCP 流，复用连接，避免每片握手；减少中间复制并使用有界读写重叠。
2. 保留已修复的 SDIO 包内存归属、TCP 背压和 OTA 双缓冲。窗口和块大小按实际读取/写入数据选择，不再盲加固定延时。
3. 同时记录网络读写、加解密、图片编码、闪存写入耗时。照片编码或闪存瓶颈不能错误归因到 Wi-Fi。

## 一次验收所需的工具和顺序

1. **本地先完成协议对端及集成测试。** 检查现有/新增协议兼容、三通道路由、取消和重连、相机内存、字节一致性、认证/防重放、OTA 镜像与回滚。所有必要检查通过后才冻结一套安装包。
2. **把受控测速一同交付。** 使用设备本地生成的确定性数据，先测内存到内存的上行/下行；不创建用户消息，不发到外部供应商，不反复写闪存。结果包含通道、有效字节、总时长、队列/传输/确认时长、连接参数、错误数、内存峰值。执行有时限，取消后释放缓冲。
3. **同一固件完成三通道矩阵。** 每通道同一内容、同一大小至少三次，覆盖上下行、大块传输与语音小块节奏、后台任务同步开启的场景。记录中位数、范围和失败次数；自动选择另测回退，固定模式另测其他两路在线时不跨路。
4. **最后做少量真实业务操作。** 图片关注添加及完整消息送达；语音关注录音、结束清空队列、草稿审阅；OTA 使用一次真实镜像完成版本、哈希、分区/VALID 与启动核验。内存测速不能替代业务成功，下载测速不能替代刷机成功。
5. **交付统一结果表。** 已通过、性能未达标、未支持分别列出。达到本机软硬件可重复的稳定最佳配置后交付，不能用芯片标称速率声称达到现场上限。

## 官方依据与实现边界

- Windows 提供临时高吞吐连接参数请求，但该 API 从 Windows 11 才引入，且会影响其他蓝牙连接的调度；不能破坏项目 Windows 10 兼容性，也不应永久占用高吞吐请求。[Microsoft API 文档](https://learn.microsoft.com/en-us/uwp/api/windows.devices.bluetooth.bluetoothledevice.requestpreferredconnectionparameters)
- NimBLE 提供连接参数、PHY 与数据长度控制；实际实现必须对照本仓库固定的 ESP-IDF/ESP-Hosted/NimBLE 版本，并读取协商结果。[Espressif 连接说明](https://docs.espressif.com/projects/esp-techpedia/en/latest/esp-friends/advanced-development/ble-application-note/connection.html)
