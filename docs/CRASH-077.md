# 0.2.76 待机蓝屏与 0.2.77 故障记录候选

## 已确认的现场证据

2026-10-01 用户反馈 TAB5 无操作时蓝屏，可能停在总览，但页面记忆不确定。23:39:55 读取到 0.2.76-ui 运行约 102 秒，`resetReason=7`；据此估计复位发生在 23:38 左右。随后通过 USB 保存 ota_1 / VALID / ELF 指纹，确认仍运行已验收的 .076 镜像。读取诊断前后运行时间连续增加，读取没有再次重启设备。

本地 ESP-IDF 5.4.2 的 `esp_system.h` 将 7 定义为 `ESP_RST_WDT`；ESP32-P4 的复位转换表把多个硬件看门狗来源归入此值。它不能单独确定是哪一个看门狗，更不能定位到某一条代码。

保留记录为 `crash=0`，PC/RA/SP/cause 均为零、没有代码地址候选，前次启动阶段为 4、健康标记 30 秒。前次 OTA 阶段和错误均为零；没有正在升级的证据。未拿到 panic 调用栈，**根因尚未确定**。不能把后来正常运行或无显示错误计数当作已经修复。

原始证据位于 `artifacts/development/crash-20261001/retained-076.jsonl`。工具会话重启桥接后出现过蓝牙认证失败；用户运行正常桌面重启脚本后，USB COM9 与蓝牙均恢复、配对匹配磁盘。桥接文件、配对和 TAB5 固件未在这次恢复操作中替换。原自动轮播六页、顺序、15 秒间隔已核验。

## 诊断候选的范围

0.2.77-ui 保留 .076 的显示行为，增加 RTC 数字检查点：界面数据刷新、LVGL 刷新阶段、LCD 提交/等待、页面缓存工作和 Flash 临界区。启动时保存两个 CPU 的 ROM 原始复位值，并通过原有 USB `displayDiag` 尾部及 `tab5_crash_status` 返回上次记录。

每个检查点只写阶段、低 32 位微秒时刻、页面编号等数字，不保存用户内容或凭据；Flash 检查点代码处于 IRAM。不同通道记录不同工作，属于尽力保存的进度线索，不是原子快照或调用栈。时间每约 71.6 分钟回绕，需结合各通道、原始复位值和复位前采样判断，不能凭单个非零阶段认定根因。

没有调整看门狗、调度或触摸参数。音乐封面放大改动保留为未部署工作稿，本候选不包含它。USB 故障输出使用 CDC 单任务独占的静态缓冲，避免扩大 8 KiB USB 任务的栈占用。
