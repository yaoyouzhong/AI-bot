# 0.2.78 横版封面放大

## 用户目标与实现

用户确认比例修正后封面更清晰，但画面太小。当前浏览器原图实测为 150×83；本次提升可见尺寸，不声称获取高清原图。

Windows 继续生成 336×336 RGB565 等比完整封面，新增可选 `artworkWidth` / `artworkHeight` 传递原图比例。TAB5 对横纵比大于 1.25 的有效横图使用 608×500 卡片，图片最大可见宽度 560 像素；这张 150×83 图片约从 336×186 放大为 560×310，面积约为原来的 2.8 倍。文字区右移并缩为 548 像素宽，标题保留两行省略、歌手/专辑/时间和进度不重叠。

资产格式、传输尺寸、CRC 和封面缓存不变；方形封面、无图和旧桥接缺失尺寸时仍使用原布局。尺寸只改变而图片 CRC 不变时也更新布局，防止仍保留上一首歌的比例。原 ESP8266 的裁切封面保持不变，USB 帧移除这两个 TAB5 可选字段。macOS 未提供字段时按旧布局兼容。

本候选同时保留 .077 的故障进度记录及已验收的生日编辑修正。它没有修复尚未定位的待机看门狗根因；参见 [崩溃记录](CRASH-077.md)。

## 本地验证

- Windows 全量 Rebuild 零警告/零错误；音乐回归验证原图左右边缘、比例留黑、原小屏裁切、TAB5 尺寸字段、旧 USB 字段省略、RLE 无损往返和播放生命周期。
- 真实 LVGL 预览检查横图约 560×310、完整边缘和文字无重叠；仅尺寸变化切回方图、非法尺寸、缺少尺寸的回退通过。原主页滑动/缓存、相机遮挡和输入反馈全量回归通过。
- 固件构建通过，镜像为 ESP32-P4 / Chip ID 18 / 0.2.78-ui，校验有效；最终 ELF 的显示中断和故障检查点 IRAM 检查通过。
- `dotnet run --status-once` 的宿主控制台句柄限制单独记录，候选 DLL 直接运行返回有效 JSON。

证据目录为 `artifacts/development/music-078-20261002`，包含部署前源码、两端候选、哈希 manifest、合成图布局截图和各项日志。
