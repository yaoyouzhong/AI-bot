# Windows 桥接设备中心验收记录

日期：2026-09-28。电脑开发与本地测试完成；未部署到正在运行的桥接，未操作硬件、刷机或发布。TAB5/ESP8266 固件未因这次入口改造而修改。

## 已实现

- 托盘左键打开“我的设备”。空设备显示添加引导；单设备显示详情；双设备提供列表和独立详情。
- 功能按登记型号显示，离线仍保留；设备名称、型号、连接状态与已观测版本分开展示。ESP8266 旧协议没有固件版本号时明确标注，不生成假版本。
- TAB5 专属连接、配网、语音、生日、OTA 与首次安装入口；ESP8266 专属亮度、页面、轮播、屏保、镜像、桌宠和刷机入口。两种新设备均可从添加引导进入各自首次安装，再经协议验证后登记。天气位置、股票、账号与额度历史归公共设置。
- 添加经过协议回执确认。USB 名称只作为线索；取消/失败不留下启用记录。每种型号最多一台。
- 设备注册表采用原子替换及上一版本备份；迁移幂等、移除后不自动恢复；坏文件及未来版本不覆盖。TAB5 原配对自动导入；明确的原小屏连接配置需用户确认导入。
- 新增 ESP8266 使用 USB 实例标识做兼容绑定，COM 改号不会绑定到占用旧端口的其他 USB 设备；旧配置保留兼容方式，不宣称拥有固件级稳定身份。
- 设备服务独立取消与释放；改名/改数据需求不重启另一台；LAN 路由动态关闭。串口发现避开 TAB5 USB，并在枚举暂时失败时重试。
- 数据采集按启用设备和电脑额度历史需求合并；取消不需要的采集，保留缓存。TAB5 所选厂商不再通过 ESP8266 页面间接决定。
- 停用与移除保留用户内容，产品内移除确认明确对象。录音、识别、升级、安装忙碌时禁止移除。旧窗口关闭后不能继续控制已经移除的目标。
- 保留的 TAB5 配对与新设备不同：添加引导要求单独确认替换，原 DPAPI 文件以带时间的 `.bak` 保留。普通移除不会执行替换或清除配对。
- `--tab5-pair` 转到设备中心引导；`--tab5-offer-ota` 要求启用且配对的 TAB5；`--flash` 要求启用 ESP8266。诊断/模拟命令继续保留。

## 次日真机验收

先备份实际用户配置，再正常退出旧桥接并运行候选桥接；不要同时运行两份。迁移只能在开始候选程序后发生，今晚没有迁移真实配置。

1. 核对自动导入 TAB5 和原小屏导入提示；账号、额度历史、轮播顺序、间隔、生日与配对继续可用。
2. 分别检查仅 TAB5、仅 ESP8266、双设备：菜单归属；离线提示；USB/Wi-Fi/BLE 心跳及重连；改名/停用/恢复不影响另一台。
3. 验证语音和电脑大疆音源恢复；离线生日编辑；窗口目标保持；固件提供/更新完成状态。安装/升级实际执行仍须单独记录包、设备、结果与启动健康。
4. 检查真实 125%/150%/200% DPI、跨显示器窗口移动、休眠恢复、COM/IP 变化及较长时间运行。
5. 在原设置基础上结束验收并按项目约定恢复原有自动轮播选择。不要用测试页面列表覆盖用户配置。

先前 TAB5 滑动、升级速度等 0.2.38 候选固件的真机项目仍按原清单执行，这次桥接改造没有替代这些验收。

## 配置与回退

- 清单：`%APPDATA%/AI-bot/devices.json`；上一个可读版本：`devices.json.bak`。其中没有配对密钥或 Wi-Fi 密码。
- 原 `settings.json`、`tab5-pairing.dat`、生日、额度历史、浏览器授权与固件备份各自保留。本版本不重写成统一资料文件。
- 正式验收前，在本机备份 AI-bot 配置目录与现有桥接程序目录；备份可能包含授权资料，不上传仓库或对外发送。
- 清单损坏时，先退出程序并备份损坏文件，再检查 `.bak` 是否为所需设备状态；手动恢复前核对时间与内容，不自动回滚或覆盖。
- 回退旧桥接时先退出候选程序，恢复原程序目录。旧版不读取设备清单，所以不会遵守新版本的停用/移除状态，并会恢复其旧的全量服务启动方式。
- 使用过“替换保留的 TAB5 配对”后，若要回到旧 TAB5，需重新配对或在同一 Windows 用户下按确认过的目标恢复对应加密备份；普通回退不能把新旧硬件身份混用。
- 首版只支持一台各型号；ESP8266 兼容身份和未回报的固件版本、真正的三种硬件组合、实际显示器 DPI 与长时间运行仍按上述真机项目核验。
