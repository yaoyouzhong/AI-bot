# 港股行情与手动切页修复验收

## 修复范围

- Windows 港股请求使用腾讯 `r_hk...` 实时接口，返回值映射回配置中的 `hk...`；新浪备用源使用 `rt_hk...`。保留最多三位小数及指数精度，逐只补查缺失股票，失败时保留缓存并标记 stale。
- Windows 切页异步排队，仅保留最新选择；USB 资源传输在完整分块/ACK 之间处理切页。心跳在取得串口锁后采样，避免旧选择覆盖新选择。
- Windows、macOS 镜像及固件均让手动模式优先于完成/待输入提醒；AUTO 继续保留提醒切页。
- 设备诊断增加有效模式、实际绘制页与股票绘制次数。旧的 `mode` 仅表示请求模式，不能作为画面已经切换的证据。

## 验证结果

首轮只验证串口命令及请求模式，遗漏提醒对实际页面的覆盖；用户复测发现仍有延迟。第二轮修复显示策略后，用户确认实际切页正常。

- Windows Release 构建：0 警告、0 错误。行情、队列、显示策略及数据源回归通过。
- 本机 `dotnet run -- --status-once` 遇到 GUI 输出句柄异常；以 Release DLL 的 `dotnet .../AIBotBridge.dll --status-once` 完成等价检查。
- 固件编译通过，已写入真实 ESP8266 并通过写入校验。工具链现有触摸引脚、未使用函数和日期格式警告仍存在。
- 持续完成提醒下，天气、系统、股票实际绘制页分别在 63ms、78ms、141ms 内由设备诊断确认；资源传输期间切页命令在 109ms 内写出，ACK/CRC 正常。
- 完成提醒、Codex 待输入和国产模型待输入三种状态均未覆盖手动股票页；切回 AUTO 后仍正常显示完成提醒。
- 部署收尾恢复自动循环，保留原页面、顺序和间隔；USB 与桥接在线、实时行情刷新正常。
- macOS 同步修改并补充回归测试，编译与测试由 macOS 发布流水线执行；交互验收仍待在 Mac 上完成。

计时表示操作发出到固件绘制分支得到诊断确认，不是外部相机测量。当前行情 `updatedAt` 仍表示抓取时间，未新增逐只行情时间或屏幕延迟标签。

## 升级要求

本修复需要同时更新桥接程序与 ESP8266 固件。仅更新桥接不能修正旧固件对手动页面的覆盖。刷写不需要清除 Wi-Fi 或资源文件。
