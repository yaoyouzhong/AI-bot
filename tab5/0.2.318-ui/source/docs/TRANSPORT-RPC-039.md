# 0.2.39 USB / BLE RPC 与设置修复

> 历史阶段记录。当前实现、验收状态和升级通道边界以 [0.2.52 收尾清单](CLOSEOUT-052.md) 为准；下文的“待实现/待部署”仅描述当时状态。

## 开发完成，待真机验收

0.2.39-ui 与本次 Windows 桥接候选增加 USB CDC / BLE 双向加密请求：Codex 历史、分页、草稿、发送、发送回执、图片附件和固件下载。附件沿用现有 PNG/JPEG 图片能力（最多 2 MiB、4096 边长及 4 百万像素限制）；没有新增任意文件类型。

新固件会按有效状态心跳及 RPC 接收端可用性选择 USB > Wi-Fi > BLE，遵守手动指定的单通道模式。一次操作固定通道，失败不会自动跨通道重发。旧桥接没有 RPC 能力时保留 Wi-Fi 路径；旧固件没有 RPC 接收端，需要首次通过既有 USB 安装/恢复程序或 Wi-Fi OTA 安装新版。不能直接用蓝牙给旧固件添加蓝牙刷写能力。

本轮没有刷写真机，没有覆盖运行中的桥接，也没有修改设备配对、网络密码或用户数据。电脑当前运行版本与设备安装版本不能由本候选构建号推断。

## 协议

- 新 GATT 特征 `7af50005-7f23-4a91-bc65-667a19320101`，与语音 `0004` 独立。USB hello/ack 增加 `rpcVersion:1`，不修改原 ESP8266 协议。
- 同一邮箱格式：读取 `[id:u32le, offset:u16le, total:u16le, bytes]`；请求为 `nonce[32] + proof[64] + AES-GCM packet`。BLE 每片最多 480 字节，USB 每片最多 2048 字节；空闲 id=0。
- 写入命令 1 为 `[1,id:u32le,next:u16le]`，只能确认刚提供的末尾；命令 2 为 `[2,id:u32le,offset:u16le,total:u16le,bytes]`，严格顺序与长度检查。请求上限 12288 字节（含 96 字节认证信息），加密响应上限 32768 字节，单次期限 75 秒。连接重建/超时不重新发送业务消息。
- USB 载体为 `@AIBOT {version:1,type:tab5_rpc,deviceId,tag,data}`，data 为 base64 或 null（读）。回复同 type/id/tag、ok 和可选 data。主机每个串口事务单独获取锁，桌面处理不持锁，正常心跳继续发送。
- 请求 HMAC：`POST|/tab5/v1/rpc|deviceId|nonce|sha256(packet)`；AES-256-GCM 使用 nonce 字符串作 AAD。响应整个 `{status,body}` 加密并绑定同一个 nonce。明文包含桥接 session 和 issuedAt；沿用 -90/+10 秒时限。nonce 在完整有效期内保留，容量超限拒绝新请求。
- `kind:codex` 复用原有操作校验、加密阅读响应、任务约束与持久化发送 journal。requestId 用于不确定结果查询/去重，不自动重新派发。
- `kind:image-chunk` 携带 taskId、requestId、总 size、整图 sha256、offset、base64 data（解码后最多 6144 字节）。按设备/任务/图片绑定、严格连续、相同分片可重复。整图通过哈希和原图片解码/像素限制后进入已有加密存储。一次最多缓存一张 2 MiB 图片，90 秒无活动失效。
- `kind:ota` 携带 sha256、offerId、offset、count（1–8192）。只读取本进程用户明确提供的不可变固件包；撤回、换包、越界立即拒绝后续块。每块成功后延长升级忙碌期 90 秒，防止分片之间移除/重启设备服务。

固件端仍聚合 64 KiB 写入备用 OTA 分区。断线、短读、写失败、哈希不符、项目/版本不符均不切换启动分区。全部成功后才改启动槽，保留原有 30 秒健康确认与 90 秒回滚策略。NVS、资源分区及分区表不改。USB/BLE 中断后从头重试，不宣称支持跨重启断点续传。

## 设置行为

- “声音”和“屏幕与提醒”合并为“屏幕与声音”，包含亮度、屏保、提醒、音量、静音与试听；顶部声音图标直接滚动到声音区域。
- 开启轮播解除固定显示；普通浏览页面不再把轮播永久改成固定模式，到间隔后继续轮播。任务/设置/应用列表等操作页面暂停轮播。显式选择固定显示时关闭轮播勾选。
- 兼容旧版“cycle=true 但 selected 为固定页”的矛盾配置：启动时按已启用轮播处理，保留页面、顺序和间隔。
- 总览模型仍是 Codex / DeepSeek / 智谱三个固定入口。本轮解释了这一限制，没有声称已完成动态平台列表。后续方案为桥接按设备启用的数据源下发平台清单，TAB5 按稳定 provider ID 保存总览选择；新增采集适配仍由桥接实现。

## 验证与剩余验收

- ESP-IDF 5.4.2 / ESP32-P4 构建通过，应用位于既有 0x6e0000 OTA 槽容量内。
- Windows Release 构建 0 warning / 0 error；`--status-once` 输出有效 JSON。
- `--self-test-tab5-rpc`：模拟 USB、MTU23/247，认证、重放、邮箱只执行一次、图片分片重复及跨任务拒绝、逐字节一致、草稿及 OTA 分块/撤回。
- `--self-test-tab5`：既有 TAB5、HTTP、图片、桌面 IPC 测试；新增 RPC 历史前后翻页和同 requestId 发送只派发一次。均使用模拟桌面，不向真实会话发送消息。
- `rpc-mailbox-test`：编译生产邮箱核心，覆盖 USB/BLE 边界、乱序、旧 ID、重复响应、完整重组。
- `ota-update-test`：生产升级任务体的 66 场景（3 通道 × 2 镜像尺寸 × 11 情况），覆盖故障不改启动槽。
- `preview-ui.ps1 -Clang`：真实 LVGL 预览通过，包括合并设置、静音/试听/保存失败、启用轮播、滑动恢复、操作页暂停、固定模式停止轮播。MSVC 预览路径有既存原子支持/bigobj 环境问题，使用项目已有 Clang 路径。

待用户确认候选后，先保留设备备份，安装新版并核对版本/分区/哈希/启动 VALID；分别验证 USB-only 与 BLE-only（禁用 Wi-Fi 数据通道）的图片、历史与一次发送回执，断线不得重复发送。蓝牙升级速度、长时间共存及真实断线恢复尚未量测，不能用这些模拟结果代替真机通过。
