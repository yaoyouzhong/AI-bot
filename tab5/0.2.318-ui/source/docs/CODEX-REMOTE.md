# Codex 任务入口（开发版）

目标是让 TAB5 作为电脑端 Codex 的随身入口：选中已有任务，输入补充要求，查看接收和执行回执。公共 Windows 桥接仍在相邻 `AI-bot` 项目维护。

## 本次实现

- 「Codex 任务」页面先选项目，再显示该项目最近会话（最多 8 条）。桥接只读取 Codex 侧栏中已保存的项目；任意会话工作目录不会自动变成项目。项目使用保存项目 ID 的稳定散列，会话仍使用任务 ID，列表刷新时不会按新位置误选另一任务。旧桥接没有项目列表时，设备回退到“最近任务”。
- 提供屏幕拼音词组/英文键盘及 A164 原厂键盘字符输入。Enter 换行，Backspace 删除，发送由屏幕按钮触发。
- 通过已配对的 Wi-Fi 桥接提交文字。输入最长 2000 UTF-8 字节；等待回执时锁定输入与任务选择，收到接收回执后清空，失败保留输入。
- 电脑桥接读取 Codex 桌面任务目录，通过正在运行的桌面进程本地 IPC 提交已有会话；继承桌面的模型与权限设置，不再启动独立 CLI 代理。仅在桌面确认空闲且最近轮次结束时允许发送。
- 回执区分已发送、运行中、完成、失败、中断及发送结果不确定。权限审批和输入请求保留在桌面处理，TAB5 提示等待电脑端确认。

最新验证状态见文末。历史记录保留当时的实现与验收范围，不代表当前架构；桌面直连发送仍需真实提交验收。

## 键盘依据

A164 通过 Ext.Port1 I²C 连接，默认地址 0x6D，使用字符模式。固件按官方寄存器协议读取事件数量、字符串长度和字符事件，每次界面刷新最多处理 4 个事件，缺席时每 3 秒重探测。

依据：[官方产品页](https://docs.m5stack.com/en/tab5/Tab5_Keyboard)、[官方 I²C 协议](https://m5stack-doc.oss-cn-shenzhen.aliyuncs.com/1241/Tab5_Keyboard-I2C-Protocol-CN-V1.0.pdf)、[官方内部固件字符映射](https://github.com/m5stack/M5Tab5-Keyboard-Internal-FW)。用户尚未购买键盘，插拔、电气、连按与实际键值验收未完成。

## 已知边界

任务目录来自桌面客户端的本地只读 SQLite 索引，其内部 schema 可能变化；读取失败时显示空列表。桌面 IPC 也是内部版本化协议：当前按安装版本验证，协议不兼容或没有会话所有者时明确失败，不回退到独立 CLI。任务操作当前仅走 Wi-Fi；USB/BLE 继续传送原状态数据和新增任务目录。

参考：[Codex App Server 官方文档](https://developers.openai.com/codex/app-server/)。
