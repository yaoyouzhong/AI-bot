# 照片输出内存修复 0.2.62

## 0.2.61 真机失败证据

2026-09-30 用户报告“照片输出内存不足，可重试（3/257）”。正常桌面桥接确认设备 e8f60ae2ec56 已运行 0.2.61-ui、USB 可读、配对一致，BLE 实际 MTU 517。`photoDiag=3,257,200507,102400,1245184,0`：JPEG 输出分配失败，最大连续 PSRAM 块 1,245,184 字节，尚未输出 JPEG，上传尚未开始。证据保存在相邻 AI-bot `artifacts/acceptance-20260930/photo-061-output-memory-failure.txt`。历史 0.2.60 添加成功保留；本次不是传输超时，不能作为速度结果。

原实现同时保留相机静止帧、1,843,200 字节编码输入副本、640×360 预览，再固定申请 2 MiB 输出；连续空间不足时，即使实际照片仅几十 KiB 也无法编码。现场未证明这是 0.2.61 新增内存泄漏；固定大块分配及重复副本在旧版已存在。

## 修正及边界

- 相机静止帧提供只读借用接口。先取得与重新拍摄共用的原子占用锁，再确认 CAPTURED；编码结束（成功或失败）均释放。相机原图继续保留供预览或重试，不提前释放，不允许编码中重拍。
- 取消整个 RGB565 编码输入副本，降低峰值 1,843,200 字节。固定 IDF 5.4.2 的编码输入路径没有额外地址对齐约束，使用 PSRAM 原帧；输出仍使用 SDK 的对齐分配器。
- 输出先申请原上限 2 MiB，失败才依次尝试 1 MiB、512 KiB、256 KiB，最多四次。分辨率 1280×720、YUV420、quality=85 不变。编码失败或返回长度超出实际容量均拒绝上传，保留原帧，不截断、不降低画质、不自动重试含糊的驱动错误。
- 成功且编码引擎释放之后，将输出缩至实际 JPEG 字节数，释放多余上传期占用。缩容失败仍保留完整已编码照片。
- Windows 协议、桥接程序、配对和连接路由均无新增变更；固定通道约束保留。

## 验证

实际生产编码函数的故障注入覆盖现场 1.19 MiB 最大块、512/256 KiB 回退、所有分配失败、编码超时、容量溢出、零长度、引擎失败、缩容失败、完整字节保留，以及失败后使用原静止帧重试。真实相机任务 + LVGL 测试覆盖帧在 DMA 释放后仍有效、借用期间拒绝二次借用/重拍、释放后可再次借用、非拍照完成状态拒绝借用。相机驱动错误清理、8 KiB 上传分片兼容、完整 LVGL 预览均通过。

固件构建与镜像结果另存候选包；以上模拟不能替代真机 JPEG DMA 编码。安装后先确认启动版本/指纹，再拍照添加，记录 photoDiag、实际通道/字节/耗时，随后继续三通道性能矩阵。新候选未获得安装批准前不刷机。
